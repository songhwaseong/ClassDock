검증: `tests/whiteboard-focus-tools.test.js`(상태 정규화·경계·입력 허용), `tests/whiteboard-context-menu*.test.js`(우클릭 메뉴 3단계), `tests/whiteboard-zoom.test.js`(배율·화면 이동)

## 0. 목표와 비목표

### 목표

- 교사가 보드의 특정 부분에 학생의 시선을 모을 수 있는 **스포트라이트**를 제공한다.
- 문제·정답·그림을 순서대로 공개할 수 있는 **화면 가리개**를 제공한다.
- 집중 도구가 켜져 있어도 **드러난 영역에는 기존 펜·형광펜·도형·텍스트 도구로 판서**할 수 있다.
- 가려진 영역에는 실수로 판서되지 않도록 입력을 차단한다.
- 보드 확대·이동, 도구막대 위치 변경, 전체화면, 창 크기 변경과 함께 안정적으로 동작한다.

### 이번 범위가 아닌 것

- 집중 도구 상태를 PNG·PDF·인쇄 결과에 포함하는 기능
- 수업 리플레이에 스포트라이트 이동 과정을 녹화하는 기능
- 여러 개의 스포트라이트 또는 여러 장의 독립 가리개
- 자유곡선 형태의 스포트라이트
- 집중 도구 상태를 문서 복구본에 영구 저장하는 기능

집중 도구는 판서 콘텐츠가 아니라 **현재 수업을 진행하기 위한 화면 상태**다. 따라서 보드 항목, 실행 취소 기록, 자동 복구, 내보내기에는 섞지 않는다.

## 1. 한 문장 요약

> 캔버스 위에 화면 기준 오버레이를 올리고, 밝게 드러난 영역에만 캔버스 입력을 통과시킨다.

현재 화이트보드는 `wb-stage` 안의 `wb-canvas`에 판서 항목을 그리고, 확대·이동은 `view.scale/x/y`로 처리한다. 집중 도구는 이 좌표계와 분리하여 **무대의 CSS 픽셀 좌표**로 렌더링한다.

이렇게 하면 교사가 보드를 확대하거나 이동해도 스포트라이트 창과 가리개 경계는 프로젝터 화면의 같은 위치에 머문다. 확대된 보드 내용만 그 아래에서 움직이므로 실제 수업용 조명·종이 가리개와 같은 감각이 된다.

## 2. 사용자 화면

### 도구막대

확대/축소 그룹 다음에 `집중` 버튼 하나를 추가한다.

```text
[−] [100%] [+]  [◉ 집중]  [∑] [이미지] ...
```

- 버튼을 누르면 작은 집중 도구 패널을 연다.
- 패널에서 `스포트라이트` 또는 `가리개`를 선택하고 `시작`을 누르면 켜진다. 실행 중 모드를 누르면 즉시 해당 효과로 전환된다.
- 집중 도구가 켜져 있으면 버튼을 강조하고 `aria-pressed="true"`로 표시한다.
- 같은 버튼을 다시 눌러도 설정 패널만 열고 닫으며, 활성 도구가 뜻하지 않게 꺼지지는 않는다.
- 도구 종료는 패널의 분명한 `종료` 버튼 또는 `Esc`로 한다.

### 집중 도구 패널

```text
┌ 집중 도구 ────────────────── × ┐
│ [스포트라이트] [화면 가리개]   │
│                                │
│ 모양     [원형] [사각형]       │  ← 스포트라이트일 때
│ 어둡기   ─────●──── 72%        │
│                                │
│ 방향     [위] [아래] [왼쪽] [오른쪽] │  ← 가리개일 때
│ 가리개색 [어두움] [밝음]       │
│                                │
│ [위치 초기화] [조절점 숨기기] [시작/종료] │
└───────────────────────────────┘
```

- 기존 배경색 패널처럼 `wb-stage` 안에 뜨는 소형 패널로 시작한다.
- 수업 화면을 가리지 않도록 패널은 이동 가능하게 만들되, 1차 구현에서는 크기 조절까지 제공할 필요는 없다.
- 수학·과학 도구상자 및 배경색 패널과는 동시에 설정하지 않도록, 하나를 열면 다른 설정 패널은 닫는다.
- 패널을 닫아도 집중 효과는 유지된다. `×`는 패널 닫기이고 `종료`는 효과 종료다.

## 3. 스포트라이트 동작

### 기본값

- 첫 실행: 화면 중앙, 원형에 가까운 타원
- 크기: 무대 너비 36%, 높이 28%
- 어두운 영역: 검정, 불투명도 72%
- 최소 크기: 화면상 96×72px

### 조작

- 가운데 이동 손잡이를 드래그하면 밝은 영역을 옮긴다.
- 상·하·좌·우 및 네 모서리 손잡이로 크기를 바꾼다.
- `원형`은 타원 형태를 뜻하며 가로·세로 크기를 독립적으로 조절할 수 있다.
- `사각형`에는 12px 둥근 모서리를 적용한다.
- `조절점 숨기기`를 누르면 테두리와 손잡이만 사라지고 효과는 유지된다.
- 숨긴 상태에서도 설정 패널에서 다시 조절점을 표시할 수 있다.
- 집중 도구 실행 중 보드 우클릭 메뉴의 `조절점 숨기기/보이기`로도 같은 상태를 빠르게 전환한다. 설정 패널과 조절점 자체의 우클릭은 제외한다.
- 선택형 `손전등 효과`를 켜면 조절점을 숨긴 발표 상태에서 SVG 손전등과 반투명 빛줄기가 스포트라이트를 따라간다. 화면 끝에서는 여유가 있는 반대편으로 자동 이동하고, 배치 공간이 없으면 숨긴다.

### 판서 규칙

- 밝은 영역 안에서 시작한 펜·형광펜·지우개·도형·텍스트 입력은 기존처럼 동작한다.
- 어두운 영역에서 시작한 입력은 만들지 않는다.
- 그리던 선이 밝은 영역 밖으로 넘어가면 경계 직전에서 해당 스트로크를 끝낸다. 다시 밝은 영역으로 들어와도 새 `pointerdown` 전에는 이어 그리지 않는다.
- 선택 항목은 밝은 영역에서 선택을 시작할 수 있다. 선택한 항목을 이동하여 일부가 어두운 영역으로 들어가는 것은 허용한다.
- 마우스 휠 확대와 `Space`/가운데 버튼 화면 이동은 어느 영역에서든 허용한다.

## 4. 화면 가리개 동작

### 모델

화면 가리개는 한쪽 가장자리에서 들어오는 **한 장의 불투명 판**이다.

| 방향 | 가려지는 곳 | 드러나는 곳 |
|---|---|---|
| 위 | 위쪽부터 경계선까지 | 경계선 아래 |
| 아래 | 경계선부터 아래쪽 | 경계선 위 |
| 왼쪽 | 왼쪽부터 경계선까지 | 경계선 오른쪽 |
| 오른쪽 | 경계선부터 오른쪽 | 경계선 왼쪽 |

방향을 바꾸면 가림 비율은 유지한다. 예를 들어 40%를 가리고 있던 상태에서 `위`를 `왼쪽`으로 바꾸면 왼쪽 40%가 가려진다.

### 기본값과 조작

- 첫 실행: 아래쪽 50% 가림
- 색: 어두움 `#111827`, 밝음 `#ffffff`
- 가리개 경계 중앙에 손잡이를 표시한다.
- 손잡이를 끌어 가림 비율을 0~100%로 조절한다.
- 키보드로 손잡이에 초점을 두고 방향키를 누르면 1%, `Shift+방향키`는 5%씩 조절한다.
- 0% 또는 100% 부근 2% 안에서는 끝점에 붙도록 스냅한다.
- 100% 가림에서도 패널과 종료 버튼은 가리개보다 위에 남는다.

### 판서 규칙

- 드러난 영역에만 판서·선택·텍스트 입력을 허용한다.
- 가려진 영역에서 시작한 입력은 차단한다.
- 진행 중인 스트로크가 가려진 영역으로 넘어가면 경계에서 끝낸다.
- 가리개를 이동해 이미 작성된 판서를 가리거나 다시 공개할 수 있다. 판서 데이터 자체는 바뀌지 않는다.

## 5. 상태 모델

집중 도구 상태는 `wb.items`가 아니라 문서의 화면 상태인 `doc.boardFocus`에 둔다.

```js
doc.boardFocus = {
  active: false,
  mode: "spotlight",        // "spotlight" | "curtain"
  controlsVisible: true,
  dimOpacity: 0.72,
  spotlight: {
    shape: "ellipse",       // "ellipse" | "rect"
    cx: 0.5,                 // 무대 너비에 대한 비율
    cy: 0.5,                 // 무대 높이에 대한 비율
    width: 0.36,
    height: 0.28,
    flashlight: false        // 발표 상태의 손전등 효과
  },
  curtain: {
    edge: "bottom",         // "top" | "bottom" | "left" | "right"
    amount: 0.5,             // 가려지는 비율
    color: "dark"           // "dark" | "light"
  }
};
```

좌표를 0~1 비율로 보관하는 이유는 전체화면 전환과 창 크기 변경 뒤에도 의도한 위치와 비율을 유지하기 위해서다. 렌더링할 때만 현재 `W`, `H`를 곱해 CSS 픽셀로 바꾼다.

### 저장 규칙

| 상태 | 저장 위치 | 이유 |
|---|---|---|
| 현재 활성 여부·위치·가림 비율 | `doc.boardFocus` 메모리 | 탭을 오가는 동안만 유지 |
| 마지막 모드·모양·어둡기·가리개색 | `localStorage` 환경설정 | 다음 수업에서도 교사 취향 유지 |
| 보드 자동 복구 스냅샷 | 저장하지 않음 | 보드를 다시 열 때 가려진 채 시작하지 않게 함 |
| 실행 취소 이력 | 저장하지 않음 | 판서 편집과 발표 화면 조작을 분리 |

## 6. 렌더링 구조

`wb-stage`의 DOM 층을 다음처럼 구성한다.

```text
wb-stage
├─ wb-canvas                 z=0   판서
├─ wb-textinput              z=5   텍스트 입력(필요할 때)
├─ wb-focus-visual           z=8   어둠/가리개, pointer-events:none
├─ wb-focus-controls         z=9   이동·크기·경계 손잡이
├─ wb-focus-panel            z=11  집중 도구 설정
├─ wb-bg-panel               z=12  기존 배경 패널
└─ wb-edu-panel              z=12  기존 수학·과학 도구상자
```

### 스포트라이트 시각층

SVG 마스크 한 장을 사용한다.

1. 전체 무대를 흰색 마스크로 채운다.
2. 밝게 보일 타원 또는 둥근 사각형을 검정으로 뚫는다.
3. 검은 반투명 사각형에 마스크를 적용한다.

CSS의 거대한 `box-shadow` 방식보다 SVG 마스크가 타원·사각형을 같은 모델로 다룰 수 있고, 무대 크기가 바뀔 때 경계가 안정적이다. 시각층에는 `pointer-events:none`을 지정한다.

### 가리개 시각층

선택 방향과 `amount`로 계산한 단일 사각형을 SVG에 그린다. 가리개는 완전 불투명으로 표시하며, 경계에는 대비되는 2px 선과 드래그 손잡이를 둔다.

### 입력 차단은 시각 마스크와 분리

마스크의 투명 영역이 브라우저 포인터 판정과 항상 일치한다고 가정하지 않는다. 캔버스 이벤트에서 아래 순수 함수를 호출해 입력 허용 여부를 직접 판단한다.

```js
whiteboardFocusAllowsPoint(focus, { x, y }, W, H) // boolean
```

- 스포트라이트 타원: 타원 방정식으로 판정
- 스포트라이트 사각형: 좌우·상하 범위로 판정
- 가리개: 선택 방향의 경계선과 비교
- 비활성 상태: 항상 `true`

시각과 입력이 같은 정규화 상태를 사용하므로 확대율이나 DPR에 영향을 받지 않는다.

## 7. 현재 화이트보드 입력 흐름과의 결합

### 포인터 시작

기존 `canvas.pointerdown`에서 화면 이동 분기를 먼저 둔 뒤, 일반 왼쪽 입력 전에 검사한다.

```js
if (e.button === 1 || (e.button === 0 && spacePanning)) {
  beginViewPan(e);
  return;
}
if (e.button === 0 && !focusAllowsScreenPoint(screenPoint(e))) {
  e.preventDefault();
  flashFocusBoundary();
  return;
}
```

이후의 선택·텍스트·펜·도형 로직은 현재 코드를 그대로 탄다.

### 진행 중 스트로크

`pointermove`에서 현재 점이 가려진 영역으로 넘어가면 `finishStroke()`를 호출한다. 마지막 허용 좌표까지만 항목에 남는다. 도형도 마지막 허용 좌표에서 끝낸다.

### 커서

- 가려진 영역: `not-allowed`
- 스포트라이트 이동 손잡이: `move`
- 크기 손잡이: 기존 선택 핸들과 같은 방향별 resize 커서
- 가리개 경계: 방향에 따라 `ns-resize` 또는 `ew-resize`
- 드러난 영역: 현재 펜·형광펜·지우개·선택 커서 유지

### 확대·이동

- `view.scale/x/y`는 바꾸지 않는다.
- 마우스 휠과 화면 이동은 집중 도구보다 우선한다.
- 보드가 움직여도 집중 도구의 정규화 화면 좌표는 그대로 둔다.

## 8. 키보드와 패널 우선순위

`Esc` 처리는 눈에 보이는 가장 안쪽 상태부터 닫는다.

1. 수식 편집 또는 텍스트 입력 취소
2. 배경색·수학과학·집중 설정 패널 닫기
3. 집중 효과가 활성 상태이면 효과 종료
4. 보드 선택 항목 해제

집중 설정 패널 안의 입력을 조작할 때는 기존 실행 취소·삭제 단축키가 보드로 전달되지 않도록 한다.

접근성 규칙:

- 모든 아이콘 버튼에 한글 `aria-label`과 `title`을 함께 둔다.
- 모드·모양·방향 버튼은 `aria-pressed`를 사용한다.
- 어둡기와 가림 비율은 실제 `<input type="range">`를 사용한다.
- 스포트라이트 이동 손잡이는 `aria-label="스포트라이트 이동"`, 가리개 손잡이는 현재 가림 비율을 `aria-valuenow`로 알린다.

## 9. 저장·내보내기·리플레이 규칙

현재 PNG·PDF·인쇄는 캔버스만 내보내므로 DOM 오버레이인 집중 도구는 자연스럽게 제외된다. 이 규칙을 명시적으로 테스트한다.

| 기능 | 집중 도구 처리 |
|---|---|
| PNG 저장 | 제외, 전체 원본 보드 저장 |
| PDF 저장 | 제외, 전체 원본 보드 저장 |
| 인쇄 | 제외, 전체 원본 보드 인쇄 |
| 메모로 보내기 | 제외, 편집 가능한 원본 보드 전달 |
| 자동 복구 | 집중 상태 제외 |
| Ctrl+Z / Ctrl+Y | 집중 상태에 영향 없음 |
| 수업 리플레이 녹화 | 1차 구현에서는 제외 |

집중 상태가 켜진 화면 자체를 저장하는 요구는 별도의 `현재 수업 화면 캡처` 기능으로 다루는 것이 맞다. 기존 `PNG 저장`의 의미를 바꾸지 않는다.

## 10. 순수 함수와 파일 배치

### `src/js/whiteboard.js`


- 상태 기본값·범위 제한

- `module.exports`에 순수 함수 노출

현재 화이트보드가 단일 파일 안에서 보드별 클로저로 입력과 UI를 관리하므로 1차 구현도 같은 위치에 두는 편이 안전하다. 집중 도구가 더 늘어날 때만 `whiteboard-focus.js`로 분리한다.

- 가려진 영역 경계 피드백 애니메이션
- 작은 화면용 패널 배치

## 12. 완료 조건

- `집중` 버튼에서 두 기능을 켜고 끌 수 있다.
- 스포트라이트의 원형·사각형을 이동하고 크기를 조절할 수 있다.
- 화면 가리개를 네 방향에서 열고 닫을 수 있다.
- 창 크기를 바꾸거나 전체화면으로 전환해도 상대 위치와 비율이 유지된다.
- 확대·이동한 보드 아래에서도 집중 영역은 화면의 같은 자리에 남는다.
- 드러난 영역에서는 모든 기존 판서 도구가 동작한다.
- 가려진 영역에서 시작하거나 넘어간 판서는 기록되지 않는다.
- 집중 도구 조작은 보드 실행 취소·자동 복구·저장 데이터에 섞이지 않는다.
- PNG·PDF·인쇄·메모에는 가림 없는 원본 보드가 들어간다.
- 도구를 닫거나 문서를 닫을 때 등록한 이벤트와 DOM이 정리된다.
- 기존 화이트보드 테스트와 신규 집중 도구 테스트가 모두 통과한다.

## 14. 1차 구현 이후 실제 변경(2026-08-11 ~ 08-12)

설계 당시에는 집중 도구 전용이던 우클릭 메뉴가 보드 전체의 빠른 메뉴로 자랐다. 이후 작업에서 실제로 달라진 부분만 기록한다.

### 우클릭 메뉴가 보드 공통 메뉴로 확장

- `wb-focus-context-menu`는 이름만 남기고 **보드 어디서 눌러도 뜨는 공통 메뉴**가 되었다. 집중 도구 묶음은 `focus.active`일 때만 맨 위에 붙는다.
- 묶음: `집중 도구` / `선택 항목`(편집·복사·잘라내기·붙여넣기·복제·레이어 4방향·좌우/상하 반전·분리·삭제) / `보드 작업`(붙여넣기·이미지·수학 과학·배경색·축소·100%·확대·집중 도구·전체 지우기) / `출력·공유`(PNG·PDF·인쇄·메모로) / `수업 기록` / `도구막대`(숨기기·보이기) / `도구막대 위치` / `필기·도형 도구` / `색상·굵기` / `크기 직접 입력` / `이력`.
- 모든 항목은 **도구막대와 같은 실행 함수**를 호출한다(활성 상태와 Undo 기록이 갈라지지 않게 하기 위한 규칙). 새 기능을 도구막대에 붙일 때 메뉴에도 같은 함수를 연결한다.
- 메뉴를 여는 순간 누른 지점으로 선택을 갱신하고(`itemAt`) 그 보드 좌표를 `contextMenuBoardPoint`에 담아, 붙여넣기가 **우클릭한 자리**에 들어가게 한다. 집중 도구 조절점이 보이는 동안에는 선택을 만들지 않는다.
- 메뉴는 가로 스크롤이 생기지 않도록 화면 안으로 접어 배치한다. 닫기는 `Esc`·바깥 클릭·창 blur.

### 편집 도구막대 표시 전환

- 우클릭 메뉴의 `도구막대` 묶음에서 편집 도구막대를 통째로 숨긴다. 표시 여부(`localStorage`의 `wbToolbarVisible`)와 위치(`wbToolbarPos`)는 **모든 보드가 함께 쓰는 화면 환경설정**이며, 숨긴 직후에는 "보드 우클릭 메뉴에서 다시 표시할 수 있어요" 안내를 띄운다(다시 켤 방법이 메뉴뿐이라 반드시 알린다).

### Esc 단계 종료

- 설계의 8장 우선순위에 **집중 도구 2단계 종료**가 더해졌다. 조절점이 보이는 상태에서 `Esc`는 조절점만 숨기고 안내를 띄우며, 한 번 더 누르면 집중 도구를 끝낸다. 그 앞 순서(배경색 판 → 도구상자 → 우클릭 메뉴 → 집중 도구 패널)는 그대로다.

### 확대·이동과 반전

- 화면 배율·이동은 순수 함수 `whiteboardClampView`·`whiteboardZoomAt`으로 분리했다(0.25~4배, 가장자리 48px 유지). 휠은 포인터 기준 확대, `Space`+드래그와 휠 클릭 드래그는 화면 이동이다. 집중 도구 조절점이 보이는 동안의 휠은 경계를 깜빡여 알리고 배율을 바꾸지 않는다.
- 이미지·교육 도형에 `flipX`/`flipY`가 생겼다. 반전은 `board-render.js`가 그룹 자식까지 재귀로 물려주므로 리플레이·PNG·PDF에도 같은 모습으로 남는다.
