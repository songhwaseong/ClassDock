# 과제 패키지(.task) 설계

작성: 2026-07-12 · 상태: **Phase 1·2·3 구현 완료**(2026-07-12) — 설계 범위 전체 완료
구현: `src/js/task-package.js` + 접점(file-loaders·documents·code-viewer·python-runtime·python-run-context·core·app·command-palette·html 메뉴)
샘플: `docs/샘플-두수의합.task` + 제출본 3종(`_12 홍길동`=정답·seal 유효 / `_7 김철수`=오답 정직 신고 / `_23 이영리`=점수 조작+seal 재계산 → 재채점에서 불일치 검출 시연)

## 0. 목표와 비목표

**목표**
- 선생님이 **문제 설명 + 시작 코드 + 자동채점 테스트**를 한 파일(`.task`)로 내보내고, USB·메신저로 배포한다.
- 학생은 더블클릭 한 번으로 문제·코드·채점이 세팅된 화면을 얻고, 풀고 나서 **제출본(`.taskdone`)** 한 파일을 내보낸다.
- 선생님은 제출본을 열어 확인하고, 원본 `.task`의 테스트로 **재채점**해 검증한다.
- 전 과정 **완전 오프라인**(EXE·오프라인 HTML 동일 동작).

**비목표 (정직한 한계)**
- 부정행위 원천 차단은 하지 않는다. 브라우저 단독 도구라 학생이 마음먹으면 `.task`/`.taskdone`을 텍스트로 열어 조작할 수 있다. 방어선은 ①선생님 재채점 ②taskHash 대조 ③교실 운영이며, 이 한계를 UI 문구와 사용법 문서에 그대로 쓴다.
- v1은 **`.py` 단일 파일 과제만**. 노트북(.ipynb) 과제는 v2.
- 문제 설명에 PDF 첨부는 v1 제외(마크다운 + 이미지 base64로 충분).

## 1. 파일 포맷

### `.task` (과제) — JSON, `.lesson` 패턴 그대로

`lesson-replay.js`의 `loadLesson`/`validateLessonPayload`/`saveLessonFile` 3단 구조를 모방한다.

```json
{
  "format": "manneung-task",
  "version": 1,
  "id": "uuid-v4",
  "meta": { "title": "리스트 합 구하기", "author": "김선생", "createdAt": "2026-07-12T...", "note": "" },
  "problem": { "md": "## 문제\n두 수를 입력받아 합을 출력하세요.\n..." },
  "starter": { "name": "main.py", "code": "a = int(input())\n" },
  "files": [ { "path": "data.csv", "b64": "..." } ],
  "tests": [ { "name": "테스트 1", "input": "2\n3", "expected": "5", "hidden": false } ],
  "options": { "showExpectedOnFail": true }
}
```

- `tests`는 기존 `normalizeAssignmentTests`(core.js:1860)의 `{name, input, expected}` 스키마 그대로 + `hidden` 불리언 하나만 추가(정규화 함수에 옵션 필드 보존 추가).
- `hidden: true` 테스트는 학생 화면에서 통과/실패만 보이고 기대·실제 출력을 가린다(base64 이상의 보호는 하지 않음 — §0 한계).
- 크기 상한: 파일 전체 **32MB**(`.lesson`의 128MB보다 보수적으로), `files` 합계는 base64 이전 **8MB**, 테스트는 기존 상한(20개·항목당 20000자) 그대로.
- **taskHash**: 파일에 넣지 않고, 열 때마다 canonical JSON(키 정렬·공백 제거)의 SHA-256을 `crypto.subtle.digest`로 재계산 — 제출본과의 버전 대조용.

### `.taskdone` (제출본)

```json
{
  "format": "manneung-task-result",
  "version": 1,
  "taskId": "...", "taskTitle": "...", "taskHash": "sha256…",
  "student": "홍길동",
  "code": "…학생 최종 코드…",
  "grade": {
    "passed": 3, "total": 5,
    "results": [ { "name": "테스트 1", "pass": true, "actual": "(2KB 절단)", "error": null } ]
  },
  "gradedWith": "local-python | pyodide",
  "submittedAt": "2026-07-12T...",
  "seal": "sha256(위 내용 canonical)"
}
```

- `seal`은 위·변조 **방지**가 아니라 파일 손상·단순 수기 수정 **감지**용. 진짜 검증은 선생님 재채점(§4).
- 파일명: `{과제제목}_{학생이름}.taskdone`.

## 2. 학생 흐름 (열기 → 풀기 → 제출)

1. **열기**: `.task` 더블클릭/드래그 → `file-loaders.js`의 `handleFiles` 확장자 분기에 한 줄 추가(`.lesson` 라인인 28행 바로 아래):
   `else if (ext === "task" && typeof loadTask === "function") made = await loadTask(file, opts);`
2. **loadTask** (새 모듈 `task-package.js`):
   - JSON 파싱 + `validateTaskPayload`(format/version/필수 필드/상한 검사, lesson과 동일 스타일의 실패 토스트).
   - `files[]`를 starter와 같은 가상 폴더의 옆 파일로 배치 → 기존 "같은 폴더 .py 번들 실행"이 데이터 파일 참조를 그대로 처리.
   - 문제 설명: md 문서를 별도 탭으로 열고 **학습 화면 참조로 자동 고정**(기존 '어떤 문서든 참고 화면 고정' 재사용, `renderMarkdown`은 viewer-base.js:238 재사용, `allowHtml=false`).
   - 시작 코드: `.py` File을 만들어 `loadOffice(pyFile, "py", opts)` — ipynb→py 변환 경로(file-loaders.js:39-69)와 같은 수법. `ownerDoc.taskCtx = { task, taskHash }` 저장.
3. **과제 바**: 편집기 위(저장 경로 표시줄 위치)에 배너 — `📦 {제목} · 통과 n/m · [✓ 채점] [📤 제출본 내보내기]`.
   - **채점**: 학생에게는 테스트 편집 모달을 열지 않고 `task.tests`로 바로 `runPythonSource(code, ui, ctx, false, { gradeTests })` 호출(code-viewer.js:1232-1235와 동일 통로). 결과 렌더에 `hidden` 플래그를 전달해 숨김 테스트의 출력 비교를 가린다.
   - 로컬 파이썬/Pyodide 양쪽 채점은 기존 하네스(`buildPythonGradingHarness`)가 이미 처리.
4. **진행 상태**: `localStorage["mn.task."+id]` = `{ lastPassed, lastTotal, lastRunAt }` → 다시 열 때 배너 복원. 코드 편집 자체는 기존 PY_DRAFT 자동복구가 이미 담당.
5. **제출**: 이름 입력(기본값 `localStorage mn.studentName` 기억) → 직전 채점 결과가 없으면 자동으로 한 번 채점 → `.taskdone` 내보내기. 저장 동선은 `saveLessonFile` 패턴 + EXE면 저장 폴더 기록·[폴더 열기] 토스트(이미지 저장 동선과 동일).

## 3. 선생님 흐름 (만들기)

**진입점 2곳**
- Python 편집기의 기존 채점 모달(`openAssignmentGradingModal`, python-run-context.js:813)에 **"📦 과제 파일로 내보내기"** 버튼 추가 → 현재 코드=시작 코드, 저장된 테스트=tests를 시드로 과제 빌더를 연다.
- '새로 만들기' 드롭다운 2곳(app.js:75 드롭존 / app.js:346 사이드바) + 명령 팔레트(command-palette.js)에 **"새 과제 만들기"**.

**과제 빌더 모달**
- 제목 / 출제자 / 문제 설명(마크다운 textarea + 미리보기 토글=renderMarkdown 재사용) / 시작 코드(현재 편집기 내용 프리필) / 테스트 목록(**기존 채점 모달의 행 UI 재사용** + hidden 체크박스) / 데이터 파일 첨부(선택, 8MB 합계) / [내보내기].
- **"학생 화면 미리보기"** 버튼: 방금 만든 task 객체를 즉시 `loadTask`로 열어 왕복 검증(직렬화→검증→열기 전 경로를 실제로 태움).

## 4. 선생님 흐름 (검수·재채점) — Phase 2

- `.taskdone` 열기 → 검수 뷰: 학생 이름·제출 시각·신고된 점수·코드(읽기 전용 코드 뷰)·seal 일치 여부.
- 같은 `taskId`의 `.task`가 열려 있으면 **[재채점]** 활성화: 학생 코드를 선생님 파일의 tests로 다시 실행하고, 신고 점수와 다르면 **불일치 경고 배지**. 이것이 진짜 검증이고 seal은 보조.
- taskHash 불일치(과제 파일이 수정된 뒤 제출) 시 "다른 버전의 과제로 푼 제출본" 안내.

**Phase 3**: `.taskdone` 다중 선택/폴더 → 일괄 재채점 표(이름·통과·불일치) → CSV 내보내기(필요시 '새 빈 표' xlsx 인프라 재사용).

## 6. 단계별 계획

- **Phase 1 (MVP — 학생 흐름 완결)**: 포맷 + loadTask + 과제 바 + 채점 연동 + 제출 내보내기 + 빌더(채점 모달 진입만).
- **Phase 2**: 검수 뷰 + 재채점 + taskHash 대조.
- **Phase 3**: 일괄 검수 + CSV, 새로 만들기 메뉴·팔레트 노출 다듬기, hidden 고급 옵션.

## 7. 확정한 기본값 (다르게 원하면 여기만 바꾸면 됨)

- 확장자 **`.task` / `.taskdone`** (대안: `.mntask` — 타 프로그램 충돌이 걱정되면).
- 학생 이름은 제출 시 1회 입력 + 브라우저 기억. 명단 관리·학번 없음(v1).
- 숨김 테스트는 v1부터 포함(구현비 낮음: 결과 렌더에 플래그 하나).
- 과제 파일 32MB / 첨부 8MB / 테스트 20개 상한.
