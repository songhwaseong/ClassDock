# 일기장(.diary) — 설계 문서

> 작성 2026-09-18 · 상태: **1·2·3·4·5단계·파일 암호·화면 잠금 구현 완료** · 대상: 개인 다이어리(다이어리 꾸미기 느낌)
> 구현: `src/js/diary.js` + 접점(`file-loaders.js`·`document-types.js`·`documents.js`·`app.js`·`command-palette.js`·`i18n.js`·`classdock.html`·`scripts.manifest.json`·`styles.css`)
> 테스트: `tests/diary.test.js`(ZIP·모델·달력·줄 무늬) · `tests/e2e/diary.spec.js`(쓰기·스티커·드롭·꾸미기·저장·새로고침 복구)

## 1. 결정한 것

| 쟁점 | 결정 | 이유 |
|---|---|---|
| 누가 쓰나 | 개인 다이어리 | 사용자 결정. 기본 양식은 줄 공책, 꾸미기(배경·스티커)에 무게 |
| 저장 | **파일 하나 = 일기장 한 권, 기본은 ZIP·선택하면 ZIP 전체 암호화** | 사진이 1년 치 쌓인다. 글과 사진을 함께 잠글 수 있다 |
| 글과 사진 | **스티커 방식** — 사진은 종이 위에 떠 있고 글은 비켜 흐르지 않는다 | 글이 사진을 비켜 흐르려면 contenteditable 이 필요하다. `.mnote` 설계 때 표·이미지·커서 버그로 일부러 피한 길이다 |
| 줄 무늬 | textarea 자체의 CSS 배경(그라디언트) | 캔버스로 그리면 글줄과 어긋난다. `line-height` = 줄 간격이면 한 글줄에 선 하나 |
| 날짜 | 하루에 일기 하나 | 달력 칸 하나 = 일기 하나라 헷갈리지 않는다 |

## 2. 파일 형식

`.diary` = 무압축(STORE) ZIP.

```
diary.json          일기 글·꾸미기·스티커 자리
assets/<해시>.png   사진 바이트(SHA-256 앞 20자리 — 같은 사진은 한 번만)
```

```jsonc
{
  "format": "classdock-diary", "version": 8,
  "title": "일기장", "createdAt": 0, "updatedAt": 0,
  "style": { "lines": "ruled|grid|dots|blank", "gap": "narrow|normal|wide",
             "bg": "assets/….jpg 또는 빈칸", "fit": "cover|contain|tile", "veil": 0.4,
             "font": "gothic|myeongjo|gungseo|gulim" },      // lines 에 "picture"(그림일기)·"genko"(원고지)도
  "entries": [
    { "date": "2026-09-18", "title": "", "text": "…",
      "style": null,                         // 있으면 그 날만 이 꾸미기(전체 꾸미기를 통째로 대신)
      "weather": "sunny|…|빈칸", "mood": "happy|…|빈칸",
      "favorite": false, "tags": ["학교", "친구"],
      "stickers": [ { "id": "st-…", "kind": "photo", "asset": "assets/….png",
                      "x": 0.2, "y": 0.5, "w": 0.3, "ar": 0.75,
                      "rot": -30, "flip": false },
                    { "id": "st-…", "kind": "art",  "art": "heart", "color": "#ef4444", … },
                    { "id": "st-…", "kind": "text", "text": "좋은 하루",
                      "color": "#1f2937", "font": "gothic", "size": 0.048,
                      "align": "left" } ] }                // 배열 순서 = 쌓는 순서(뒤가 앞)
  ]
}
```

- **스티커 좌표는 종이 폭에 대한 비율**이다(x·y·w 모두 폭 기준, `ar` = 높이/폭). 창 폭이 바뀌어도 같은 자리에 남는다. `rot` 는 한가운데를 축으로 돈 각도(-180 초과 180 이하로 모음), `flip` 은 좌우 뒤집기(그림만 뒤집고 손잡이는 그대로).
- **스티커는 세 갈래**(`kind`): `photo`(사진, `asset` 이 ZIP 안 바이트를 가리킴) · `art`(내장 그림, 이름 `art` 와 `color` 만) · `text`(글상자). `kind` 가 없던 옛 파일은 `asset`·`art`·`text` 중 무엇이 있는지로 가른다(`diaryStickerKind`).
- **version 2** (2단계): 날씨·기분·`rot`·`flip`·`font`·`lines:"picture"` 추가. 1 도 그대로 열린다(새 필드는 기본값). 반대로 1단계 앱은 2 를 거절한다 — 모르는 필드를 버린 채 덮어써서 날씨·회전을 잃는 것보다 낫다.
- **빈 날은 저장하지 않는다**(글·제목·스티커·꾸미기가 모두 없음). 달력을 넘겨 보기만 해도 빈 일기가 쌓이면 안 된다.
- 열 때 신뢰하지 않는다: 날짜는 실제 있는 날만, 사진 이름은 `assets/[a-z0-9_-]+.(png|jpg|jpeg|webp|gif)` 이면서 ZIP 안에 있어야 한다. 가리키는 사진이 없는 스티커·배경은 버린다.
- 저장할 때는 모델이 가리키는 사진만 담는다 → 뗀 스티커의 사진은 다음 저장에서 빠진다.

### ZIP 을 직접 만드는 이유
- 사진은 이미 압축돼 있어 DEFLATE 로 줄일 게 없다.
- JSZip 은 지연 로드이고 2.x/3.x 전역을 바꿔치기하는 사정이 있다(`lazy.js`). 새 문서 뼈대를 **동기로** 만들어야 `handleFiles([new File(...)])` 로 바로 열 수 있다.
- 읽기는 남이 다시 묶은 DEFLATE 항목도 받는다(브라우저 내장 `DecompressionStream("deflate-raw")`). ZIP64 는 지원하지 않는다(4GB 미만).

### 파일 암호 봉투

암호를 설정한 `.diary` 는 위 ZIP 바이트 전체를 PBKDF2-HMAC-SHA256(기본 600,000회)으로 만든 AES-256-GCM 키로 봉인한다. 파일 머리에는 `CDDYENC1`·반복 수·16바이트 salt·12바이트 IV만 두고, 이 40바이트도 GCM additional data로 인증한다. 제목·날짜·사진 이름은 암호 봉투 밖에 두지 않는다.

- 비밀번호는 저장하지 않고, 열 때 만든 `extractable:false` `CryptoKey`만 열린 문서가 메모리에 보관한다.
- 같은 키로 다시 저장할 때도 IV는 매번 새 난수다. 암호 변경 때는 salt와 키를 모두 새로 만든다.
- 자동 복구본과 작업공간 사본도 같은 봉투로 저장한다. 복구 저장과 실제 저장은 문서별 큐로 직렬화해, 먼저 시작한 평문 복구본이 새 암호 저장본을 뒤늦게 덮지 못하게 한다.
- 폴더 일괄 열기·작업공간 복원에서는 암호창을 연달아 띄우지 않고 잠긴 탭만 만든다. 사용자가 그 탭을 실제로 열 때 암호를 묻는다.
- 암호 변경·제거도 파일 저장이 성공했을 때만 확정한다. 저장 취소·실패 시 이전 보호 상태로 되돌린다.
- 봉투 버전은 일기 모델 `DIARY_VERSION`과 별개다. 암호를 제거하면 다시 기존 ZIP이 되어 이전 판과 호환된다.
- 암호를 잊으면 복구할 수 없다. 화면 잠금은 열린 화면의 DOM을 가리고 다시 암호를 확인하지만, 운영체제 메모리에서 모델 자체를 지우는 기능은 아니다.
## 3. 화면

```
[탐색][목록][몰입] | [일기장 이름] ● 저장 안 됨 | [↶][↷][사진][스티커][꾸미기][암호][저장]
┌ 달력 ────────┐ ┌ ← 2026년 9월 18일 금요일 (오늘) → [제목] [🗑] ┐
│ ← 2026년 9월 → 오늘 │ │ ┌ 종이 ─────────────────────────┐ │
│ 일 월 화 수 목 금 토 │ │ │ 배경 그림 / 종이색 덮개 / textarea(줄) │ │
│  …  17•  [18•] … │ │ │ 스티커 층(끌기·손잡이·×)          │ │
│ 이번 달 일기 2편     │ │ └──────────────────────────────┘ │
└──────────────┘ └──────────────────────────────────┘
```

- 종이 높이 = max(글 높이, 가장 아래 스티커 + 두 줄, 24줄)을 줄 간격의 배수로 올림.
- 줄 위치: 글자는 줄 상자 한가운데에 서므로 선을 **가운데 + 글자 크기 × 0.62** 로 올린다(`lift`). 안 그러면 글이 두 선 사이에 떠 보인다.
- 꾸미기 창의 **이 날짜에만 적용**: 켜면 그날 `entry.style` 에 전체 꾸미기를 복사해 두고 거기를 바꾼다. 끄면 `null` 로 돌아간다.
- 종이는 테마와 따로 종이색(`--diary-paper`)을 쓴다. 어두운 테마에선 어두운 종이.

### 2단계에서 더한 것
- **날씨·기분**: 머리줄 단추 → 고르개(8가지씩, 다시 누르면 지움). 달력 칸엔 점 대신 **기분 그림(없으면 날씨)**. 검색·목록에는 그림 글자 대신 이름("날씨 비 · 기분 피곤")을 쓴다.
- **그림 글자 함정**: `icons.js` 가 앱 UI 의 이모지를 지우고 `U+FE0F` 까지 떼어 낸다(☀️ → 흑백 ☀, 😊 는 통째로 사라짐). 이모지를 보이는 칸(머리줄 단추·고르개·달력·목록)은 모두 `.ui-keep-symbols` 안에 둔다.
- **그림일기**(`lines:"picture"`): 위에 그림 칸(종이 폭의 55%), 그 아래는 **원고지**(2026-09-18 줄 공책에서 바꿈 — 실제 그림일기 공책 모양). 원고지 편집기를 그대로 쓰고 `diaryGenkoMetrics` 의 `padTop` 만 그림 칸 아래로 내린다(`diaryUsesGenko` 가 원고지·그림일기를 함께 가린다). 그림 칸 좌우는 원고지 칸 줄의 양 끝(`offsetX`, 폭 `cols×cell+1`)에 맞춰 두 테두리가 한 줄로 선다. 칸 가운데의 사진·연필 아이콘과 칸 안에 떨어뜨리기로 사진 붙이기·그리기를 시작한다. 사진은 칸에 꼭 맞춰 붙이고(첫 장만), 그 뒤로는 보통 스티커다. 내용이 있으면 안내 문장만 감추고 두 아이콘은 흐리게 남겨 다시 편집할 길을 유지한다.
- **글꼴**: 오프라인이라 웹 글꼴을 못 받는다 → Windows·Mac 기본 한글 글꼴(고딕·바탕·궁서·굴림)만. 손글씨 글꼴은 따로 싣는 결정이 필요하다(OFL 글꼴이면 가능하지만 한글 전체는 수 MB).
- **스티커**: 위 손잡이로 돌리기(Shift 15°), `[`·`]` 5°(Shift 15°), 우클릭·⋯ 메뉴(맨 앞/한 칸 앞/한 칸 뒤/맨 뒤·15° 돌리기·돌리기 되돌리기·좌우 뒤집기·그림 칸에 맞추기·떼기), `Ctrl+]`/`Ctrl+[`(Shift 면 맨 앞/뒤). 돌린 채 크기를 바꿀 땐 끈 거리를 스티커 가로축으로 옮겨 잰다. 종이 높이는 돌린 뒤 상자로 잰다(`diaryStickerBottom`).

### 원고지 한 줄 칸 수 (version 6)
- `style.genkoCols` = 0(자동 — 예전처럼 줄 간격 크기 칸을 폭에 맞게 채움) 또는 8·10·12·16·20·24. 칸 크기를 픽셀로 고르지 않고 **칸 수**로 고르게 한 이유: 쓰기 공책(8·10칸)·원고지(20칸)처럼 익숙한 기준이고, 칸 수가 고정되면 창 폭이 달라도·인쇄 폭(680px)에서도 **줄바꿈 자리가 같다**.
- 칸 크기 = floor((폭 − 64) / 칸 수), 12~120px. 칸 줄 계산은 `diaryGenkoGrid` 한 곳 — 원고지 편집·인쇄·그림일기 칸 테두리가 모두 여기서 재야 테두리가 한 줄로 선다.
- 한 쪽 길이(`pageH`)는 칸 크기가 아니라 줄 간격 × 26 으로 잰다 — 8칸처럼 큰 칸을 골라도 종이가 끝없이 길어지지 않게. 줄 간격 칩은 그대로 그림일기 칸 높이·한 쪽 길이에 쓰인다.
- 꾸미기 창의 '원고지 칸' 줄은 원고지·그림일기일 때만 보인다.
- 함께 고친 것: 줄 무늬 칩의 원고지·그림일기 견본이 비어 보였다 — JS 가 `background-image:none` 을 인라인으로 박아 CSS 견본을 덮었다.

### 스티커 여러 장 고르기 (파일 형식 변화 없음)
- 고른 상태는 `selection`(id 배열) 하나. 한 장이면 손잡이(크기·돌리기·×·⋯)가 보이고, 여러 장이면 점선 테두리만(`.diary-stickers.is-multi`).
- 고르는 법: Shift/Ctrl+클릭 = 넣고 빼기 · **Ctrl(⌘)+끌기 = 네모**(걸친 것 모두, Shift 를 더하면 기존 것에 더함) · 스티커에 포커스가 있을 때 Ctrl+A = 그날 모두. 종이 대부분이 글칸이라 그냥 끌기·Shift+끌기는 글 고르기로 남겨 두었다. 네모는 종이에 캡처 단계로 걸어 글칸·원고지보다 먼저 받는다.
- 무리 안 하나를 **끌면 모두 함께**, 끌지 않고 **누르기만 하면 그 한 장만** 고른다(흔한 그림 도구와 같은 규칙). 방향키·`[`/`]` 돌리기·뒤집기(하나라도 안 뒤집혔으면 모두 뒤집기)·떼기는 모두에, 되돌리기는 한 단계.
- 앞뒤 순서는 순수 함수 `diaryReorder(list, picked, where)` — 고른 것끼리의 순서는 지키고, 한 칸 앞/뒤는 고르지 않은 이웃하고만 자리를 바꾼다(붙어 있는 무리는 한 덩어리로).
- 함정: 순서를 바꾸면 스티커 요소를 새로 그려 포커스가 빠지고 다음 단축키가 안 먹는다 → `renderStickers` 가 같은 스티커에 포커스를 되돌린다.

### 내장 스티커(그림)·글상자 (version 8)

사진밖에 붙일 게 없어서 "다이어리 꾸미기"가 반쪽이었다. 둘 다 **ZIP 에 바이트를 싣지 않는 스티커**로 더했다 — 그림 획(`drawing`)과 같은 생각이다.

- **내장 그림**(`kind:"art"`): `DIARY_ART` 144종(꾸미기·날씨·표정·표시·학용품·옷차림·놀이·악기·명절·학교·축하·음식·동물·자연·탈것·여행). 한 줄에 `[id, 한글, English, 높이÷폭, SVG 속, 반투명?]`. 저장되는 건 **이름과 색뿐**이라 크게 늘려도 선명하고 여든 장을 붙여도 파일이 거의 안 는다. 색은 `currentColor` 라 바깥 요소의 `color` 만 바꾸면 된다.
  - 모르는 `art` 이름은 **버린다**(`diaryNormalizeSticker` 가 `null`). 앱이 그릴 수 없는 스티커를 자리만 차지한 채 두면 다음 저장에서 조용히 사라지는 것보다 낫다.
  - 이름은 `diaryArtName`(표 안 `ko`/`en`)으로 고른다 — "별"·"잎" 같은 짧은 말을 앱 공용 사전에 넣으면 다른 화면의 같은 글자까지 바뀐다(3단계에서 겪은 그 함정).
- **글상자**(`kind:"text"`): 종이 위 아무 데나 글을 얹는다. 두 번 누르면(또는 Enter) 그 자리에 **같은 글꼴·크기의 textarea 를 잠깐 얹어** 고쳐 쓴다. `contenteditable` 은 여기서도 쓰지 않았다.
  - **글자 크기(`size`)는 종이 폭에 대한 비율**이다. 그래서 창 폭이 달라도·인쇄 폭(680px)에서도 줄바꿈 자리가 같다(원고지 칸 수와 같은 이유).
  - **높이(`ar`)는 파일에 저장하지 않는다.** 글에서 나오는 값이라 담아 두면 창 폭에 따라 잰 값이 달라져, 고치지도 않은 일기장이 '저장 안 됨'으로 보인다(`diaryContentKey` 가 이걸 읽는다). 대신 `measureTextStickers` 가 그릴 때마다 재서 메모리의 `ar` 을 채우고, 종이 길이(`layout`)·인쇄는 사진과 똑같이 `ar` 로 잰다 — **재기가 종이 길이 셈보다 먼저** 와야 한다.
  - 글을 모두 지우면 글상자가 사라진다(빈 상자는 `diaryNormalizeSticker`·`diaryCleanSticker` 둘 다에서 걸러진다). Esc 는 고치기 전으로 되돌린다.
  - 좌우 뒤집기는 주지 않는다 — 거울 글씨가 될 뿐이다(`flip` 은 늘 `false` 로 저장).
- 도구막대 **스티커** 단추 → 색 칸 + 그림 타일 + 글상자 넣기. 색 칸은 **고른 스티커가 있으면 그 색을 바꾸고**, 없으면 다음에 붙일 색만 기억한다. 이 창은 종이 위 스티커를 고르며 쓰는 창이라 **종이를 눌러도 닫지 않는다**(꾸미기 창과 다른 점).
- 새로 붙는 스티커는 `cascadeOffset` 으로 조금씩 어긋내 놓는다 — 같은 자리에 똑같이 겹치면 위의 것만 잡혀서 아래 것을 고를 길이 없다.
- 옮기기·크기·돌리기·앞뒤 순서·여러 장 고르기는 **사진과 똑같은 길**을 쓴다(`startStickerDrag`·`diaryReorder`·`diaryStickerBottom`). 갈래마다 다른 건 그리는 곳뿐이다.
- 스티커 창은 꾸미기 창과 **모양만 같고 클래스는 따로**다(`.diary-art-panel`). 한때 `.diary-style-panel` 을 같이 달았더니 e2e 선택자가 둘을 한꺼번에 집었다.
- 함께 고친 것: 목록 카드가 사진만 썸네일로 썼다 → 내장 그림만 붙인 날도 그 그림이 보인다. 목록 이름도 "사진 2장 · 스티커 1개"로 갈래를 나눠 센다.

### 양옆 칸 접기 · 몰입 모드 (파일 형식 변화 없음)

왼쪽 두 칸(`224px` + `300px`)이 늘 524px 를 먹어, 1280px 화면에서도 종이가 제 폭(`max-width:780px`)을 못 찾고 700px 로 눌려 있었다.

- 도구막대 **왼쪽 보기 묶음** 세 단추: 탐색 칸 접기 · 일기 목록 접기 · 몰입 모드. 접기 상태는 보는 사람 편의라 파일이 아니라 `localStorage`(`mn.diaryPanels`)에만 둔다 — 접었다고 일기장이 '저장 안 됨'이 되면 안 된다.
- **칸 폭은 CSS 변수**(`--diary-c-side`·`--diary-c-rail`)다. 접을 때 `display:none` 만 해서는 안 된다 — 격자 틀이 그대로면 남은 칸이 앞 칸의 폭을 물려받아 짜부라진다. 접힌 조합마다 `grid-template-columns` 를 다시 정하고, 1180px 이하 반응형은 변수 값만 바꾼다.
- 접기는 **761px 이상에서만**. 좁은 화면은 이미 세로로 쌓이고 제 접기 단추(`.diary-side-mobile-toggle`)가 있다.
- **몰입 모드는 접기와 따로 건다**(`is-focus`). 접기 클래스에 얹으면 나갈 때 사용자가 접어 둔 상태를 잃는다. 몰입 중에는 접기 단추를 `disabled` 로 둔다(접을 게 없다).
- 몰입은 **도구막대를 남기고 흐리게**(opacity .4 → hover·focus-within 에서 1) 둔다. 없애면 저장·되돌리기로 가는 길이 사라지고 나갈 단추도 없어진다.
- **종이 폭(`max-width:780px`)은 모드에 따라 바꾸지 않는다.** 바꾸면 줄바꿈 자리가 흔들린다(원고지 칸 수·글상자 글자 크기를 비율로 둔 것과 같은 규칙).
- **위아래 여백도 바꾸지 않는다.** 처음엔 몰입일 때 `.diary-main` 위 여백을 16→30px 로 넓혔는데, 양옆을 **이미 접어 둔 채로** 들어가면 그 14px 이 유일하게 눈에 띄는 변화라 화면이 툭 내려갔다 올라오는 것으로 보였다. 몰입이 더하는 것은 '감추기'지 '여백'이 아니다.
- **Esc 로 나간다.** 이 처리기는 `capture` 라 글상자 textarea 의 Esc 보다 먼저 오므로, 여기서 차례를 직접 가려야 한다 — 그리기 → 글상자 고치기 취소 → 열린 창 → 고른 스티커 풀기 → 그다음이 몰입 나가기다. 일기 본문 칸(`area`)만 예외로 받는다(글을 쓰다가도 나갈 수 있게).
- 함정: 도구막대를 순서로 집던 e2e(`.diary-bar .diary-btn` 의 `first()` = 되돌리기)가 새 단추 때문에 엉뚱한 것을 눌렀다 → `diary-undo-btn`·`diary-redo-btn` 클래스를 줘서 순서에 기대지 않게 했다.

### 손글씨 글꼴 (version 5)
- 나눔손글씨 **펜**·**붓**(google/fonts, SIL OFL 1.1 — 한글 11,172자 전부)을 `tools/build-hand-fonts.py` 로 TTF(약 3MB) → WOFF2(약 0.6MB) → base64 JS(`vendor/hand-font-pen.js`·`hand-font-brush.js`, 약 0.8MB 씩)로 만든다. 글꼴 이름은 바꾸지 않는다(Reserved Font Name). 라이선스 전문은 `vendor/licenses/nanum-handwriting-OFL.txt`.
- 시작할 때 읽지 않는다 — 그 글꼴을 고르거나(`applyStyle`), 꾸미기 창을 열거나(칩 견본), 인쇄할 때만 `MNLazy.tryNeed` → `FontFace` → `document.fonts.add`. 올린 뒤 base64 문자열은 지운다. 다 읽으면 줄바꿈 자리가 달라지므로 `layout()` 을 다시 부른다.
- 손글씨는 같은 크기에서 작아 보여 글자만 키운다(펜 1.35·붓 1.3배, 원고지 칸은 넘치지 않게 1.25배까지). 줄 간격·칸 크기는 그대로라 줄 무늬와 계속 맞는다.
- 개구(Gaegu)는 한글 2,350자만 있어 드문 글자가 다른 글꼴로 섞여 뺐고, 하이멜로디·감자꽃은 한 벌 12MB 라 뺐다.

### 그림 칸 그리기 (version 4)
- `entry.drawing` = 획 배열 `{ c:"#rrggbb", w, p:[x,y,x,y…], e? }`. 좌표·굵기는 **그림 칸 폭에 대한 비율**(y 도 폭 단위 — 가로세로 비율 유지). 그림 파일(PNG)로 굳히지 않고 벡터로 둔 이유: 칸 크기가 바뀌어도 선명, 획 하나씩 되돌리기, 파일이 작음. 인쇄 때만 두 배 해상도 PNG 로 그려 넣는다.
- 그리기 층은 그림 칸과 같은 자리에 **스티커 위**로 둔다(사진에 덧그리기). 그리기 중에만 누르는 것을 받고, 평소엔 통과시켜 스티커를 그대로 고를 수 있다.
- 지우개는 `destination-out` 획 — 그리기 캔버스만 지우고 아래 사진·칸·배경은 그대로. 그리는 동안은 새 토막만 바로 그리고(획이 많아도 빠르게), 손을 떼면 전체를 다시 그린다. `getCoalescedEvents` 로 빠른 선도 촘촘하게.
- 한 날 3000획·한 획 4000점 상한. 펜 색·굵기는 보는 사람 편의라 `localStorage`(mn.diaryPen)에만.
- 그림일기가 아닌 줄 무늬로 바꾸면 그림은 숨지만 지우지 않는다(다시 그림일기로 돌아오면 보인다).

### 3단계에서 더한 것
- **원고지**(`lines:"genko"`, 파일 **version 3** — 2단계 앱이 원고지를 줄 공책으로 바꾼 채 덮어쓰지 않도록 옛 앱은 새 파일을 거절한다).
  textarea 는 글자 폭을 칸에 맞출 수 없어서, 원고지에서는 **textarea 를 커서 자리에 숨긴 입력칸**으로만 쓰고(IME·타자 단위 되돌리기·붙여넣기·맞춤법은 그대로) 칸과 글자는 `diaryRenderGenko` 가 따로 그린다.
  - 배치 규칙은 순수 함수 `diaryGenkoLayout(text, cols)` 한 곳: 한글·문장부호·빈칸 한 칸, 영문·숫자 두 자 한 칸, Enter 는 다음 줄 첫 칸, 꽉 찬 줄 뒤 `.,!?` 는 끝 칸 옆 여백에(`hang`), 꽉 찬 줄 뒤 빈칸은 새 줄 첫 칸을 비우지 않게 여백으로. 그림 글자(서로게이트 쌍)도 한 칸.
  - `pos[i]` = 글자 i 앞 커서 자리. 누른 자리·위아래·처음/끝 이동은 `diaryGenkoIndexAt(row, col)` 로 가장 가까운 자리를 찾는다(textarea 의 위아래는 칸 줄과 맞지 않아 직접 처리). 끌어서 고르기·Shift 이동도 된다.
  - IME 후보 창이 커서 옆에 뜨도록 숨은 textarea 를 커서 칸으로 옮긴다. 선택이 바뀌면 `selectionchange` 에서 다시 그린다.
- **인쇄·PDF**: 인쇄 단추(도구막대·상단 머리글 둘 다) → 이 날 / 이번 달(달력에서 보고 있는 달) / 일기장 전체. 화면을 찍지 않고 **인쇄 전용 층**(`#diaryPrintLayer`)을 A4 폭(680px)으로 다시 배치해 그것만 찍는다(연대표 방식). 한 날 = 한 쪽에서 시작, 긴 글은 이어진다. 줄 무늬가 배경이라 `print-color-adjust:exact`. 사진은 `decode()` 를 기다린 뒤 찍는다. PDF 는 인쇄 창의 대상 'PDF로 저장'.
  - 함정: 인쇄 머리를 `<header>` 로 만들면 전역 `header{color:#fff}` 를 물려받아 흰 글자로 찍힌다(e2e 로 색까지 확인).
- **영어 화면**: 고정 단추·안내는 `MNI18N.translateTree` 가 언어 전환까지 맡고, 날짜·달력·목록·상태 글처럼 그때그때 그리는 글자는 `diaryT`/`diaryTf`/`diaryUi*` 로 그 자리에서 고른 뒤 `mni18nchange` 때 다시 그린다. 저장·검색용 글자(`diaryDateLabel`·`diaryPlainText`)는 언어와 무관하게 한국어.
  - 함정: "점"·"비"·"눈"·"빼기" 같은 짧은 말을 앱 공용 사전에 넣으면 다른 화면의 같은 글자까지 바뀐다 → 줄 무늬·간격·글꼴·맞춤·날씨·기분 이름은 diary.js 안에 영어를 함께 둔다(`*_EN` 표, `diaryName`). 사전에는 문장·긴 이름만. 사전 누락은 `tests/diary.test.js` 가 소스에서 뽑아 검사한다.

### 4단계에서 더한 것 (version 7)

- **탐색 패널**: 왼쪽을 달력·찾기·돌아보기 세 탭으로 나눴다. 찾기는 현재 일기장 안에서 제목·본문·날짜·태그를 즉시 검색하고 즐겨찾기·사진·태그·기분/날씨가 있는 날로 거른다. 모바일에서는 탐색 패널을 기본으로 접어 종이를 먼저 보여 준다.
- **월간·연간 돌아보기**: 보고 있는 달의 작성일·최장 연속 기록·사진·즐겨찾기 수, 가장 잦은 기분/날씨, 자주 쓴 말과 연간 기록 지도를 모델에서 즉석 계산한다. 통계 캐시는 파일에 저장하지 않는다. 같은 월·일의 지난 기록도 `그해 오늘`에 모은다.
- **태그·즐겨찾기**: `entry.favorite`과 `entry.tags`를 추가했다. 태그는 앞의 `#`와 겹치는 공백을 정리하고 한 태그 24자·하루 12개로 제한한다. 검색·인쇄·통합 검색에도 포함한다.
- **글감·양식**: 하루 돌아보기·감사·학교생활·독서·여행 질문을 본문에 삽입한다. 글감은 앱에 내장된 시작 문구일 뿐 별도 필드를 만들지 않는다.
- **화면 잠금**: 파일 암호가 설정된 일기장에서 즉시 잠금과 5·10·30분 자동 잠금을 제공한다. 잠금 중에는 일기장 이름·달력·검색 결과·종이를 모두 가리고, 같은 파일 암호를 PBKDF2로 다시 확인해야 연다. 자동 잠금 시간만 로컬 설정에 저장하며 암호와 검증 바이트는 저장하지 않는다.
- **화면 구조**: 본문을 `달력·검색·회고 / 일기 카드 목록 / 선택한 일기 편집기`의 3단으로 나눴다. 카드는 날짜·제목·두 줄 미리보기·태그·첫 스티커 사진을 보여 주며, 사진 URL은 이미 열린 에셋의 object URL을 재사용해 파일에 별도 썸네일을 저장하지 않는다. 일기장 이름·저장 상태와 작성 도구를 두 묶음으로 나누고, 날짜/제목/기분·날씨/태그에 행별 위계를 줬다. 760px 이하에서는 세 영역을 세로로 쌓는다.
