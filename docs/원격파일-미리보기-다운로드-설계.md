# 원격 파일 미리보기·다운로드 설계

작성: 2026-08-31 · 상태: 첫 버전 구현·코드 검증·HTML/EXE 빌드 완료

구현 파일: `desktop/ssh_files.cs`, `src/js/remote-files.js`, `src/js/remote-files-ui.js` 및 기존 터미널·런처 연결부.

구현 시 구체화한 정책: 파일 패널은 도킹 영역에서 터미널과 전환하며 기존 문서를 유지한다. 이미지 캔버스·PDF 페이지는 800만 픽셀로 제한한다. 애니메이션 WebP와 암호화 PDF는 다운로드로 안내한다. 저장은 로컬 Windows 디스크를 지원하며 UNC 경로는 거부한다. 미리보기 임시 파일은 화면에 바이트를 전달하면 즉시 해제하고 화면 자체는 닫을 때 해제한다. 프로토콜·디스크 동작은 모의 SFTP 스트림을 사용하는 실행 테스트로 검증하고, 실제 SSH 서버 연결·네이티브 저장창·화면 조작 검증은 별도로 구분한다.

검증 기록(2026-08-31): `npm run check` 통과, `npm test` 1,707개 통과·실패 0개·환경 조건에 따른 건너뜀 2개, `npm run build`·`desktop\build.bat`·`npm run release-check` 통과. 설치된 Windows OpenSSH 9.5의 설정 출력에서 SFTP subsystem·PTY 비활성화 인수가 적용되는 것도 확인했다. 실제 서버 전송과 브라우저·저장창 조작은 실행하지 않았다. 실행 중인 ClassDock 프로세스는 빌드 직전 없었으며 새 EXE는 자동 실행하지 않았다.

## 1. 목표와 첫 버전 범위

2026-08-31 실패·재시도 회귀 수정: Windows 이벤트 로그의 15:21 `.NET Runtime` 오류에서 인증 pipe의 비동기 접속 대기 핸들을 조기에 Dispose하여 `ObjectDisposedException`으로 ClassDock 전체가 종료된 것을 확인했다. 인증 완료·취소·시간 초과를 처리할 때 .NET 내부 대기 핸들을 직접 해제하지 않고 완료 콜백과 Task로 종료를 확인하도록 바꿨다. 실제 Windows named pipe의 인증·취소 40회, 시간 초과 10회, 후속 재인증을 실행 검사에 추가했다. 미리보기로 숨긴 xterm의 0×0 크기를 원격 PTY의 20×5 크기로 전송하지 않으며, 파일 인증 실패 시 닫힌 연결 ID를 버리고 인증 입력란을 다시 표시한다. PDF 첫 페이지 렌더 실패는 빈 성공 화면 대신 기존 미리보기와 실패 안내를 유지한다.

ClassDock.exe의 원격 터미널에서 파일 경로를 입력해 내용을 읽기 전용으로 확인하거나, Windows에 다른 이름으로 저장한다. 원격 파일을 수정·삭제·실행하지 않는다.

- 진입점: 기존 `파일 업로드` 버튼 옆에 `원격 파일` 버튼 추가.
- 파일 하나의 경로를 직접 입력한다. 폴더 탐색, 다중 파일, 폴더 다운로드, 압축 해제는 후속 범위다.
- 미리보기: 이미지, 텍스트·코드·로그, CSV/TSV, PDF.
- 다운로드: 형식에 관계없이 서버 계정으로 읽을 수 있는 일반 파일 하나.
- 미지원 형식이나 미리보기 제한을 넘긴 파일은 이유를 표시하고 다운로드를 제공한다.
- 자동 새로고침, 원격 편집·재저장, 동영상 스트리밍, 터미널 출력 경로 자동 링크는 제외한다.
- 기존 업로드 기능은 유지한다. 이번 작업에서 업로드 전송 방식까지 교체하지 않는다.

## 2. 현재 코드에서 확인한 기반

| 기존 위치 | 확인한 동작 | 설계에 활용할 부분 |
|---|---|---|
| `src/js/remote-terminal.js` | 작업공간별 터미널, 업로드 패널, 접속별 OSC 7 경로 알림 수신 | 버튼·패널 연결, 작업공간 상태, 자동 현재 폴더 |
| `desktop/ssh_terminal.cs` | `ssh.exe`와 ConPTY 터미널, 별도 `scp.exe` 업로드, askpass 인증, 전용 known_hosts, 개인키 임시 사본 | 연결 대상·인증·호스트 키 검증·취소 수명 관리 |
| `desktop/launcher.cs` | loopback API, Host/Origin 검사, 실행별 토큰, 네이티브 파일 선택창 요청 | 파일 API와 저장 대화상자 |
| `src/js/pdf-render.js`, `src/js/file-loaders.js` 등 | 기존 PDF·문서 처리 기반 | 읽기 전용으로 분리 가능한 렌더링 기능 검토 |

현재 터미널은 재사용 가능한 SFTP 객체를 보유하지 않는다. 업로드도 별도 연결에서 비밀번호 또는 개인키 암호를 다시 받는다. 따라서 **접속 정보는 재사용하되 파일 연결은 별도로 여는 설계**다. 인증 없이 기존 터미널 연결에 파일 전송을 바로 붙일 수 있다고 가정하지 않는다.

## 3. 사용자 흐름과 화면

```text
[파일 업로드] [원격 파일] [연결 끊기]

원격 파일                         student@server:22
원격 파일 경로  /home/student/project/results/chart.png
자동 감지한 현재 폴더: /home/student/project/
확인 경로       /home/student/project/results/chart.png
           [미리보기] [다운로드…]

chart.png · PNG · 1.8 MiB · 서버에서 읽은 시각
[이미지/텍스트/표/PDF 표시 영역]
           [새로고침] [다운로드…] [닫기]
```

1. 연결된 터미널에서 `원격 파일`을 누른다. 터미널 도킹 영역 안에 보조 패널을 열고 기존 문서는 유지한다. 공간이 좁으면 패널과 터미널을 탭으로 전환한다.
2. `원격 파일 경로`에는 Bash 세션이 알려준 현재 폴더를 자동으로 채운다. 파일명을 덧붙이면 이후 폴더 이동이 입력을 덮어쓰지 않는다. 입력을 비우면 자동 경로로 복귀한다. 미지원 셸에서는 `/`로 시작하는 전체 경로를 직접 입력한다. 기준 폴더 입력칸과 현재 경로 조회 버튼은 두지 않으며, 상대 경로나 `~`는 지원하지 않는다.
3. 첫 미리보기·다운로드 때 파일 연결을 인증한다. 인증이 필요한 경우에만 비밀번호 또는 키 암호 입력란을 표시한다.
4. 미리보기는 파일 정보를 확인하고 필요한 양만 가져온다. 파일명·전체 크기·형식·읽은 시각을 표시한다. 부분 내용이면 `앞부분만 표시`를 명시한다.
5. 다운로드는 Windows `다른 이름으로 저장` 창에서 위치를 고른 뒤 전송한다. 저장창 취소는 전송 취소와 구분한다.
6. 미리보기의 `새로고침`은 명시적으로 원격 파일을 다시 읽는다. 기존 화면은 새 결과가 준비될 때 교체하며, 실패하면 기존 내용에 `새로고침 실패 — 이전 내용`을 표시한다.

SSH 접속의 원격 시작 명령으로 Bash 세션에만 알림 기능을 설정한다. `desktop/ssh_shell_integration.bash`는 EXE 내장 리소스이며 프로세스 치환의 파이프로 공급한다. 기존 서버 설정 파일을 생성·수정하지 않는다. Bash의 POSIX 시작 지점에서 기본 동작으로 복귀하고 로그인 프로필을 순서대로 읽은 뒤 기존 `PROMPT_COMMAND` 문자열·배열을 보존하며 현재 폴더 알림을 추가한다. 경로는 UTF-8 바이트 단위로 URI 인코딩한다. 프런트엔드는 새 출력만 순차 해석하고 현재 세션 표식의 알림만 반영하며, 업로드·원격 파일의 수동 입력과 진행 중 요청 경로는 유지한다. Bash 외의 셸은 원래 셸을 로그인 모드로 실행하며 경로는 직접 입력한다. 조회 명령을 PTY 입력에 자동 전송하거나 SFTP 연결에 셸 초기화 코드를 붙이지 않는다.

## 4. 경로와 서버의 의미

- 파일 연결 대상은 ClassDock에서 최초로 연결한 SSH 서버·계정이다. 터미널 안에서 다시 실행한 `ssh`, `sudo`, `docker exec`의 서버·권한·컨테이너를 따라가지 않는다. 패널에 대상 서버와 계정을 항상 표시한다.
- 현재 세션 표식의 OSC 7 알림만 입력 보조로 사용하고, 다른 호스트·세션의 일반 알림은 자동 입력에 사용하지 않는다. 표식은 출력의 상관관계를 확인할 뿐 보안 인증 수단이 아니다. 자동 경로는 원래 Bash가 마지막 프롬프트에서 알려준 폴더이며 중첩 SSH·컨테이너 내부의 현재 폴더를 추적하지 않는다.
- 입력한 전체 경로는 요청 시작 시 고정한다. 전송 중 터미널에서 `cd`를 해도 해당 요청의 경로는 바뀌지 않는다.
- 서버 파일 경로를 Windows `Path.Combine`으로 결합하지 않는다. 첫 지원 대상은 Linux/POSIX 경로이며 Windows SSH 서버 경로 지원은 별도 검증 후 추가한다.
- 상대 경로와 `~` 경로는 거부하고 `/`로 시작하는 전체 경로를 입력하도록 안내한다. 임의로 로그인 홈을 선택하지 않는다.
- 공백·한글·따옴표는 파일명으로 처리한다. NUL·개행·제어문자는 거부하고 와일드카드·환경변수·명령 치환은 수행하지 않는다. `~` 자동 확장은 첫 버전에서 지원하지 않는다.
- 일반 파일만 허용한다. 디렉터리·FIFO·장치 파일은 거부한다. 심볼릭 링크는 대상 경로를 확인·표시하고 최종 대상이 일반 파일이며 해당 계정으로 읽을 수 있을 때만 허용한다.
- SFTP의 루트가 셸과 다른 서버에서는 터미널 경로가 그대로 통하지 않을 수 있다. SFTP에서 보이는 경로를 입력하도록 안내한다.

## 5. 파일별 미리보기 정책

아래 한도는 첫 구현을 위한 제안값이다. 서버가 보고한 크기만 믿지 않고 수신량과 렌더링 자원에도 한도를 적용한다.

| 종류 | 첫 버전 동작 | 제안 한도·대안 |
|---|---|---|
| PNG/JPEG/WebP/GIF/BMP | 화면 맞춤, 확대·축소, 원본 크기 | 파일 20 MiB, 이미지 25메가픽셀. GIF는 첫 프레임 정지 표시. 디코드 시간·메모리 제한 초과 시 다운로드 |
| TXT/LOG/소스/JSON/MD | 읽기 전용 텍스트, 줄 번호, 표시 범위 내 검색 | 앞 1 MiB 또는 10,000줄까지만 표시. 긴 한 줄도 제한. UTF-8 기본, BOM 기반 UTF-16, 필요 시 CP949 선택 |
| CSV/TSV | 읽기 전용 표, 원문 보기 전환 | 앞 1 MiB 안에서 완성된 레코드 최대 1,000행·100열. 수식 실행·자동 형 변환 없음. 파싱 실패 시 원문 |
| PDF | 페이지 이동·확대·축소 | 30 MiB 이하 전체 파일을 받은 뒤 보이는 페이지 위주 렌더. 스크립트·첨부 실행·외부 링크 자동 열기 금지 |
| HTML/SVG/XML | 소스 텍스트로만 보기 | HTML 문서나 SVG로 직접 실행·삽입하지 않음 |
| DOCX/XLSX/PPTX/ZIP/실행 파일/오디오·동영상 등 | 기본 정보와 다운로드 | 첫 버전 전용 미리보기 없음, 자동 실행 없음 |

- 확장자는 힌트이며, 실제 헤더와 내용 검사로 표시 방식을 확인한다. 잘못된 형식은 강제로 렌더링하지 않는다.
- 텍스트의 검색 결과는 전체 파일 검색이 아님을 표시한다. 잘린 멀티바이트 문자나 CSV 레코드는 무리하게 완성하지 않는다.
- 다운로드는 디코딩·변환·잘림 없는 원본 바이트다. 화면의 일부 내용만 저장하지 않는다.
- PDF·이미지 디코더의 자원 제한과 읽기 전용 분리가 완료되어야 해당 형식을 활성화한다. 기존 문서 편집기에 파일을 넘겨 자동 저장·복구 기록에 남기는 방식은 사용하지 않는다.

## 6. 전송과 인증 설계

```text
원격 파일 패널
    │ 메타데이터·작업 요청·상태
    ▼
ClassDock 로컬 API ── 파일 작업 관리자
                         │
                         ├─ SFTP 읽기 전용 연결 ── 기존에 선택한 SSH 서버
                         ├─ 미리보기: 제한된 임시 파일 → 인증된 응답 → 뷰어
                         └─ 다운로드: 저장 폴더의 임시 파일 → 완료 후 최종 이름
```

전송 계층은 **별도 SFTP 연결**을 기본안으로 한다. 파일 메타데이터 조회·부분 읽기·바이트 단위 진행률을 같은 계층에서 처리하고, 파일 경로를 원격 셸 명령에 끼워 넣지 않기 위해서다. OpenSSH는 SSH subsystem 요청을 제공하며 SFTP는 SSH 전송 위에서 동작한다. 근거: [OpenSSH ssh 매뉴얼](https://man.openbsd.org/ssh.1), [OpenSSH sftp 매뉴얼](https://man.openbsd.org/sftp.1).

- 현재 EXE 빌드에 맞춰 Windows OpenSSH `ssh.exe`가 SFTP subsystem을 열고, C# 어댑터가 필요한 파일 프로토콜을 처리하는 방식을 우선 검증한다. PTY 없이 stdin/stdout의 바이너리 스트림을 사용하며 stderr는 진단에만 쓴다.
- 어댑터의 범위는 버전 협상, 경로 확인, 속성 확인, 읽기 전용 열기, 오프셋 읽기, 닫기다. 패킷 길이·요청 ID·동시 읽기 수·응답 시간에 한도를 둔다. SSH 암호화나 인증 프로토콜을 직접 구현하지 않는다.
- 기존 `known_hosts`, 엄격한 호스트 키 검사, 개인키 사본과 askpass 전달 방식은 유지한다. 파일 연결의 키 사본은 해당 연결 수명 동안 유지하고 종료 시 정리한다.
- 파일 연결당 인증은 한 번이다. 진행 중 요청이 없을 때 최대 5분간 연결을 유지해 다음 조회에서 재사용하고, 이후 종료한다. 비밀번호·키 암호는 인증 후 보관하지 않는다. 재연결에는 다시 인증이 필요하다.
- 비밀번호는 URL·명령행·환경변수·로그·브라우저 저장소에 남기지 않는다. 기존처럼 요청 본문에서 받아 일회성 pipe로 전달하며 입력칸과 수신 버퍼를 가능한 즉시 정리한다.
- SFTP가 차단된 서버에는 지원 불가를 알린다. 셸 `cat`이나 구형 SCP로 조용히 우회하지 않는다.
- 현재 별도 업로드 구조를 활용할 수 있어도, SFTP 읽기 어댑터는 새 구현이다. 버튼만 추가하는 작업으로 보지 않는다. Windows OpenSSH와 현재 .NET 빌드에서 바이너리 통신·askpass·취소 호환성을 먼저 확인한다.

## 7. 저장·캐시·취소

- 다운로드는 브라우저 메모리에 전체 파일을 올리지 않고 C#에서 디스크로 스트리밍한다. 표시 한도와 별개로 고정된 전체 파일 크기 상한은 두지 않되 디스크 여유·64비트 파일 크기·진행량을 검사한다.
- Windows 저장창이 선택한 목적지는 서버 측 불투명 ID로 관리한다. 클라이언트가 전달한 임의 로컬 경로에 저장하는 API는 만들지 않는다.
- 원격 이름에서 Windows 예약명, 경로 구분자, ADS 구문 등을 제거해 제안 이름을 만든다. 사용자가 선택한 최종 경로만 사용한다.
- 대상 폴더에 무작위 이름의 임시 파일을 배타적으로 생성한다. 정상 전송·검증 완료 후 최종 이름으로 반영한다. 덮어쓰기는 저장창에서 명시적으로 승인받고, 저장 중 대상 파일이 바뀌면 재확인한다.
- 취소·실패 시 부분 파일을 제거하며 기존 파일은 보존한다. 정리는 작업 관리자가 직접 만든 파일에만 한정한다. 실패한 정리는 기록하고 앱 재시작 시 재시도한다.
- 미리보기 캐시는 사용자 전용 임시 디렉터리에 난수 이름으로 보관한다. 앱 전체 합계 100 MiB, 닫힌 캐시는 즉시 정리하고 사용하지 않는 캐시는 최대 10분 뒤 제거한다. 앱 종료·다음 실행에서도 잔여 캐시를 정리한다.
- 파일 연결 유휴 만료와 미리보기 캐시 만료는 별개다. 연결이 만료되어도 남아 있는 미리보기에는 읽은 시각을 표시할 수 있다.
- 미리보기에서 다운로드를 누르면 기본적으로 원격 파일을 새로 읽는다. 부분 캐시를 전체 원본으로 오인하거나 오래된 캐시를 몰래 저장하지 않는다.
- 전송 전후 크기·수정 시각과 읽은 바이트 수를 비교한다. 변경을 감지하면 `전송 중 파일 변경`으로 실패 처리하고 재시도를 제공한다. 이 검사는 원격 파일의 원자적 스냅샷을 보장하지 않으며, 계속 쓰이는 로그는 정지된 복사본을 권장한다.

## 8. API·작업 수명 제안

아래는 새 API의 계약 초안이며 기존 API는 아니다. 작업 시작 요청은 클라이언트 요청 ID로 중복을 제거한다.

| API | 역할 |
|---|---|
| `GET /ssh-capability` 확장 | 로컬 파일 전송 기능 준비 여부. 서버 SFTP 사용 가능 여부는 실제 연결 때 판정 |
| `POST /ssh-file-connect` | `sessionId`와 인증 정보로 파일 연결 시작, 연결 ID 반환 |
| `POST /ssh-file-inspect` | 연결 ID·경로로 메타데이터 조회 작업 시작 |
| `POST /ssh-file-preview` | 파일 ID로 제한된 읽기·미리보기 준비 작업 시작 |
| `POST /ssh-file-save-pick` | 파일 ID로 Windows 저장창 요청, 선택 결과는 작업 상태로 조회 |
| `POST /ssh-file-download` | 파일 ID·저장 선택 ID로 원본 다운로드 시작 |
| `GET /ssh-file-job?id=` | 상태·수신 바이트·전체 크기·오류·부분 표시 여부 조회 |
| `GET /ssh-file-content?id=` | 완료된 미리보기 바이트만 반환. 임의 로컬 파일 경로 입력 금지 |
| `POST /ssh-file-cancel` | 지정 작업만 취소, 부분 파일 정리 |
| `POST /ssh-file-release` | 파일 핸들·미리보기 캐시 해제 |
| `POST /ssh-file-disconnect` | 파일 연결 종료와 종속 작업 정리 |

- 모든 API는 기존 loopback Host/Origin 검사와 `X-ClassDock-Token`을 적용한다. 새 GET 경로도 `RequiresLocalAuthToken`에 명시적으로 등록한다. 저장창 요청은 기존의 action 헤더 검사도 적용한다.
- 연결 ID → SSH 세션, 파일 ID → 연결, 작업 ID → 파일, 저장 선택 ID → 해당 요청의 관계를 C#에서 검증한다. 프런트엔드의 작업공간 ID만 신뢰하지 않는다.
- 경로·비밀번호·로컬 목적지를 조회 문자열에 넣지 않는다. 내용 응답은 `no-store`, `nosniff`를 적용한다. 인증된 fetch로 받은 제한 크기의 Blob만 표시하고 해제 시 Object URL을 회수한다. 실행별 토큰을 이미지 URL에 넣지 않는다.
- 상태: `대기 → 인증/정보 확인 → 읽는 중 → 표시 준비/저장 중 → 완료`, 모든 진행 상태에서 `취소/실패` 가능. 서버 수신 바이트로 진행률을 계산하며 크기를 모르면 무한 진행 표시를 쓴다.
- 앱 전체 수신 작업은 최대 2개, 작업공간별 미리보기는 1개를 기본값으로 한다. 연결 수는 기존 SSH 세션 최대 4개와 연동해 제한한다. 슬롯 예약·반납은 서버에서 원자적으로 처리한다.
- 작업공간 전환·터미널 접기에는 전송을 유지한다. 패널 닫기는 그 패널의 미리보기만 취소하고 다운로드는 상태 배지와 취소 버튼으로 계속 확인할 수 있게 한다.
- SSH 연결 끊기·작업공간 삭제·앱 종료 시 해당 파일 연결과 진행 작업을 취소한다. 단순 네트워크 단절과 상태 조회 실패도 서버에서 제한 시간 뒤 정리한다.
- 이전 요청의 늦은 응답은 요청 세대 번호로 무시하되 서버 작업도 취소·해제한다. 완료를 확인하지 못한 다운로드는 성공이라고 표시하지 않는다.

## 9. 구현 분리와 완료 기준

| 파일 | 변경 제안 |
|---|---|
| `src/js/remote-terminal.js` | 버튼과 세션·작업공간 수명 연결, 업로드·파일 패널 공통 자동 경로 수신 |
| `desktop/ssh_shell_integration.bash` | 기존 설정 파일을 변경하지 않는 Bash 세션 초기화, 프롬프트별 경로 알림 |
| `src/js/remote-files.js` 신규 | 경로·형식·한도 정책과 파일 작업 클라이언트 |
| `src/js/remote-files-ui.js` 신규 | 미리보기 패널·인증·진행 상태·저장 UI |
| `src/styles.css` | 패널·뷰어·좁은 도킹 영역 대응 |
| `desktop/ssh_terminal.cs` | 기존 인증·세션 정보의 제한된 공유 인터페이스 |
| `desktop/ssh_files.cs` 신규 | SFTP 읽기 어댑터, 작업·캐시·다운로드 관리 |
| `desktop/launcher.cs` | 인증된 API·네이티브 저장창 연결 |
| `desktop/build.bat`, 오프라인 빌드 입력 | 신규 C#·JS 포함 |

구현 순서는 파일 연결·메타데이터·다운로드를 먼저 완성하고, 텍스트·이미지, CSV·PDF, 수명·보안·오류 처리를 통합한다. 이미지·PDF의 자원 제한은 해당 미리보기 출시 전에 함께 완성한다.

검증은 경로와 파일 내용의 바이트 정확성, 인증과 접근 통제, 취소 시 기존 파일 보존을 중심으로 한다. 한글·공백·따옴표 파일명, 누락·권한 거부, 0바이트 파일, 링크·특수 파일, 대용량·디스크 부족, 전송 중 변경·끊김, UTF-8 경계·불완전 CSV, 악성 HTML/SVG·초대형 이미지, 작업공간 전환·삭제, 오래된 응답·중복 요청을 포함한다. 기존 업로드와 대화형 터미널 입력에 회귀가 없어야 한다.

구현을 반영할 때는 코드 검증 후 프로젝트 지침에 따라 실행 중인 `ClassDock.exe`를 종료하고 오프라인 HTML을 생성한 다음 `desktop\build.bat`으로 EXE를 다시 빌드한다. 사용법은 `사용법.md`만 수정하고 HTML은 생성한다. 스크린샷·브라우저 자동화는 사용자가 UI 검증을 명시적으로 요청한 경우에만 실행한다.
