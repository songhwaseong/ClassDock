## 1. 목표와 범위

**한 화면에서 악보를 만들고, 만들면서 바로 듣는다.** 오선 위 자리를 클릭해 음표를 놓고, 도구상자에서 음표 길이·쉼표·임시표를 고르고, 음표 하나를 누르면 그 음이 나고, ▶로 전체 또는 고른 마디만 들려주고, 결과를 **WAV 파일로 저장**한다. 자체 확장자 **`.msheet`(JSON)** 로 저장·재편집한다.

### 결정된 네 가지 (2026-08-13)

| 항목 | 결정 | 이유 |
|------|------|------|
| 녹음 | **작성한 악보 → 오디오 파일 저장**(마이크 아님) | `OfflineAudioContext` 렌더 + WAV 인코딩으로 코덱 의존 없이 무손실. 실시간 대기 없음 |
| 수준 | **동요 단선율**(한 성부, 높은음자리표) | 교실 용도에 충분하고, 조판 난이도가 급감 |
| 렌더 | **VexFlow 도입** | 조판(기둥 방향·꼬리 잇기·간격 배분)을 검증된 코드에 위임 |
| 음색 | **실제 피아노·기타·실로폰·하프·플루트·클라리넷 + 오실레이터 신디사이저** | 실제 녹음은 자연스러운 소리, 합성음은 즉시 동작하는 가벼운 대안. 샘플은 해당 음색을 처음 재생할 때만 지연 로드 |

### 범위
- **포함**: 단선율 한 성부 · 높은음자리표 · 2/4·3/4·4/4·6/8 박자 · 조표(#·b 최대 2개) · 온음표~16분음표와 각 쉼표 · 점음표 · 임시표(#·b·♮) · 음표 클릭 소리 · 전체/부분 재생 · 템포 · WAV 저장 · `.msheet` 저장·열기 · 인쇄용 SVG
- **1차 제외**: 화음(한 자리 여러 음), 두 성부·대소보표, 붙임줄·이음줄, 가사, 셈여림, 반복기호·도돌이, 잇단음표, MusicXML, MIDI 입력

## 2. 데이터 모델 (.msheet 스펙)

`.msheet` 파일 = **UTF-8 JSON 한 개**. `.mnote`와 같이 판별 서명 + 버전을 앞에 둔다.

```jsonc
{
  "format": "manneung-sheet",      // 판별 서명
  "version": 2,
  "title": "학교종",
  "createdAt": 0, "updatedAt": 0,
  "tempo": 100,                     // BPM (40~208)
  "time": { "beats": 4, "beatValue": 4 },
  "key": "C",                       // C G D F Bb … (#·b 최대 2개)
  "clef": "treble",
  "timbre": "piano",                // piano(기본)·guitar·xylophone·harp·flute·clarinet·triangle·sine·square
  "measures": [
    { "id": "m-1", "notes": [
      { "id": "n-1", "rest": false, "step": "G", "octave": 4, "alter": 0,
        "value": "quarter", "dots": 0 },
      { "id": "n-2", "rest": true,  "value": "eighth", "dots": 0 }
    ]},
    { "id": "m-2", "lineBreakBefore": true, "notes": [] } // 선택: 이 마디 앞에서 새 오선 단 시작
  ]
}
```

### 음높이를 VexFlow 표기로 저장하지 않는 이유 — 결정

VexFlow는 음을 `"g/4"` 같은 문자열로 받는다. 그걸 그대로 파일에 저장하면 **파일 포맷이 렌더 라이브러리에 묶인다.** 대신 MusicXML과 같은 결의 `{ step, octave, alter }`로 저장하고, 경계에서 변환한다.

```
{step:"G", octave:4, alter:0}
        ├─→ musicVexNote()  → "g/4"   (화면)
        └─→ musicMidiNumber() → 67 → 391.995Hz (소리)
```

이 변환 두 개가 모델과 바깥을 잇는 **유일한 접점**이다. 나중에 렌더러를 바꾸거나 MIDI 내보내기를 붙일 때 모델은 그대로 둔다.

### 음표 길이 표

| `value` | VexFlow | 4분음표=480틱 기준 | 점 1개 |
|---------|---------|-----|--------|
| `whole` | `w` | 1920 | 2880 |
| `half` | `h` | 960 | 1440 |
| `quarter` | `q` | 480 | 720 |
| `eighth` | `8` | 240 | 360 |
| `16th` | `16` | 120 | 180 |

쉼표는 같은 `value`에 `rest:true`(VexFlow는 `"qr"`처럼 `r` 접미사). 틱은 정수로만 다뤄 부동소수 오차를 없앤다.

### 마디 채움 규칙
- 한 마디의 틱 합 = `beats × (1920 / beatValue)`. 4/4면 1920틱.
- **넘치면 입력을 막고** 안내한다(자동 마디 넘김은 P3). **모자라면** 남은 만큼 렌더 시 빈 자리로 두되, 재생 시에는 그 시간만큼 쉰다.
- 마지막 마디를 뺀 모든 마디가 정확히 차 있는지 `musicValidate()`가 검사하고, 저장은 막지 않되 상태 표시줄에 경고한다.

## 3. 화면 구성

```
┌ 상단바 ─────────────────────────────────────────────────┐
│ 제목  |  ♩=100  4/4  다장조  높은음자리표 |  ↶ ↷  💾  ⬇WAV │
├ 도구상자 ───────────────────────────────────────────────┤
│ [𝅝 𝅗𝅥 ♩ ♪ 𝅘𝅥𝅯] [ · 점] [𝄻 𝄼 𝄽 쉼표] [♯ ♭ ♮] [지우개] [마디+] [오선+] │
├ 악보(VexFlow SVG) ──────────────────────────────────────┤
│  &  ###  4/4  |  ♩  ♩  ♪ ♪  |  ♩  𝄽  ...                │
│                    ▲ 재생 중 이 음표 강조                  │
├ 재생 ──────────────────────────────────────────────────┤
│ ▶ 전체   ▶ 고른 마디(3~6)   ■ 정지   ♩=[100]  음색[△▽]    │
└────────────────────────────────────────────────────────┘
```

### 편집 조작
- **도구상자에서 길이를 고른 뒤 오선을 클릭** → 클릭한 세로 위치의 음높이로 음표 삽입. 오선 밖은 덧줄 2개까지(C4~A5 정도, 동요 음역).
- **음표 클릭** = 선택 + **그 음 소리**(요구사항의 "하나씩 눌러도 소리"). 선택 상태에서 ↑↓로 음 이동, ←→로 이웃 음표 이동, Delete로 삭제.

> **↑↓ 이동 단위 — 결정(2026-08-13, P2 구현 중 변경)**: 처음에는 "반음 이동"으로 적었으나 **흰건반 한 음(도→레→미)** 으로 바꿨다.
> 반음 이동은 임시표(alter)를 계속 바꿔 동요 편집에서 예측하기 어렵고, 화면상 음표가 제자리에 머무는 경우(F→F#)가 생긴다.
> 반음은 도구상자의 ♯·♭·♮ 버튼이 담당하고, **Shift+↑↓는 한 옥타브**로 둔다.
- **마디 클릭(음표 없는 여백)** = 마디 선택. Shift+클릭으로 범위 선택 → 그 범위가 "부분 재생" 대상.
- 도구상자 없이도 되게: 숫자키 1~5 = 온·2분·4분·8분·16분, `R` = 쉼표 토글, `.` = 점.

## 5. 오디오 엔진 설계 (`music-audio.js`)

실제 악기 샘플과 합성음 예약을 `music-audio.js` 하나에 가둔다. 각 악기 녹음은 앱 음역(G3~C6)을 가까운 실제 샘플로 덮고 사이 음은 재생 속도로 보정한다. 플루트·클라리넷은 긴 음표에서 안정 구간을 반복하고 끝에서 릴리스한다.

### 5.1 신호 흐름

```
피아노·기타·실로폰·하프·관악기 → AudioBufferSourceNode(가까운 실제 녹음·playbackRate 보정) ─┐
합성음 → OscillatorNode(sine/triangle/square) ────────────────────┴→ GainNode → master Gain → destination
```

- **주파수**: `440 * 2 ** ((midi - 69) / 12)`
- **ADSR**: attack 0.01s / decay 0.06s / sustain 0.7 / release 0.08s. 게인을 **0에서 시작**해 램프로 올리고 내린다 — 안 그러면 딸깍 잡음이 난다.
- **동시 발음**: 단선율이라 최대 2개(앞 음의 release와 다음 음의 attack이 겹치는 순간)면 충분.
- **음색**: 실제 녹음인 `piano`를 기본으로 하고 `guitar`·`xylophone`·`harp`·`flute`·`clarinet`과 `sine`·`triangle`·`square` 합성음을 함께 노출.
- **지연 로드**: 실제 악기 MP3는 해당 음색의 첫 재생 때만 따로 읽고 디코딩하며, 단일 HTML에서는 악기별로 분리한 실행되지 않는 JSON 데이터 URL 블록에 포함한다.
- `AudioContext`는 **첫 소리 요청 때 생성**하고, 브라우저 자동재생 정책 때문에 **사용자 제스처 안에서 `resume()`** 한다. 문서를 여는 것만으로는 만들지 않는다.

### 5.2 스케줄링 — 정확한 템포의 핵심

`setTimeout`으로 음을 울리면 템포가 흔들린다. **`AudioContext.currentTime` 기준으로 미리 예약**한다.

```
25ms마다 도는 타이머 → 앞으로 100ms 안에 시작할 음들을 지금 예약(osc.start(t) / stop(t2))
```

메인 스레드가 파이썬 실행 등으로 잠깐 밀려도 이미 예약된 소리는 정확히 난다.

**재생 중 음표 강조는 오디오 콜백이 아니라 `requestAnimationFrame`에서** 한다. 예약할 때 만들어 둔 `[{noteId, startTime, endTime}]` 타임라인을 `ctx.currentTime`과 비교해 현재 음표에 클래스를 붙인다. 오디오 스레드에서 DOM을 만지지 않는다.

### 5.3 공개 API

```js
MNMusicAudio.previewNote(note, timbre)      // 음표 하나 미리듣기(클릭 시)
await MNMusicAudio.play(sheet, { from, to, onNote, onEnd }) // 피아노 첫 로드 뒤 재생
MNMusicAudio.stop()
MNMusicAudio.renderWav(sheet, { from, to }) // → Promise<Blob>
```

### 5.4 WAV 저장 — 들리는 것과 저장본을 같게

**핵심 설계: 예약 함수를 컨텍스트에 의존하지 않게 하나로 만든다.**

```js
function scheduleInto(target, destination, events, offset, timbre){ … }   // 실시간·오프라인 공용
```

- **재생**: `scheduleInto(liveCtx, liveCtx.destination, …)`
- **저장**: `new OfflineAudioContext(1, Math.ceil((총초 + 0.5) * 44100), 44100)`에 같은 함수를 태우고 `startRendering()` → `AudioBuffer` → **16bit PCM WAV 인코딩** → `Blob`

같은 코드가 두 경로를 만들므로 "들은 것과 다른 파일이 저장되는" 사고가 구조적으로 막힌다. 오프라인 렌더는 실시간을 기다리지 않아 3분 곡도 1초 안에 끝난다.

WAV 헤더(44바이트, RIFF/fmt /data)는 자체 인코더 40줄 남짓 — 외부 의존 없음.

**저장 경로 주의**: exe에서는 로컬 토큰 때문에 `<a href>`로 서버 파일을 받을 수 없다. 여기서는 메모리 Blob이라 `URL.createObjectURL` + `<a download>`로 충분하고, 원본 폴더에 떨어뜨릴 거라면 `saveTextDoc` 계열의 바이너리 저장 경로를 쓴다.

### 5.5 대기 화면(화면보호기) 충돌 — 확인된 문제와 해법

`screensaverBusy()`는 재생 중 미디어를 `document.querySelectorAll("video,audio")`로 검사한다([screensaver.js:154](../src/js/screensaver.js:154)). **Web Audio 소리는 `<audio>` 요소가 아니라 이 검사에 걸리지 않는다** → 긴 곡을 재생하는 동안 대기 화면이 덮을 수 있다.

**해법: `screensaver.js`를 고치지 않는다.** 같은 함수가 바로 위에서 `.is-running`을 "파이썬/노트북 실행 중"으로 이미 검사하므로([screensaver.js:151](../src/js/screensaver.js:151)), **재생 중에만 악보 편집기 컨테이너에 `is-running` 클래스를 붙였다 떼면** 기존 규칙이 그대로 우리를 보호한다.

## 6. VexFlow 사용 범위 — 경계를 좁게

VexFlow는 **그리기만** 담당한다. 소리·편집·저장은 우리 코드다.

- 넘기는 것: 음자리표·조표·박자표·마디별 `StaveNote` 배열. 꼬리 잇기는 `Beam.generateBeams()`, 간격은 `Formatter`에 맡긴다.
- **자동 줄바꿈은 VexFlow가 해 주지 않는다** → 한 줄에 4마디 고정으로 시작하고(동요는 대부분 4마디 프레이즈), P3에서 컨테이너 폭 기반 계산으로 넓힌다.
- **클릭 좌표 → 음높이 변환은 우리 몫**: `stave.getYForLine(line)`로 각 줄의 y를 얻어 표를 만들어 두고, 클릭 y에 가장 가까운 줄/칸을 고른다.
- 렌더는 **마디 단위 캐시 + 디바운스**. 편집마다 전체 재조판하면 저사양 교실 PC에서 느려진다.
- 버전은 **고정해서 `vendor/`에 내장**하고 `sha384`를 매니페스트에 등록한다. 최근 VexFlow는 TypeScript로 다시 쓰이며 API가 바뀌었으므로, 착수 시 배포본의 전역 이름·API·용량을 먼저 확인한다.

## 11. 조옮김(전조) — 2026-08-13

교실에서 가장 자주 나오는 요구가 "아이들 목소리에 맞게 두 음 올려 주세요"인데 그때까지는 방법이 없었다.
조표 선택(`musicRetuneForKey`)은 **음표를 제자리에 두고 조표만** 갈아끼우는 반대 기능이라, 이걸로는 노래 높이를 못 바꾼다.

### 왜 "반음 몇 개"만으로는 부족한가 — 결정

반음 수는 **소리**만 정하고 **적는 법**은 정하지 않는다. 다장조를 반음 올리면 올림다장조(♯7개)와 내림라장조(♭5개)가
같은 소리다. 그래서 순서를 뒤집어, **새 조표를 먼저 정하고 그 조표에 맞춰 음을 적는다.**

```
1) 새 조표      5도권에서 fifths + 7×반음 → 12로 나눈 나머지가 같은 후보 중 |fifths| 가 작은 쪽
                (같으면 올릴 때는 ♯쪽) → 다장조 +1반음 = 내림라장조
2) 이동 칸수    새 으뜸음이 음이름으로 몇 칸 움직였나(D − C = 1칸)
3) 음 하나하나  이름을 그 칸수만큼 옮기고, 남는 반음 차이를 alter 로 적는다
                C4(60) → 이름 D4(62) → alter = 61 − 62 = −1 → D♭4
```

이름을 한 옥타브(7칸) 어긋나게 잡으면 `alter` 가 12씩 튀므로 **`-2~2` 안에 드는 자리는 하나뿐**이다.
그래서 후보 세 개만 훑으면 답이 유일하게 정해진다(`musicTransposePitch`).

### 지키는 것

| 항목 | 규칙 |
|------|------|
| 범위 | 위아래 한 옥타브(`MUSIC_TRANSPOSE_LIMIT = 12`). 그 이상은 옥타브를 겹쳐 쓰면 된다 |
| 대상 | 네 성부(오른손·왼손 × 성부 1·2) 전부 + 화음음 + **마디별 `keyChange`** 까지 같은 간격으로 |
| 음역 밖 | 막지 않고 **먼저 물어본다**(박자 바꾸기와 같은 규칙). 되돌리기 한 단계로 취소 |
| 적을 수 없는 음 | 옥타브 0~9를 벗어나면 **하나라도 있으면 전부 취소**(`blocked`). 일부만 옮긴 악보는 고치는 것보다 다시 그리는 게 빠르다 |
| 미리보기 | `musicTransposeSheet(sheet, n, { apply:false })` — 같은 코드로 세어만 본다(경고용 계산을 따로 만들지 않는다) |

### 화면

머리말 `조표` 옆의 **조옮김** 버튼과 악보 우클릭 메뉴가 **같은 목록(`transposeContextItems`)** 을 연다.
간격마다 도착할 조표를 미리 적어(`온음(장2도) 올리기 — 라장조`) 누르기 전에 결과를 알 수 있고,
`prompt()` 로 숫자를 받지 않는다(마디 설정의 프롬프트 연속 입력이 남긴 교훈).

`musicPitchFromMidi` 는 이때 만든 표기 함수인데, MIDI 건반 입력에도 같은 표(편집기에 중복돼 있던 것)를 쓰도록 합쳤다.

## 12. 자동 복원 — 저장했는데 다음 실행에 빈 악보가 되던 문제 (2026-08-13 수정)

**증상**: 음표를 넣고 `Ctrl+S` 로 저장한 뒤 앱을 껐다 켜면 그 악보가 **만들 때의 빈 상태**로 열렸다.

**원인**: 자동 복원은 문서를 **열 때 담아 둔 File 바이트**로 되살린다(`workspace-store.js`).
`saveTextDoc` 은 **디스크에만** 쓰고 이 사본은 건드리지 않으며, `readRestoredLocalFile` 이 디스크 최신본을
다시 읽어 오는 확장자는 `.py/.txt/.db` 뿐이라 `.msheet` 는 항상 저장된 사본을 쓴다.
새 악보의 그 사본은 `newMusicScratch` 가 만든 **빈 악보**였다 → 아무리 저장해도 되살아나는 건 빈 악보.

**해결**(다른 문서 종류가 이미 쓰던 공용 헬퍼 두 개를 그대로 붙였다. `workspace-store.js` 는 고치지 않는다):

| 시점 | 부르는 것 | 하는 일 |
|------|-----------|---------|
| 저장 성공 직후 | `markDocumentSavedSnapshot(doc, bytes, "application/json")` | `doc.sourceFile` 과 작업공간 사본을 저장한 내용으로 교체 |
| 편집이 1.5초 멈췄을 때 | `saveDocumentRecoverySnapshot(doc, bytes, "application/json")` | 저장 전에 꺼져도 되살아나게 복구본만 남긴다(원본 파일은 안 건드림) |

`doc.flushBackupRecovery` 도 붙여 백업·종료 경로가 마지막 상태를 한 번 더 밀어 넣게 했다(`backup.js`).

> **주의**: `saveTextDoc` 을 쓰는 문서는 저장만으로 복원 사본이 갱신되지 않는다.
> 새 문서 종류를 붙일 때는 **저장 직후 `markDocumentSavedSnapshot`** 을 잊지 말 것.

같은 구멍이 `.mnote`(`mnote.js` `saveMnote`)와 코드 편집기(`js-editor.js` 저장 버튼·자동 저장)에도
좁게 남아 있었다 — 복구본 디바운스(1.5초) 안에 저장하면 타이머가 `hasUnsavedEdits=false` 를 보고
건너뛰어 그 마지막 편집분만 사라졌다. 2026-08-13 같은 헬퍼로 함께 맞췄다.
