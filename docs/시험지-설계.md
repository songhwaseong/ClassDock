# 시험지 패키지(.exam) 설계

작성: 2026-08-03 · 상태: **구현 완료** — 출제·응시·채점 전 구간
구현: `src/js/exam-paper.js` + 접점(file-loaders·app·command-palette·html 메뉴·styles.css·scripts.manifest)
검사: `tests/exam-paper.test.js`(암호·채점 단위), `tests/e2e/exam-paper.spec.js`(브라우저 한 바퀴)

## 0. 목표와 비목표

**목표**
- 선생님이 **객관식·주관식 문항(이미지 포함)** 으로 시험지를 만들어 한 파일로 배포한다.
- 학생은 더블클릭으로 열어 풀고, **이름·서명** 후 제출본 한 파일을 낸다. 제출 후 답안은 학생이 다시 열 수 없고 해당 기기에서는 시험지가 잠긴다.
- 선생님은 반 전체 제출본을 모아 **자동 채점**하고 수동 O/X 결과를 영구 저장하며 시험별·누적 성적 CSV를 뽑는다.
- 전 과정 **완전 오프라인**(EXE 기준).

**비목표 (정직한 한계)**
- 시험 중 부정행위(화면 캡처·검색·대리 응시)는 막지 않는다. 방어선은 교실 운영이다.
- 제출 전 로컬 초안(localStorage)은 학생 것이다 — 학생이 자기 답을 보는 것은 막지 않는다.
- 선생님 암호 분실 시 복구 경로를 만들지 않는다(복구 경로 = 뒷문).
- 문항 배점은 v1 에서 **전부 1점**(요구사항 확정). 부분점수·가중치는 다루지 않는다.
- 주관식 자동 채점은 글자 비교까지다. 서술형 판단은 선생님 몫이고, UI 는 그것을 "확인 필요"로 드러낸다.

## 1. 왜 파일이 세 개인가

정답을 배포본에 넣으면 암호를 걸어도 새어나간다 — 학생은 시험지를 열기 위해 그 암호를 알아야 하고, 암호를 아는 순간 정답에도 닿는다. 그래서 **배포본에서 정답을 아예 뺐다**. 그러면 채점은 선생님 파일로만 가능해지고, 원본과 배포본이 갈라진다.

| 파일 | 내용 | 잠금 | 보관 |
|---|---|---|---|
| `.examkey` | 문항 + **정답** + RSA 키쌍(공개/개인) | 통째로 **선생님 암호**(PBKDF2+AES-GCM) | 선생님만 |
| `.exam` | 정답을 뺀 문항 + **공개키** | 선택적 **열기 암호**(같은 방식) | 학생 배포 |
| `.examdone` | 답안·서명 봉인 + 평문 학생 이름·제출 시각 | **공개키 봉인**(RSA-OAEP + AES-GCM) | 학생 제출 |

`.examkey` 를 실수로 배포해도 암호 없이는 열리지 않는다. `.exam` 은 뜯어봐야 정답이 없다.

## 2. 제출 후 답안 잠금과 중복 제출 감지

대칭 암호로는 불가능하다 — 시험지를 열 수 있는 학생은 같은 열쇠로 제출본도 열 수 있기 때문이다. 그래서 **공개키 봉인**을 쓴다.

1. 시험지를 처음 저장할 때 RSA-OAEP 2048 키쌍을 만든다. **공개키만 배포본에 들어간다.**
2. 학생이 제출하면 1회용 AES-256-GCM 키로 답안·서명을 암호화하고, **그 키만 공개키로 감싼다**(하이브리드).
3. 개인키는 선생님 암호로 잠긴 `.examkey` 안에만 있다 → **개인키를 가진 선생님만** 제출본을 연다.
4. 제출과 동시에 로컬 초안(`mn.exam.<id>`)을 지우고 `mn.examDone.<id>` 를 남긴다 → 같은 시험지를 다시 열면 "제출 완료" 화면만 뜬다.

즉 학생은 자기가 낸 답안조차 되돌려 볼 수 없다. 해당 기기의 완료 표식은 localStorage 기반이므로 저장소를 지우거나 다른 기기를 쓰면 다시 제출할 수 있다. 암호학적으로 제출 횟수를 제한한다고 주장하지 않으며, 같은 봉인 답안은 파일 지문으로 제외하고 같은 학생의 복수 제출은 채점표에 명시한다.

## 3. 파일 포맷

```json
// .examkey
{ "format":"manneung-exam-master", "version":1, "id":"uuid",
  "meta":{ "title":"2학기 중간고사", "author":"김선생", "createdAt":"…", "updatedAt":"…", "count":20 },
  "enc":{ "alg":"PBKDF2-SHA256/AES-256-GCM", "iter":210000, "salt":"b64", "iv":"b64", "ct":"b64" } }
//   ct 안: { items:[정답 포함 문항], keys:{ alg, publicJwk, privateJwk } }

// .exam
{ "format":"manneung-exam", "version":1, "id":"같은 uuid",
  "meta":{ "title","author","createdAt","count" },
  "itemsHash":"sha256(배포 문항 canonical)",
  "publicJwk":{…}, "locked":false,
  "items":[ { id, type:"choice"|"short", stem, images:[dataUrl], choices:[{text,image}] } ] }
//   locked:true 이면 items 대신 enc(열기 암호 봉투)만 담는다

// .examdone
{ "format":"manneung-exam-result", "version":1,
  "examId","examTitle","itemsHash","student","submittedAt","count",
  "seal":{ "alg":"RSA-OAEP-2048/AES-256-GCM", "sealedKey":"b64", "iv":"b64", "ct":"b64" } }
//   ct 안: { examId, examTitle, student, signature(dataUrl), submittedAt, itemsHash, answers:[{id,type,value}] }
```

- 학생 이름과 제출 시각만 봉인 밖에도 둔다 — 원본을 열기 전 목록용이며 신뢰하지 않는다. 채점표와 CSV는 **봉인 안의 이름·시각**만 기준으로 삼고 외부 값이 다르면 변조·불일치로 표시한다.
- `itemsHash` 는 배포 문항(정답 제거본)의 canonical JSON SHA-256. 배포 후 시험지를 고쳤으면 채점 표에 "다른 버전의 시험지"로 뜬다.
- 상한: 파일 48MB / 문항 100개 / 보기 8개 / 문항당 이미지 4장 / 이미지 합계 12MB(데이터 URL 기준). 이미지는 긴 변 1200px 로 줄여 JPEG 로 재인코딩한다(작은 원본은 그대로 둬 투명 배경 보존).

## 4. 화면

| 화면 | 진입 | 하는 일 |
|---|---|---|
| 시험지 편집기 | 새로 만들기 → 새 시험지 / `.examkey` 열기 | 제목·출제자, 문항 추가·순서·복제·삭제, 지문/이미지, 보기와 정답, 주관식 정답(`\|` 구분)·느슨한 비교 |
| 학생 응시 | `.exam` 더블클릭 | 문항 렌더, 보기 클릭·주관식 입력, 자동 임시 저장, 이름·서명 패드, 제출 |
| 채점 | 새로 만들기 → 시험 채점 / `.examdone` 더블클릭 / 편집기의 [🗂 채점하기] | 원본 열기(암호), 제출본 다중 추가, 버전 일치 확인, 자동 채점 표, 답안 상세(O/X 수동 조정·서명 확인), 성적 자동 저장과 시험별·누적 CSV |

- 채점 화면은 **한 번에 하나만** 둔다(여러 탭에 흩어지면 어느 표에 넣었는지 헷갈린다).
- 서명 패드는 pdf-editor.js 의 `trimCanvas`(여백 자동 제거)를 있으면 재사용한다.
- 저장 동선은 `.task` 와 동일 — EXE 로컬 서버가 있으면 저장 폴더에 바로 쓰고 [폴더 열기], 없으면 다운로드.

## 5. 채점 규칙 (v1: 문항당 1점)

- **객관식**: 고른 번호 == 정답 번호. 완전 자동.
- **주관식**: 정답 목록(`잎|leaf`) 중 하나와 일치하면 정답. 기본은 **공백 제거 + 소문자 변환** 후 비교(문항별로 끌 수 있음).
- 주관식이 자동으로 안 맞았고 **답이 비어 있지 않으면** "확인 필요"로 센다(무응답은 확인할 것이 없다).
- 선생님이 답안 상세에서 O/X 를 누르면 그 값이 점수의 기준이 되고, [자동 채점으로 되돌리기]로 원래 판정으로 복귀한다.

## 7. 환경 제약

WebCrypto(`crypto.subtle`)는 보안 컨텍스트에서만 동작한다. EXE 는 `http://127.0.0.1` 로 서빙되어 문제없지만, 오프라인 HTML 을 `file://` 로 열면 브라우저가 막는다. 그래서 시험지 만들기·열기·제출·채점의 **첫 관문에서 확인하고 EXE 사용을 안내**한다(다 풀고 나서 제출 못 하는 사태를 막기 위해 배포본 열기 시점에 미리 검사).
