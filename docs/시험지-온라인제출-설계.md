# 시험지 온라인 제출(교실 LAN) 설계

작성: 2026-08-03 · 상태: **1단계 구현 완료 · 교실 실측 전**
전제 문서: `docs/시험지-설계.md`(포맷·봉인·채점은 그대로 따른다)
구현: `desktop/launcher.cs`(제출 전용 리스너·제어 엔드포인트), `src/js/exam-paper.js`(제출 받기 패널·보내기), `src/styles.css`
검사: `tests/e2e/exam-paper.spec.js`(보내기 실패 → 파일 폴백)

## 0. 목표와 비목표

**목표**
- 학생이 [제출 확정하기]를 누르면 제출본이 **선생님 PC로 바로 들어간다**. USB·메신저로 파일을 옮기는 단계를 없앤다.
- 선생님은 받은 제출을 **파일로 받은 것과 구분 없이** 그대로 채점한다.
- 교실 네트워크가 막혀 있으면 **막혔다고 알려 주고 파일 제출로 흘러간다**. 실패가 예외가 아니라 정상 경로다.

**비목표 (정직한 한계)**
- 인터넷 경유·외부 서버는 만들지 않는다. 학생 이름과 **서명 이미지**가 학교 밖으로 나가면 안 된다.
- 이름 사칭을 막지 않는다. 파일 제출과 동등한 수준이며, 방어선은 봉인 속 서명과 교실 운영이다.
- 학생 PC를 관리하지 않는다. 원격 제어·화면 감시·강제 제출은 다루지 않는다.
- 선생님 PC가 꺼져 있거나 세션이 닫혀 있으면 제출은 실패한다. 대기열을 두어 나중에 보내지 않는다(제출 시각이 흐려진다).

**전제**
- 선생님·학생 모두 **EXE**를 쓴다. 오프라인 HTML(`file://`)은 WebCrypto가 막혀 애초에 응시 자체가 불가하다(`시험지-설계.md` 7절).
- 같은 교실 LAN. 무선 AP의 단말 격리(client isolation)가 켜져 있으면 이 기능은 동작하지 않는다 — **도입 전에 반드시 확인해야 한다**.

## 1. 왜 기존 서버에 얹지 않는가

EXE의 로컬 서버는 `IPAddress.Loopback` 에만 바인딩하고(`launcher.cs`), Host 헤더가 `127.0.0.1`/`localhost` 가 아니면 거부하며, 파일을 쓰는 요청은 페이지에 심은 토큰(`X-Manneung-Token`)을 요구한다. 이건 실수가 아니라 설계다 — 그 서버에는 `/save-file`, `/workspace-save` 처럼 **디스크를 건드리는 통로**가 열려 있다.

여기에 외부 접속을 허용하면 제출 하나 받자고 그 통로 전체를 교실 네트워크에 노출하게 된다. 그래서 **제출 전용 리스너를 따로 연다.** 기존 리스너는 손대지 않는다.

## 2. 통로 — 제출 전용 리스너

선생님이 제출 받기를 켤 때만 `0.0.0.0:17650`(점유 시 다음 후보)에 리스너를 연다. 아래 세 경로가 전부이고, 나머지는 전부 404다. 기존 엔드포인트는 **이 리스너에 존재하지 않는다.**

| 경로 | 용도 | 인증 |
|---|---|---|
| `OPTIONS /exam-submit` | CORS + Private Network Access 사전 응답 | 없음 |
| `GET /exam-hello?code=` | 학생의 [연결 확인] — 세션 열림 여부와 시험 제목만 | 코드 |
| `POST /exam-submit` | 본문은 `.examdone` JSON 그대로 | 코드(`X-Exam-Code`) |

사전 응답은 `launcher.cs` 의 `/tile-proxy` 처리(`Access-Control-Allow-Origin: *` + `Access-Control-Allow-Private-Network: true`)를 그대로 따른다. 학생 앱은 `http://127.0.0.1:<자기포트>` 에서 서빙되므로 선생님 IP로 보내는 요청은 크로스 오리진이고, 사설 대역이라 PNA 사전 요청이 먼저 온다.

로컬 토큰은 쓸 수 없다 — 학생 PC에는 선생님 PC의 토큰이 없다. 대신 **세션 코드 + 열려 있는 동안만 + 경로 화이트리스트** 세 겹으로 막는다.

## 3. 받은 제출을 어떻게 다루는가

`SaveRoot/제출함/<시험제목>/<학생>_<시각>.examdone` 로 **파일로 떨어뜨린다.** 메모리에만 들고 있지 않는다 — 앱이 죽어도 제출본이 남아야 하고, 그래야 파일로 받은 제출과 같은 물건이 된다.

화면에는 접수 목록을 폴링해 새 것만 `examAddSubmissions()` 로 넣는다(파일을 다시 읽지 않는다 — 목록이 곧 방금 받은 원문이다). 채점 로직·중복 판정·성적부는 **한 줄도 바뀌지 않는다.**

## 4. 검증과 한도

`POST /exam-submit` 이 받아들이는 조건:

- 세션이 열려 있고 코드가 일치한다 (틀리면 403, 안 열렸으면 409)
- 본문 ≤ 1MB, `format`/`version` 이 `.examdone` 규격에 맞는다
- 선생님이 지금 채점 중인 시험의 `examId` 와 같다 (다르면 거부하고 화면에 알린다)
- 같은 봉인 해시가 이미 있으면 저장하지 않고 `이미 접수됨` 을 200으로 돌려준다

한도: IP당 분당 N건, 세션당 총 300건, 세션은 앱 종료 시와 마지막 활동 후 일정 시간이 지나면 자동으로 닫힌다.

**중복을 200으로 돌려주는 이유:** 저장은 됐는데 응답이 유실되면 학생 화면은 실패로 보인다. 학생이 다시 누를 때 오류가 나면 "낸 건가 안 낸 건가"가 된다. 두 번째 시도가 조용히 성공하는 쪽이 안전하다.

## 5. 화면

**선생님 — 채점 화면 위 제출 받기 패널**

```
[ 제출 받기 시작 ]
  → 주소  192.168.0.12 : 17650      제출 코드  418203
    받은 제출  12개                              [ 받기 끝내기 ]
```

- 코드는 세션마다 새로 만든다(6자리).
- 열려 있는 동안 **"제출 받는 중"이 화면에서 사라지지 않는다.** 모르는 사이 열려 있으면 안 된다.
- 1~2초 폴링으로 들어온 제출이 그대로 채점표에 쌓인다.

**학생 — 제출 상자**

`선생님 PC로 보내기` 선택과 주소·코드 입력을 둔다. 한 번 넣으면 기억해 다음 시험에 그대로 뜬다. [제출 확정하기] → 봉인 → 전송 → 접수증(봉인 해시 앞 8자리)과 접수 시각을 보여 준다.

봉인은 **전송 전에** 끝낸다. 봉인에 실패하면 전송 자체를 시도하지 않는다(현재 동작 유지).

## 6. 실패했을 때

답안이 사라질 수 있는 경우에만 파일로 저장한다. 코드를 잘못 친 경우까지 파일을 만들면 폴더가 실패한 제출본으로 지저분해진다.

| 상황 | 안내 | 파일 저장 |
|---|---|---|
| 연결 실패·시간 초과(4초) | "선생님 PC에 연결하지 못했어요. 같은 와이파이인지 확인하고, 안 되면 파일로 내세요." | **자동 저장** |
| 코드 불일치(403) | "제출 코드가 달라요. 칠판의 6자리를 확인하세요." | 안 함 |
| 세션 미개방(409) | "선생님이 아직 제출 받기를 시작하지 않았어요." | 안 함 |
| 시험이 다름 | "선생님이 받고 있는 시험이 아니에요." | 안 함 |
| 주소 형식 오류 | 누르기 전에 입력칸에서 표시 | — |

선생님 쪽에서 방화벽에 막혀 리스너가 열리지 않으면 그 자리에서 "방화벽 허용이 필요해요 · 파일로 받으려면 그대로 진행하세요"로 안내하고 기존 방식으로 흘러간다.

**어느 경로로 실패하든 제출 확정 자체는 성립한다** — 로컬 완료 표식(`mn.examDone.<id>`)은 지금과 동일하게 남는다.

## 7. 구현 메모 (1단계에서 정해진 것)

- 선생님 화면의 제어는 **루프백 서버**의 토큰 필요 엔드포인트다: `POST /exam-receive-start`(본문 `{examId,title}`), `POST /exam-receive-stop`, `GET /exam-receive-status?since=N`. 학생이 쓰는 제출 전용 리스너와 통로 자체가 다르다.
- 화면은 `since` 이후 접수분만 받아 `examAddSubmissions()` 로 넘긴다. 1.5초 간격이며 문서를 닫으면 `cleanupFns` 로 멈춘다.
- **중복 판정은 제출본 바이트의 SHA-256** 이다. 같은 봉인을 다시 보내면 중복이고, 학생이 처음부터 다시 제출하면 봉인이 새로 만들어져(다른 IV) 별개 제출로 접수된다 — 같은 학생의 복수 제출은 지금처럼 채점표가 드러낸다.
- 요청 본문은 `Content-Length` 로만 읽는다(chunked 미지원). 브라우저 `fetch` 는 문자열 본문에 항상 길이를 붙이므로 실사용 경로에는 영향이 없다.
- 학생 쪽 주소·보내기 여부는 `localStorage`(`mn.examSendAddr`, `mn.examSendOn`)에 남지만 **코드는 남기지 않는다**(세션마다 바뀐다).
- 접수번호는 지문 앞 8자리다. 학생 화면의 제출 완료 패널과 `mn.examDone.<id>` 에 함께 남아 다시 열어도 보인다.

## 8. 검증

같은 PC에서 대부분 검증된다. 학생 앱이 `127.0.0.1:17650` 으로 보내면 코드 경로는 교실과 동일하다 — 코드 불일치·세션 미개방·중복 제출·크기 초과·시험 불일치를 전부 여기서 확인한다.

e2e 로는 **리스너가 없을 때 파일 폴백으로 떨어지는지**를 잡아 둔다(가장 중요한 회귀 지점).

교실 실측은 마지막에 한 번 필요하다: 단말 격리 여부, 방화벽 승인, 30명 동시 제출.
