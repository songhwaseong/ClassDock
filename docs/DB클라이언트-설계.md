# ClassDock DB 클라이언트 1·2차 설계

> 1차(MySQL)는 구현 완료. 아래 내용은 실제로 만들어진 것을 기준으로 한다.

## 범위

- ClassDock.exe에서 호스트, 포트, 데이터베이스, 계정, 비밀번호로 원격 관계형 DB에 접속한다.
- 스키마 탐색(데이터베이스 → 테이블·뷰 → 컬럼), 테이블 데이터 미리보기, SQL 편집기와 실행, 결과 표를 제공한다.
- 1차 버전은 MySQL·MariaDB만 다룬다. 드라이버는 `pymysql`이며 이미 `vendor/wheels/pymysql-1.2.0-py3-none-any.whl`로 번들되어 있다.
- 2차 버전은 같은 구조에 Oracle을 얹는다. 드라이버는 `python-oracledb` thin 모드로, Oracle Instant Client를 요구하지 않는다. 휠 번들 가능 여부는 아래 "미확인 항목"에서 먼저 확인한다.
- 접속은 기본이 읽기 전용이다. 쓰기는 접속마다 사용자가 명시적으로 켜야 하며 켠 상태가 화면에 계속 보인다.
- 브라우저 단독 HTML은 TCP로 DB에 붙을 수 없다. SQLite 뷰어와 같은 문구로 EXE 전용 안내를 표시한다.
- 로컬 Python이 없으면 기능 전체를 쓸 수 없다. SQLite 미리보기와 동일한 제약이며 같은 안내와 같은 '다시 검사' 경로를 쓴다.
- 범위 밖: 스키마 편집 GUI, ERD 그리기, 마이그레이션, 저장 프로시저 디버깅, 접속 개수 무제한, SSH 터널 경유 접속.

## 왜 문서 탭인가

원격 터미널처럼 도킹 패널로 만드는 방안을 먼저 검토했지만 두 가지가 걸렸다. 도킹은 `main` 에 거는
`ssh-dock-left` · `--ssh-dock-width` 로 SSH 전용이라 두 번째 패널을 만들려면 배치 코드를 복제하고
같은 자리를 두고 경합해야 한다. 그리고 520px 폭은 결과 그리드에 좁다.

접속을 `.dbconn` 문서로 두면 탭·작업공간·백업·최근 파일이 전부 기존 문서 구조를 그대로 따라오고,
콘텐츠 영역 전체를 쓰며, 접속 하나가 탭 하나라 여러 서버를 동시에 열 수 있다. 접속 파일 자체를
학생에게 나눠 줄 수도 있다(비밀번호는 들어 있지 않다).

## 왜 SQLite 뷰어 방식을 그대로 쓸 수 없나

SQLite 미리보기는 `launcher.cs`가 임시 Python 스크립트를 만들고 한 번 실행한 뒤 stdout JSON을 읽는 one-shot 구조다(`SqlitePreviewRunner`, `RunSqliteRunner`). 원격 DB에는 이 구조가 맞지 않는다.

- 매 쿼리마다 새로 접속하면 왕복 지연이 쿼리 시간보다 커진다.
- 트랜잭션, 임시 테이블, 세션 변수, `USE` 로 바꾼 현재 스키마가 쿼리 사이에 유지되지 않는다.
- 실행 중인 쿼리를 취소할 대상 커넥션이 남아 있지 않다.

그래서 접속 하나당 상주 Python 워커를 하나 띄운다. 이 구조는 새로 만드는 것이 아니라 노트북 커널(`desktop/python_kernel.py`)이 이미 쓰고 있는 방식이다. stdin으로 base64 JSON 한 줄을 받고 stdout으로 base64 JSON 한 줄을 돌려주며, 프로세스가 살아 있는 동안 상태를 유지한다.

## 구성

```text
스키마 트리 / SQL 편집기 / 결과 표  (src/js/db-client.js)
  │  JSON 요청 · JSON 응답
  ▼
127.0.0.1 ClassDock API (실행별 토큰 필요)
  │
  ▼
db_worker.py — 접속 하나당 상주 프로세스 1개
  │  stdin: base64 JSON 라인 / stdout: base64 JSON 라인
  │
  ├─ pymysql ──────── MySQL · MariaDB      (1차)
  └─ oracledb(thin) ── Oracle 12.1 이상     (2차)
       ▲
       └─ 비밀번호는 접속 직후 첫 handshake 라인으로만 전달
```

## 사용자 흐름

1. 사이드바 `+ → 새 DB 접속(.dbconn)`으로 접속 문서를 만들거나, 이미 있는 `.dbconn` 파일을 연다.
2. 호스트, 포트, 데이터베이스, 계정, 비밀번호를 입력한다. 쓰기 허용 여부를 여기서 정한다(기본은 읽기 전용).
3. 드라이버 패키지가 없으면 설치 버튼을 보여 준다. 기존 `/pip-install-start` 와 진행 로그 폴링을 그대로 쓰고, `vendor/wheels` 덕분에 MySQL은 인터넷 없이 설치된다.
4. 접속에 성공하면 왼쪽에 스키마 트리, 오른쪽 위에 SQL 편집기, 오른쪽 아래에 결과 표가 나온다.
   가운데 세로 분할선을 끌어 스키마 패널 폭을, 편집기와 결과 사이 가로 분할선을 끌어 편집기 높이를 조절한다.
   각각 더블클릭하면 기본값으로 돌아간다. 편집기의 브라우저 기본 resize 손잡이는 끈다 —
   컨테이너 높이와 textarea 높이를 두 방식이 각각 정하면 서로를 덮어써 화면이 어긋난다.
   문서 탭 하나가 접속 하나이므로 여러 서버를 탭으로 나란히 열 수 있다.
5. 트리에서 테이블을 고르면 컬럼 정의와 상위 N행 미리보기를 보여 준다. 카운트는 큰 테이블에서 느려질 수 있어 별도 버튼으로 뺀다.
   `DDL 보기`는 `SHOW CREATE TABLE` 결과를 값 패널에 띄운다(뷰에도 그대로 쓴다).
   트리의 `▸`를 누르면 그 테이블의 컬럼이 펼쳐지고, 컬럼 이름이나 테이블 옆 `＋`를 누르면 편집기 커서 자리에 이름이 들어간다.
   평범한 식별자가 아닌 이름(공백·한글·숫자로 시작)은 역따옴표로 감싸서 넣는다. 트리 펼치기는 컬럼만 따로 받아 온다 — 미리보기 200행을 함께 끌어올 이유가 없다.
6. SQL 편집기에서 실행한다. 무엇이 실행될지는 선택과 커서가 정한다.

   | 상황 | 실행 대상 |
   |---|---|
   | 선택 영역이 있음 | 선택한 글자 그대로 |
   | 선택 없음 + `Ctrl+Enter` | 커서가 놓인 문장 하나 |
   | `Ctrl+Shift+Enter` 또는 `전체 실행` | 편집기의 모든 문장 |

   DBeaver·MySQL Workbench·DataGrip 이 공통으로 쓰는 규칙이다. 커서가 문장 사이 빈 곳에 있으면
   바로 앞 문장을 고른다. 실행 버튼의 이름은 지금 무엇이 실행되는지에 따라 바뀐다
   (`선택 실행` / `현재 문장 실행`) — 겉모습이 같은 버튼이 상황마다 다르게 동작하는 것이 규칙보다 위험하다.
   여러 결과 집합이 나오면 결과 탭으로 모두 볼 수 있고, 걸린 시간을 함께 표시한다.
   첫 페이지(1000행)를 넘는 결과는 `더 보기`로 이어 받는다.
   결과 헤더를 누르면 그 컬럼으로 정렬한다. 받아온 행을 다시 늘어놓지 않고 문장의 `ORDER BY` 를
   고쳐 서버에 다시 묻는다 — 1000행에서 잘린 결과를 정렬하면 "전체에서 가장 큰 값"처럼 보이는 거짓말이 되기 때문이다.
   편집기 내용은 건드리지 않는다 — 정렬은 결과를 보는 방식이지 사용자가 쓴 문장을 고치는 일이 아니다.
   대신 결과 줄에 `정렬 · ORDER BY ...` 로 무엇이 적용됐는지 적어 편집기와 지금 보는 결과가 다르다는 것을 알린다.
   같은 컬럼을 누를 때마다 오름차순 → 내림차순 → 해제로 돌고, 정렬 클릭은 실행 이력을 채우지 않는다.
   `SELECT` 계열이 아니거나(`SHOW` 는 `ORDER BY` 를 받지 못한다) 문장이 4000자를 넘어 잘려 왔으면 정렬을 걸지 않는다.
   화살표 표시는 실제로 실행된 문장의 `ORDER BY` 에서만 읽는다 — 클릭 기록으로 만들면 사용자가 손으로 고쳤을 때 거짓말을 한다.
   편집기는 파이썬·자바스크립트 편집기와 같은 위젯(`buildCodeEditor`)을 쓴다. 되돌리기(Ctrl+Z)·줄 삭제(Ctrl+D)·
   줄 이동(Alt+↑↓)·줄 복제(Ctrl+Alt+↓)·찾기(Ctrl+F)·줄 이동(Ctrl+G)·사각 선택·괄호 자동 짝·줄 번호를
   여기서 다시 만들지 않고 그대로 얻는다. `plain:true` 로 파이썬 전용 지능(Jedi 질의·import 추론)은 끈다.
   `Ctrl+/`는 위젯이 처리하며 SQL 프로파일이라 `--` 를 붙인다.
   `Ctrl+Space`는 위젯의 자동완성을 연다. 후보는 SQL 키워드 + 현재 데이터베이스의 테이블·컬럼이며,
   `completionWords` 배열을 위젯이 참조로 붙들고 있어 접속 뒤 스키마가 오면 그 자리에서 채운다.
   `별칭.` 뒤에서는 `memberCandidates` 훅이 그 별칭이 가리키는 테이블의 컬럼만 준다.
   편집기가 고정 높이(`overflow:hidden`)라 목록은 `completionPortal` 로 body 에 띄운다(노트북 셀과 같은 이유).
   `실행 계획`은 지금 실행할 문장 앞에 `EXPLAIN` 을 붙여 실행하고 편집기는 그대로 둔다.
7. 실행이 길어지면 진행 표시와 취소 버튼이 나온다. 취소는 워커가 별도 커넥션으로 `KILL QUERY`(Oracle은 `Connection.cancel()`)를 보내 끊는다.
8. 문장이 둘 이상이면 결과가 탭으로 갈린다. 표를 낸 문장뿐 아니라 `INSERT`·`UPDATE` 같은 문장과 실패한 문장도 탭 하나를 차지한다 —
   무엇이 어느 순서로 실행됐는지가 결과 자체만큼 중요하기 때문이다. 탭 이름에는 그 문장의 앞머리를 함께 적는다(`2 · UPDATE score SET… · 3행 반영`).
   중간에 오류가 나면 거기서 멈추되 **그때까지의 결과를 함께 그리고** 멈춘 탭을 먼저 연다. 앞의 문장은 이미 서버에서 실행됐으므로
   (자동 커밋이면 확정된 상태다) 무엇이 반영되고 무엇이 안 됐는지 보여 주지 않으면 사용자가 알 길이 없다.
   앞의 결과가 셀 예산(12,000)을 다 써서 한 줄도 싣지 못한 결과에는 그 사실을 적는다 — "데이터가 없다"와 구분해야 한다.
9. 결과 표는 칸 단위로 고른다. 칸을 끌면 사각 범위, 왼쪽 번호 칸은 그 행 전체, 컬럼명은 그 열 전체, 왼쪽 위 모서리는 표 전체다.
   Shift 로 넓히고 Ctrl 로 더하거나 뺀다(이미 다 고른 범위를 Ctrl 로 끌면 빼기가 된다). `Ctrl+C` 는 고른 칸을 탭 구분 글자로 복사하고
   (`Ctrl+A` 전체, `Esc` 해제) NULL 은 빈칸으로 보낸다 — 붙여 넣는 곳에서 "NULL" 이라는 글자를 값으로 받으면 안 된다.
   그래서 표에는 글자 드래그 선택을 끈다(`user-select:none`). 칸을 끄는 동작과 글자를 긁는 동작이 같은 드래그를 두고 다투기 때문이다.
   값 일부만 복사하는 일은 셀 값 창의 `값 복사` 가 맡는다. 정렬은 컬럼명 오른쪽 화살표 버튼으로 옮겼다 — 머리 전체가 정렬 버튼이면 열을 고를 자리가 없다.
   칸마다 리스너를 달지 않고 표 하나에서 위임으로 받는다(1,000행 × 20열이면 리스너가 2만 개가 된다).
   고른 자리를 칠할 때도 바뀐 칸과 머리 구간만 다시 칠한다 — 교실 PC 에서 표 전체를 매번 훑으면 끌린다.
10. 결과 표는 CSV·엑셀로 내보내거나 스프레드시트 문서로 열 수 있다. `table-export.js`와 `spreadsheet-viewer.js`를 그대로 쓴다.
   셀을 더블클릭하면 그 칸이 열린다(클릭은 고르는 일, 더블클릭은 여는 일 — ERD 의 테이블 카드와 같은 규칙이다).
   고칠 수 없는 결과에서는 예전처럼 값 전체를 보는 창이 열린다.
   그리드는 한 줄로 줄여 그리므로 여러 줄 값과 긴 값은 여기서만 온전히 읽힌다.
   서버에서 500자로 잘라 온 셀은 `⋯` 표시가 붙고 창이 그 사실을 밝힌다 — 잘린 값을 전부인 것처럼 보여 주지 않는다.
   예전에는 결과 아래 패널이 늘 자리(32vh)를 차지했는데, 모달로 옮겨 결과 표를 그만큼 넓게 쓰고 큰 값도 크게 본다.
   `Esc` 는 맨 위의 창부터 닫는다 — ERD·테이블 정보 창이 셀 값 창에 양보한다.
   ⚠ 표의 `pointerdown` 에서 `preventDefault` 를 부르면 뒤따르는 `click`·`dblclick` 까지 막힌다.
   글자 드래그 선택은 CSS 의 `user-select:none` 이 막으므로 그 자리에서 `preventDefault` 를 부르지 않는다.
10-1. 값 창에서 그 칸의 값을 고칠 수 있다(1단계 — 칸 하나씩). 고칠 수 있는 결과에서만 `값 고치기` 버튼이 보인다.
    무엇을 고칠 수 있는지는 프런트가 짐작하지 않고 워커가 판정해 결과에 실어 보낸다. 열 이름만으로는 별칭·조인·계산식을
    가릴 수 없기 때문이다 — 드라이버가 서버에서 받아 둔 필드 메타데이터(`org_table`·`org_name`)를 봐야 어느 테이블 어느 컬럼인지 알 수 있다.
    조건은 이렇다. ① 한 베이스 테이블에서 온 결과일 것(조인·뷰·집계는 잠긴다) ② 그 테이블의 기본키가 결과에 모두 실려 있을 것.
    칸 단위로는 기본키 칸(행을 짚는 근거라 값 수정과 다른 이야기다), 계산식 열, 이진 컬럼, 생성 컬럼이 잠기고 잠긴 까닭을 창이 밝힌다.
    고치기를 누르면 미리보기 SQL 이 함께 뜬다 — GUI 로 고친 일이 어떤 `UPDATE` 가 되는지 보여 준다(SQL 을 배우는 도구라 감추지 않는다).
    `빈 값(NULL)으로 두기` 는 따로 체크한다. NULL 과 빈 문자열은 다른 값이라 입력칸 하나로 가를 수 없다.
    여러 줄 값도 다루므로 `Enter` 는 줄바꿈이고 저장은 `Ctrl+Enter` 다. 고치던 중의 `Esc`·바깥 클릭은 창이 아니라 고치기를 먼저 접는다.
    `담기` 를 누르면 그 칸에 표시가 남아 무엇을 고쳤는지 보인다. 아직 서버에는 가지 않았다(아래 10-2).
    ⚠ 표에 실린 값은 500자에서 잘려 있을 수 있다. 그 글자를 그대로 저장하면 서버의 값이 잘린 채로 덮이므로,
    잘린 칸과 NULL 칸은 고치기를 열 때 원본을 서버에서 다시 읽는다. 기본키가 잘려 온 행은 그 값으로 행을 짚을 수 없어 아예 열지 않는다.
    ⚠ 조건에 옛 값을 섞지 않는다(낙관적 잠금을 쓰지 않는다). 표의 값은 글자로 옮겨진 것이라(`FLOAT`·`DATETIME` 소수부·잘린 텍스트)
    아무도 바꾸지 않았는데 0행이 반영되는 일이 잦다. 대신 고친 뒤 같은 조건으로 다시 읽어 "값이 이미 같았다"와 "그 행이 사라졌다"를 가른다.
    ⚠ 이진 컬럼 판정은 컬레이션 번호만 보면 안 된다. MySQL 은 숫자·날짜 컬럼도 이진 컬레이션(63)으로 알려 주기 때문에
    그것만 보고 잠그면 `INT`·`DATETIME` 이 전부 고칠 수 없는 칸이 된다. 컬레이션과 자료형을 함께 봐야 `BLOB`·`BINARY` 만 걸린다.

10-1-1. 칸을 고르고 **바로 타자를 치거나 `F2`** 를 누르면 그 자리가 입력칸이 된다(3단계).
    `Enter` 는 담고 아래 칸으로, `Tab`·`Shift+Tab` 은 담고 옆의 고칠 수 있는 칸으로 옮겨 이어서 연다. `Esc` 는 되돌린다.
    칸 밖을 누르면 담는다(엑셀과 같다). 방향키로 칸을 옮기고 `Shift+방향키` 로 범위를 넓힌다 —
    그러지 않으면 `Enter` 뒤에 어디로 갈지 정할 수 없고, 결과 영역만 스크롤되어 지금 칸을 잃는다.
    담기는 값 창과 같은 길(`stageUpdate`)을 쓴다. 입력하는 자리만 다를 뿐 무엇이 담기는지·언제 서버에 가는지는 하나다.
    ⚠ 한 줄짜리 입력칸이라 **여러 줄 값과 잘려 온 값은 여기서 고치지 않고 값 창으로 보낸다** —
    `input` 은 값에 든 줄바꿈을 조용히 지우므로 그대로 담으면 서버의 줄이 사라진다.
    ⚠ NULL 칸을 빈 채로 두고 지나가면 아무 일도 하지 않는다. 빈 문자열은 NULL 과 다른 값이라
    "그냥 지나갔다"를 "빈 문자열로 바꿔라"로 읽으면 안 된다(빈 문자열과 NULL 은 값 창에서 가른다).
    ⚠ 한글 IME 는 `keydown` 이 `Process`(229)로 온다. 그때는 `preventDefault` 하지 않고 입력칸만 열어
    조합이 그 칸에서 시작되게 한다 — 막으면 첫 글자 조합이 끊긴다(`spreadsheet-viewer.js` 가 같은 이유로 같은 방식을 쓴다).
    칸을 여는 길은 하나로 모았다(`openCellAt`) — **두 번 누르기·`F2`·타자가 모두 같은 길**이다.
    고칠 수 있으면 그 자리에서 열리고, 그러지 못하면 값 창이 열린다. 값 창은 긴 값·여러 줄 값·NULL 을 다루는 자리이자
    고치지 못하는 까닭(기본키 칸·계산식 열·이진·뷰·조인)을 밝히는 자리다. 길이 하나여야 "어떨 때 무엇이 열리는지"를
    한 문장으로 설명할 수 있다 — 두 번 누르기만 다른 일을 하면 규칙이 둘이 된다.
10-2. 고친 칸은 곧바로 서버로 가지 않는다. **변경 목록에 담겼다가 `적용` 을 누를 때 한 묶음으로 나간다**(2단계).
    값 창의 `담기`, 결과 도구의 `행 추가`·`행 삭제` 가 모두 같은 목록에 쌓이고, 담긴 것이 있으면 결과 위에 변경 바가 나온다.
    담은 칸은 노랗게, 지울 행은 빨간 취소선으로 표시된다 — 지금 화면과 서버가 다르다는 사실을 계속 알리기 위해서다.
    `미리보기` 는 나갈 문장을 그대로 늘어놓고 하나씩 뺄 수 있게 한다. 전부 복사해 SQL 편집기에 붙여 넣을 수도 있다.
    쓰는 길을 하나로 모은 것이 요점이다. 칸 하나만 따로 쓰는 길을 남겨 두면 트랜잭션 규칙이 둘로 갈린다.
    ⚠ 되돌리기는 **적용 전에만** 있다(목록에서 빼기·모두 취소). 적용한 뒤에는 자동 커밋이면 이미 확정이고,
    수동 커밋이면 툴바의 `롤백` 이 그 일을 맡는다. 그래서 적용 확인창이 지금 어느 쪽인지 함께 알린다.
    표를 다시 그리면 담아 둔 변경은 되돌릴 자리를 잃는다. 그래서 다시 조회·정렬·테이블 미리보기·연결 끊기 앞에서 먼저 묻는다.
11-1. `행 삭제` 는 고른 칸이 걸친 행을 담는다(왼쪽 번호 칸을 누르면 그 행 전체가 골라진다). 조건은 언제나 기본키다.
    `행 추가` 는 결과에 실린 열만으로는 부족하므로 테이블 정의(`mode=info`)를 읽어 컬럼 전체를 늘어놓는다.
    컬럼마다 `기본값`·`값`·`NULL` 중 하나를 고른다 — 적지 않은 칸은 서버의 기본값이 채운다.
    빈 문자열을 넣어 버리지 않으려면 이 셋을 가르는 자리가 있어야 한다. 자동 증가·생성 컬럼은 사람이 채우지 않는다.
11-2. 적용은 한 묶음이 통째로 되거나 통째로 안 된다. ⚠ 수동 커밋 모드에서 `rollback()` 을 부르면 사용자가 앞서 쌓아 둔
    커밋하지 않은 변경까지 사라지므로, 세이브포인트(`SAVEPOINT classdock_edit`)를 걸어 이 묶음만 되돌린다.
    자동 커밋 모드에서는 문장마다 확정되어 세이브포인트가 뜻이 없으므로 묶음을 트랜잭션으로 연다(`begin` → `commit`).
    문장 순서는 고치기 → 지우기 → 넣기다. 지운 기본키를 같은 묶음에서 다시 넣을 수 있다.
    반영 0행은 두 가지다. **사라진 행을 고치라는 요청은 실패로 본다** — 말없이 아무 일도 일어나지 않는 것이 제일 나쁘다.
    **사라진 행을 지우라는 요청은 뜻이 이미 이루어진 것**이라 몇 건인지만 알린다. 값이 이미 같았던 경우와는 행 존재 확인으로 가른다.
    적용한 뒤에는 결과를 다시 조회한다 — 지운 행·넣은 행까지 화면에 맞추는 가장 정직한 방법이다.
11. 쓰기 허용 접속이면 툴바에 `자동 커밋` 토글과 `커밋`·`롤백` 이 나온다. 토글을 끄면 그 뒤의 쓰기 문장은 커밋을 눌러야 확정되고,
   확정하지 않은 변경이 있는 동안 `커밋 대기` 배지가 켜진다. 자동 커밋으로 되돌릴 때 남은 변경이 있으면 커밋할지 먼저 묻는다
   (되돌리려면 롤백을 먼저 누른다). 실행 중에는 세 컨트롤 모두 잠긴다 — 워커 요청이 `ExecLock` 으로 직렬화되므로 끼어들 수 없다.
12. `SQL 열기` 는 `.sql` 파일을 읽어 편집기에 넣는다(실행하지는 않는다). 파일 선택은 브라우저 입력으로 끝나고 서버에 올라가지 않는다.
    한글 주석이 든 덤프는 CP949 인 경우가 많아 코어의 `detectTextEncoding` 으로 인코딩을 고른 뒤 읽는다.
    쓰던 SQL 이 있으면 덮어쓸지 먼저 묻고, 1MB 를 넘으면 한 번 더 묻고, 8MB 를 넘으면 받지 않는다(편집기가 감당하지 못한다).
    `DELIMITER` 로 시작하는 프로시저 덤프는 문장 나누기(세미콜론)가 다루지 못하므로 불러올 때 그 사실을 알린다.
13. `저장`(또는 `Ctrl+S`)은 호스트·포트·데이터베이스·계정·쓰기 허용 여부·자동 커밋 여부·표시색과 편집기의 SQL 을 `.dbconn` 파일에 적는다. 비밀번호는 적지 않는다.
   `Ctrl+S` 는 자체 처리기를 두지 않고 저장 버튼에 `run-save` 클래스를 붙여 앱의 전역 `saveCurrent` 경로가 눌러 주게 한다(두 경로가 겹치지 않게).
14. 탭을 닫거나 접속을 끊으면 워커 프로세스와 서버 커넥션을 정리한다. 커밋하지 않은 변경이 있는 채로 `연결 끊기` 를 누르면
    한 번 묻는다 — 커넥션이 닫히는 순간 서버가 롤백하므로 말없이 사라지게 두지 않는다.
15. 실패한 접속은 원인을 구분해 안내한다. 인증 실패, 호스트를 찾을 수 없음, 연결 거부, 방화벽·타임아웃, 드라이버 미설치, 지정한 데이터베이스 없음, 권한 없음.

## 보안 원칙

- 비밀번호는 localStorage, 앱 상태, 파일, 명령행, 환경변수, 로그에 저장하지 않는다. 원격 터미널과 같은 기준이다.
- 비밀번호는 워커를 띄운 직후 stdin으로 보내는 첫 handshake 라인에만 실린다. 프로세스 인수로 넘기지 않는다. `SqliteExec`가 SQL을 stdin으로 넘기는 방식과 같다.
- 워커의 stderr는 프런트에 그대로 흘리지 않는다. 드라이버 예외 문자열에 접속 문자열이 섞여 나오는 경우가 있어, 분류한 코드와 다듬은 메시지만 내보낸다.
- DB 요청 API는 기존 loopback Host/Origin 검사와 `X-ClassDock-Token` 검증을 모두 거친다.
- 호스트·포트·데이터베이스·계정은 허용 문자와 길이를 검사한다. 검사는 C# 쪽에서 하고, 통과한 값도 워커에는 JSON 필드로만 넘겨 명령행에 닿지 않게 한다.
- 사용자가 쓴 SQL은 문자열 조작 없이 그대로 드라이버에 넘긴다. 앱이 SQL을 다시 쓰거나 이어 붙이지 않는다.
- 셀 편집의 값도 SQL 에 이어 붙이지 않는다. 워커가 `UPDATE … SET `col` = %s WHERE `pk` = %s` 를 만들고 값은 드라이버 자리표시자로 보낸다.
  런처는 이름과 값을 JSON 값으로 옮기기만 하고 SQL 을 만들지 않는다. 값 창의 미리보기 문장은 사람이 읽으라고 만든 글자이고
  서버로 나가지 않는다 — 따옴표 처리를 프런트가 떠맡는 순간 NULL·숫자·날짜 구분이 무너진다.
- 셀 편집은 읽기 전용 접속에서 판정 이전에 잠긴다. 쿼리 경로에만 읽기 전용을 걸어 두면 셀 편집이 뒷문이 된다.
- 표를 고치는 길은 `apply-edits` 하나다. 칸 하나만 따로 쓰는 길을 남겨 두면 트랜잭션·되돌리기 규칙이 둘로 갈린다.
  런처는 변경 갈래(`update`·`delete`·`insert`) 이름만 알아보고 나머지는 JSON 값으로 옮긴다. 문장은 언제나 워커가 만든다.
- 읽기 전용 접속은 안내 문구가 아니라 서버에서 건다. 세션에 `SET SESSION TRANSACTION READ ONLY` 를 걸면
  autocommit 상태에서도 각 문장이 세션 기본 접근 모드를 물려받아 쓰기가 1792 로 거절된다.
  프런트의 낱말 검사는 친절한 메시지를 위한 것이고 최종 판단은 서버가 한다.
- autocommit 은 기본으로 켠다. 끄면 `SELECT` 하나가 트랜잭션을 열어 유휴 상태에서도 스냅샷과 언두를 붙들고 있어,
  오래 열어 둔 접속이 서버의 다른 작업을 방해한다. 사용자가 `BEGIN`/`COMMIT` 을 직접 쓰면 그대로 동작한다.
- 쓰기 허용 접속에 한해 툴바에서 자동 커밋을 끌 수 있다(수동 커밋 모드). 실수한 `UPDATE`를 롤백으로 되돌리려면
  트랜잭션이 열려 있어야 하는데, 그 대가가 위 문단의 잠금·언두 유지다. 그래서 기본값이 아니라 사용자가 그때그때 켜는 스위치로 둔다.
  대가를 감추지 않기 위해 화면이 세 곳에서 알린다 — 커밋하지 않은 변경이 있으면 `커밋 대기` 배지, 자동 커밋으로 되돌릴 때 확인,
  연결을 끊기 전 확인. 읽기 전용 접속에는 확정할 것이 없으므로 이 스위치를 아예 감춘다.
- 자동 커밋 여부는 워커가 커넥션에 직접 건다(`connect(autocommit=...)`·`connection.autocommit()`). 앱이 `SET autocommit` 문장을
  만들어 끼워 넣지 않는다 — 사용자가 쓴 SQL 에 앱이 문장을 이어 붙이지 않는다는 원칙과 같다.
- 커밋하지 않은 변경 유무(`pending`)는 프런트가 짐작하지 않고 워커가 응답에 실어 보낸다. `CREATE`·`ALTER`·`DROP` 같은
  암묵적 커밋 문장 뒤에는 되돌릴 것이 남지 않으므로 워커가 그 표시를 지운다 — 롤백하면 돌아온다고 오해하게 두지 않는다.
- 쓰기 모드에서 `DROP` · `TRUNCATE` · `WHERE` 없는 `DELETE`/`UPDATE`는 실행 전에 한 번 더 확인받는다. 확인은 차단이 아니라 되돌릴 수 없는 문장을 알아보게 하는 장치다.
  검사 대상은 편집기 전체가 아니라 이번에 보낼 것만이다. 아래에 적어 둔 `DROP` 때문에 위의 `SELECT` 하나에도 확인창이 뜨면 아무도 확인창을 읽지 않게 된다.
- 접속마다 표시색을 고를 수 있다. 운영 DB 를 빨강으로 두면 어느 탭에서 실행하는지 한눈에 구분된다. 색 이름은 정해진 목록의 값만 받는다(임의 문자열이 CSS 선택자에 들어가지 않게).
- 워커는 접속을 연 사용자의 권한 그대로 동작한다. 앱이 권한을 대신 넓히거나 관리자 계정을 권하지 않는다.

## 로컬 API

- `GET /db-capability` — Python 유무와 `pymysql` 설치 여부·버전
- `POST /db-session-open` — 워커 기동과 접속. 본문은 길이 접두 문자열(호스트·포트·DB·계정·비밀번호·읽기전용·자동커밋).
  뒤의 두 값은 없으면 기본값(읽기 전용·자동 커밋)으로 읽는다
- `GET /db-schema?id=` — 데이터베이스 목록과 현재 DB 의 테이블·뷰
- `GET /db-table?id=&name=&mode=` — `table`(기본, 컬럼 정의와 상위 200행) · `columns`(컬럼만) · `count`(전체 행 수) · `ddl`(`SHOW CREATE TABLE`).
  런처는 아는 `mode` 만 워커에 넘긴다.
- `POST /db-use?id=&name=` — 현재 데이터베이스 전환
- `GET /db-schema?id=&mode=columns` — 자동완성용 전체 컬럼 목록
- `GET /db-page?id=&set=&offset=&limit=` — 보관해 둔 결과에서 다음 페이지
- `POST /db-query?id=` — SQL 실행 시작. 즉시 job id 반환
- `GET /db-query-poll?job=` — 진행 상태 또는 결과 조회
- `POST /db-query-cancel?job=` — 실행 중인 쿼리 취소
- `POST /db-cell?id=` — 고치기 전에 값 전체를 다시 읽는다(표의 값은 500자에서 잘려 있을 수 있다)
- `POST /db-apply?id=` — 담아 둔 변경을 한 묶음으로 적용한다. 본문은 길이 접두 문자열의 평평한 줄이다 —
  데이터베이스·테이블·건수에 이어 변경마다 갈래와 그 값이 온다. ⚠ 프런트가 싣는 차례와 런처가 읽는 차례가
  어긋나면 값이 엉뚱한 칸으로 들어간다(테스트로 두 쪽을 함께 묶어 두었다)
- `POST /db-tx?id=&op=` — `commit` · `rollback` · `autocommit`(`&on=0|1`) · `state`. 런처는 아는 `op` 만 워커에 넘긴다
- `POST /db-session-close?id=` — 커넥션과 워커 종료

런처에는 JSON 파서가 없다. 워커는 응답 한 줄을 `'+'`(성공) 또는 `'-'`(실패) + base64(JSON) 으로 내고,
런처는 첫 글자로 성공 여부만 판단해 본문은 열어 보지 않고 그대로 브라우저에 넘긴다.

모든 API는 EXE가 HTML에 주입한 실행별 로컬 토큰을 요구한다. 실행을 시작만 하고 폴링으로 결과를 받는 형태는 `/pip-install-start` · `/pip-install-poll` 과 같은 모양을 따른다.

## 한도

- 동시 접속 4개. 원격 터미널의 동시 세션 상한과 같은 기조다.
- 셀 하나는 500자에서 자르고, 잘린 셀의 좌표를 함께 보내 화면이 그 사실을 밝힐 수 있게 한다.
- 걸린 시간은 워커가 `time.perf_counter()` 로 잰 값만 쓴다. 프런트에서 재면 폴링 간격(300ms)이 섞여 빠른 쿼리가 느리게 보인다.
- 한 번에 보내는 결과는 1000행, 총 12000셀. 그 뒤로 5000행(또는 10만 셀)까지는 워커가 들고 있다가 `더 보기` 로 이어 준다.
  임의의 SQL 에 `LIMIT`/`OFFSET` 을 덧붙이지 않는다 — 이미 `LIMIT` 이 있는 쿼리가 망가지기 때문이다.
  보관 상한까지 읽고도 서버에 더 남아 있으면 `더 보기` 를 감추고 그 사실을 문장으로 알린다.
- 자동완성 후보는 현재 데이터베이스의 컬럼 5000개까지. 넘으면 자동완성만 덜 똑똑해지고 접속은 그대로 쓴다.
- 결과 1000행, 총 12000셀. SQLite 미리보기의 셀 예산과 같은 값을 쓴다. 잘린 결과는 표 위에 명시한다.
- 셀 하나는 500자에서 자르고 BLOB은 `<BLOB n bytes>`로 대체한다. SQLite 미리보기와 같은 표시 규칙이다.
- 쿼리 기본 제한 시간 60초. 초과하면 취소하고 사용자가 다시 늘려 실행할 수 있게 안내한다.
- 워커 프로세스는 유휴 30분이면 스스로 종료한다.
- 한 번의 실행이 화면에 싣는 총량은 12,000셀이다. 여러 문장이 이 예산을 나눠 쓰므로, 앞의 결과가 크면 뒤의 결과가 밀린다.
  밀린 결과는 워커가 보관한 것을 `더 보기` 로 불러오거나 그 문장만 따로 실행하면 된다.
- "더 보기"용으로 보관하는 결과 집합은 4개까지다. 그보다 뒤의 결과는 첫 페이지만 보인다.

## 미확인 항목

Oracle 지원을 결정하기 전에 아래 두 가지를 실제로 확인한다. 확인 전에는 2차 범위를 확정하지 않는다.

- `python-oracledb` 휠을 `vendor/wheels`에 오프라인 번들할 수 있는가. thin 모드는 Oracle 클라이언트를 요구하지 않지만 패키지 자체는 플랫폼·파이썬 버전별 휠이고 `cryptography` 의존이 붙는다. `pymysql`처럼 파일 하나로 끝나지 않으면 온라인 `pip install`만 지원하고 그 사실을 화면에 밝힌다.
- 학교·기관이 실제로 쓰는 Oracle 버전이 12.1 이상인가. thin 모드는 11g 이하에 붙지 못한다. 대상이 11g면 Instant Client가 필요하고, 그러면 1차 범위에서 뺀다.

확인 방법은 대상 파이썬에서 `pip download oracledb --only-binary=:all: -d vendor/wheels` 를 돌려 받아지는 파일과 의존성을 보는 것이다.

## 검증 항목
- 조인·뷰·`GROUP BY` 결과에서는 `값 고치기` 가 뜨지 않고 그 까닭이 창에 적히는지
- 기본키가 없는 테이블, 기본키를 빼고 조회한 결과에서 편집이 잠기는지
- 500자에서 잘린 칸을 고칠 때 원본 전체를 다시 읽어 오는지(잘린 글자가 저장되지 않는지)
- NULL 로 두기와 빈 문자열이 서로 다른 값으로 저장되는지, `NOT NULL` 컬럼에서 NULL 이 막히는지
- 같은 값으로 저장했을 때 "바뀐 것이 없다"고 하고, 다른 곳에서 지운 행을 고칠 때 "행을 찾지 못했다"고 하는지
- 수동 커밋 모드에서 셀을 고치면 `커밋 대기` 가 켜지고 롤백으로 되돌아가는지
- 읽기 전용 접속에서는 편집 UI 가 아예 뜨지 않는지
- 칸을 고르고 한글을 바로 쳤을 때 첫 글자가 사라지지 않는지(IME 조합이 그 칸에서 시작하는지)
- 여러 줄 값·잘려 온 값에서 F2 나 두 번 누르기를 하면 값 창이 대신 열리는지
- 읽기 전용 접속·조인 결과에서 두 번 누르기가 예전처럼 값 창을 여는지(값을 읽는 길이 막히지 않았는지)
- NULL 칸에서 F2 를 누르고 빈 채로 Enter 를 눌렀을 때 아무것도 담기지 않는지
- Enter 로 아래 칸, Tab 으로 옆 칸으로 옮겨 가며 여러 칸을 이어서 담을 수 있는지
- 담은 변경이 있는 채로 다시 조회·정렬·테이블 미리보기·연결 끊기를 하면 먼저 묻는지
- 미리보기의 문장이 실제로 나가는 문장과 같은지, `빼기` 로 하나만 뺄 수 있는지
- 여러 칸을 담아 한 번에 적용했을 때 하나가 실패하면 나머지도 반영되지 않는지(수동 커밋에서 앞서 쌓아 둔 변경은 남는지)
- `행 추가` 에서 자동 증가 컬럼을 비워도 들어가는지, `기본값` 으로 둔 칸에 빈 문자열이 들어가지 않는지
- 지울 행을 다른 곳에서 먼저 지웠을 때는 넘어가고, 고칠 행이 사라졌을 때는 묶음 전체가 실패하는지

자동 검사로 덮은 것(`tests/db-client.test.js`, 16건):

- 접속 문서 직렬화에 비밀번호가 들어가지 않고, 깨진 문서도 읽기 전용 기본값으로 안전하게 읽힌다
- 세미콜론 나누기가 따옴표·역따옴표·주석 안의 세미콜론을 구분자로 보지 않는다
- 프런트(확인 창)와 워커(실행 단위)의 문장 나누기가 같은 입력에 같은 결과를 낸다
- 되돌릴 수 없는 문장(`DROP`·`TRUNCATE`·`WHERE` 없는 `DELETE`/`UPDATE`)만 확인 대상으로 골라진다
- 비밀번호가 명령행·환경변수가 아니라 stdin 의 connect 요청으로만 건너간다
- 읽기 전용을 서버가 걸고(`SET SESSION TRANSACTION READ ONLY`), 취소가 응답을 만들지 않는다
- `/db-` API 가 GET·POST 양쪽에서 로컬 토큰을 요구하고, 워커가 EXE 리소스로 포함되며 종료 시 정리된다
- 자동 커밋 여부를 접속 요청이 정하고(읽기 전용은 언제나 켬), 커밋·롤백·전환이 모두 같은 세션으로 나간다
- 커밋하지 않은 변경 유무를 워커가 알려 주고, 암묵적 커밋 문장 뒤에는 그 표시가 지워진다
- 여러 문장 중 하나가 실패해도 그때까지의 결과를 `statements` 에 담아 돌려주고, 화면이 멈춘 자리를 먼저 연다
- 탭 이름이 문장 앞머리를 밝히고, 예산에 밀린 결과에 `budgetExhausted` 가 붙는다
- 표 칸 고르기 셈(범위·더하기/빼기·경계·TSV 옮기기)이 스프레드시트와 같은 모듈에서 나오고, 정렬이 화살표 버튼에만 걸린다

실제 서버로 확인할 것:

- Python 없는 PC, Python은 있으나 드라이버가 없는 PC, 둘 다 있는 PC의 안내와 설치 흐름
- 인터넷이 끊긴 상태에서 `vendor/wheels`만으로 `pymysql` 설치
- 접속 성공·인증 실패·호스트 오류·연결 거부·타임아웃·없는 데이터베이스·권한 없음의 원인별 안내
- 한글 데이터와 한글 테이블·컬럼 이름의 표시, `utf8mb4` 와 다른 문자셋 서버
- `NULL`, 빈 문자열, BLOB, 날짜·시간, `DECIMAL`, 매우 긴 텍스트의 표시 구분
- 여러 문장 실행, 결과가 없는 문장(`INSERT` 등)의 영향 행 수 표시
- `SELECT` 두 개를 선택해 실행하면 결과 탭 두 개가 각각의 표를 그리는지
- UTF-8 과 CP949 로 저장한 `.sql` 파일을 각각 `SQL 열기` 로 불러왔을 때 한글 주석이 깨지지 않는지
- 세 문장 중 두 번째에서 오류를 내면 첫 문장의 결과가 남고 오류 탭이 열리는지
- 큰 `SELECT` 뒤의 `SELECT` 가 예산에 밀렸을 때 안내가 뜨고 `더 보기` 로 이어 볼 수 있는지
- 1,000행짜리 결과에서 칸 끌기·행/열 고르기·표 전체 고르기가 교실 PC 에서 끌리지 않는지
- 고른 칸을 `Ctrl+C` 로 복사해 엑셀에 붙여 넣었을 때 행·열이 그대로 들어가고 NULL 이 빈칸으로 오는지
- 컬럼명을 눌러 열을 고르는 것과 화살표를 눌러 정렬하는 것이 서로 끼어들지 않는지
- 셀을 더블클릭하면 값 창이 열리고, 칸을 끌어 고르는 동작과 서로 끼어들지 않는지
- ERD·테이블 정보 창 위에서 셀 값 창을 열고 `Esc` 를 눌렀을 때 값 창만 닫히는지
- 읽기 전용 접속에서 쓰기 문장이 서버에서 거부되는지 확인
- 쓰기 모드에서 `DROP` · `TRUNCATE` · `WHERE` 없는 `DELETE`의 확인 창
- 수동 커밋 모드에서 `UPDATE` 후 롤백하면 값이 되돌아오고, 커밋하면 다른 접속에서도 보인다
- 수동 커밋 모드에서 `ALTER TABLE` 뒤에는 `커밋 대기` 가 꺼지고 롤백해도 되돌아오지 않는다(MySQL 암묵적 커밋)
- 커밋하지 않은 채 연결 끊기·탭 닫기·유휴 30분 종료를 했을 때 변경이 서버에 남지 않는다
- 1000행·12000셀을 넘는 결과의 잘림 표시와 남은 행 안내
- 긴 쿼리 실행 중 취소, 취소 뒤 같은 접속에서 이어서 쿼리 실행
- 60초 초과 쿼리의 자동 취소와 제한 시간 조정 후 재실행
- 서버가 커넥션을 끊은 뒤(`wait_timeout`) 다음 쿼리의 재접속 또는 명확한 안내
- 트랜잭션 유지 확인: 임시 테이블 만들고 다음 쿼리에서 조회
- 결과 표의 CSV·엑셀 내보내기와 스프레드시트 문서로 열기
- 분할선 드래그의 `pointerup`·`pointercancel` 정리(터치가 끊긴 뒤 폭이 손을 따라다니지 않는지)
- 창을 좁혔을 때 편집기가 사라지지 않는지(스키마 패널 상한), 분할선을 끝까지 내려도 결과가 남는지(편집기 높이 상한)
- 작업공간 전환·삭제 시 접속 유지와 정리, 창 닫기·앱 종료 시 워커 프로세스 정리
- 동시 접속 상한을 넘긴 시도의 안내
- 유휴 30분 뒤 워커 종료와 재접속
- 비밀번호가 명령행·환경변수·로그·`app-state.json`·진단 로그 어디에도 남지 않는지 확인
- HTML 단독 실행 시 EXE 전용 안내
- 이름 해석 실패와 연결 거부가 서로 다른 안내로 갈리는지(pymysql 은 둘 다 errno 2003 으로 감싼다)
