## 0. 먼저 조사한 것 — 이미 있는 기능

설계 전에 지금 코드를 훑었다. **처음 추천했던 "코드 기호 → 자동 반주"는 이미 구현되어 있다**(`musicAccompanimentPattern` · `drumStyle` · `accompanimentMode:"drums"|"bass"|"full"`). 그래서 이 문서에서 뺐다.

| 이미 있음 | 근거 |
|---|---|
| 가사(음표당 한 음절) | `note.lyric`(80자), `music-lyric` SVG 텍스트 |
| 코드 기호 + 자동 반주(드럼·베이스·코드) | `musicParseChordSymbol` · `musicAccompanimentPattern` |
| 도돌이·1·2번 괄호 (재생도 따라감) | `musicPlaybackMeasureIndexes` |
| 파트 여러 개(파트별 음색·음량·음소거·MIDI 트랙) | `musicPart` · `musicTimeline({partId})` |
| 조옮김(악보 전체) | `musicTransposeSheet` |
| MIDI 입출력 · MusicXML 왕복 · WAV 저장 · 메트로놈·카운트인 | `exportMusicMidi` · `music-xml.js` · `renderWav` · `timeline.metronome`·`countInBeats` |

| 없음 (이 문서가 설계하는 것) | 왜 실무에서 걸리나 |
|---|---|
| **가사 여러 절**(1·2·3절) | 교가·동요 악보는 절이 여러 개다. 지금은 1절만 적힌다 |
| **마디 번호 · 연습 기호 · 한 줄 마디 수** | 합주에서 "32마디부터", "B부터"가 안 된다. 줄 나눔이 폭 자동이라 인쇄본마다 마디 위치가 달라진다 |
| **이조 악기 파트**(B♭ 클라리넷·E♭ 알토색소폰 등) | 밴드부 파트보를 손으로 옮겨 적어야 한다 |
| **파트 연습 음원 일괄 저장** | 합창·합주 파트 연습용 음원을 파트마다·템포마다 손으로 만든다 |

## 1. P1 — 가사 여러 절

### 1.1 데이터

```jsonc
{ "id":"n-1", "step":"G", "octave":4, "value":"quarter",
  "lyric":"학",                      // 1절 (예전 판이 읽는 자리 — 계속 씀)
  "lyrics":["학","우"] }             // 2절 이상일 때만 추가. lyrics[0] === lyric
```

| 결정 | 내용 | 이유 |
|---|---|---|
| 배열을 새로 두되 `lyric`을 남긴다 | 읽기: `lyrics` 있으면 그것, 없으면 `[lyric]` · 쓰기: 절이 1개면 `lyric`만, 2개 이상이면 **둘 다** | 예전 `.msheet`·예전 버전 앱·MusicXML 어느 쪽으로 가도 **1절은 반드시 살아남는다**. `musicSerialize`의 "빈 값은 쓰지 않는다" 규칙도 지켜진다 |
| 절 개수는 악보 한 곳에 | `sheet.lyricVerses`(1~6) | 음표마다 배열 길이가 들쭉날쭉하면 화면 높이 계산이 음표마다 달라진다. 절 수는 문서의 성질이다 |
| ~~화면 표시 `sheet.lyricVerseView`~~ → **두지 않았다** | 늘 모든 절을 함께 그린다 | 구현하며 접었다. 인쇄도 그림도 **화면에 그린 그 SVG**를 그대로 쓰므로 "보기는 한 절, 인쇄는 전부"를 지키려면 렌더를 한 벌 더 돌려야 한다. 상태를 하나 없애 화면·그림·인쇄가 언제나 같은 악보를 보여 주는 쪽을 택했다. 지금 넣는 절(`lyricVerse`)만 편집기 안의 보기 상태로 남는다 |
| 빈 절은 늘 처음부터 | `lyricStartIndex()` | 구현하며 추가했다. 1절 이어치기를 끝낸 자리에서 2절 붙여넣기가 시작하면 절이 통째로 어긋난다. 이미 가사가 있는 절(=고치는 중)만 고른 음표부터 이어 간다 |

파일 버전 `9 → 10`.

### 1.2 화면 — 창을 음표마다 여는 지금 방식을 버린다

지금 `가사` 버튼은 고른 음표 하나에 대해 입력 창을 연다. 4절짜리 동요면 창을 수백 번 연다.

- **가사 ▾** 메뉴: `절 고르기(1~6)` · `이어치기` · `한 줄 붙여넣기` · `이 절 지우기`
- **이어치기**: 켠 뒤 고른 음표부터 그냥 친다. `Space`/`Enter`=다음 음표, `Backspace`(빈칸에서)=이전 음표, `-`=한 음표를 두 음절로 나눠 쓰는 표시(`가-사`), `Esc`=끝.
  따라치기(`musicPractice…`)가 이미 쓰는 **"편집 입력을 한 곳으로 몰아 잠그는"** 방식을 그대로 빌린다.
- **한 줄 붙여넣기**: `학교 종이 땡땡땡`을 붙여 넣으면 음절 단위로 앞에서부터 배분한다. 쉼표·붙임줄로 이어진 뒷 음표는 건너뛴다(관례). 배분 결과는 **되돌리기 한 번**으로 취소된다(`history.commit()` 한 번).

### 1.3 그리기 — 줄 높이가 고정이라는 함정

지금 한 단의 높이는 상수다. 절이 늘면 아랫단과 겹친다.

```js
const MUSIC_LINE_HEIGHT = 205;   // 가사·셈여림·페달이 다음 단과 겹치지 않을 간격
```

- `musicScoreLineHeight(sheet)` 한 함수로 모으고 `MUSIC_LINE_HEIGHT + (절 수 - 1) * MUSIC_LYRIC_ROW_GAP(17)`을 돌려준다.
- **이 값을 쓰는 곳이 두 군데다** — 화면 렌더(`music-editor.js:1671`)와 그림·메모 발췌(`:4282`). 둘 다 새 함수로 바꾸지 않으면 "메모로 보낸 악보만 가사가 잘리는" 증상이 난다. 인쇄는 화면 SVG를 그대로 쓰므로 따라온다.
- 절 번호(`1.`, `2.`)는 각 단 **첫 마디 왼쪽**에만 작게 적는다.

### 1.4 MusicXML

- 내보내기: `<lyric number="1"><text>…</text></lyric>`를 절 수만큼. ~~`<syllabic>`~~ 은 적지 않는다 — 우리 모델은 음절 이음을 사람이 친 `-` 글자로만 알고 있어 begin/middle/end 를 지어내면 틀린 정보를 내보내게 된다(들일 때도 `<text>`만 읽는다).
- 들이기: 지금은 첫 `<lyric>`만 읽는다(`music-xml.js:265`). `number` 속성으로 모아 배열로 만든다. 6절을 넘으면 자르고 알린다.

`tests/music-model.test.js` — 절 배분(쉼표·붙임줄 건너뜀), 1절만 있으면 `lyrics`를 쓰지 않음(같은 모델 = 같은 바이트), 6절 상한, MusicXML 왕복.

## 2. P2 — 마디 번호 · 연습 기호 · 한 줄 마디 수

### 2.1 데이터

```jsonc
{ "measureNumbers": "line",     // "off" | "line"(단의 첫 마디) | "every" | 5(N마디마다)
  "barsPerLine": 0,             // 0=자동(지금 방식) · 2~8=고정
  "measures": [ { "rehearsal": "A" } ] }   // 연습 기호(최대 6자)
```

| 결정 | 이유 |
|---|---|
| 마디 번호 기본값은 `"line"` | 악보 관례이고, 모든 마디에 번호를 달면 동요 악보가 지저분해진다 |
| 못갖춘마디는 번호를 세지 않는다 | 이미 `measure.pickupTicks`가 있다. 첫 마디가 못갖춘마디면 그 다음이 1번 |
| 한 줄 마디 수는 화면·인쇄 **공통 한 값** | 두 벌로 두면 "화면과 인쇄가 다르다"는 더 큰 혼란이 생긴다. 인쇄본을 고정하고 싶은 사람은 화면도 그렇게 보면 된다 |
| 연습 기호는 마디의 성질 | 도돌이·1·2번 괄호와 같은 자리(`MUSIC_PART_STRUCTURE_KEYS`)에 두면 파트끼리 자동으로 맞춰진다 — **이게 핵심이다.** 파트보마다 연습 기호가 어긋나면 합주가 안 된다 |

### 2.2 계산 — 순수 함수 한 곳만 고친다

```js
musicPackLines(measures, availableWidth, { barsPerLine })   // 0이면 지금 그대로
```
`musicPackLines`는 이미 브라우저 없이 검증되는 순수 함수다. 고정값이 들어오면 폭 계산을 건너뛰고 N개씩 자르되, `lineBreakBefore`(＋오선)는 여전히 이긴다.

연습 기호 자동 부여 `musicAutoRehearsal(measures)` — 도돌이 시작·1번 괄호·`lineBreakBefore` 자리에 A·B·C…를 매긴다. 수동으로 적은 기호는 건드리지 않는다.

### 2.3 그리기 함정

- 마디 번호·연습 기호는 **SVG 안에** 그린다(`appendNotationText`와 같은 길). 지도에서 축척·방위표를 Leaflet 컨트롤로 만들었다가 캡처에서 사라진 그 실수를 되풀이하지 않는다 — 악보는 그림·메모·인쇄로 세 번 나간다.
- 연습 기호는 네모 테두리 + 굵은 글자, 단의 위쪽(음표 위 20px). 마디 번호는 그보다 작게 왼쪽 위.
- 부분 재생·따라치기의 "몇 마디부터"는 화면 번호와 **같은 값**이어야 한다. **구현에서는 못갖춘마디를 0번으로 두고**(악보 관례), 사람이 숫자를 적는 칸만 `musicMeasureIndexForNumber`로 배열 위치로 옮겼다 — 재생·발췌·따라치기가 받는 `from`·`to`는 예전 그대로 배열 위치다. 메뉴·안내 글의 마디 번호도 `measureNumberLabel()`로 한꺼번에 옮겼다(빈 칸은 `Number("")=0` 이라 첫 마디로 읽히는 함정이 있어 따로 걸렀다).
- 구현하며 더한 것: 마디 번호·연습 기호는 오선 **위**에 붙어 첫 단이 잘리므로 `musicScoreTopPad(sheet)`로 위 여백을 계산한다(단 높이와 같은 '두 곳이 같은 값을 써야 하는' 함정). 연습 기호 상자는 빠르기 표시보다 더 위에 둔다 — 처음엔 겹쳐서 확인 스크립트가 잡아냈다.
- 구현하며 정한 것: 연습 기호를 매길 구조가 하나도 없는 악보는 **8마디마다** 매긴다. 메뉴에는 숫자 모드를 `5마디마다` 하나만 내놓는다(모델은 2~99를 받는다).

### 2.4 테스트

순수 — `barsPerLine:4`면 네 개씩·`lineBreakBefore`가 우선·못갖춘마디 번호 매김·자동 연습 기호.
e2e — 고정 4마디로 바꾸면 단 수가 달라지고, 인쇄 SVG에 `A`가 남는지.

## 3. P3 — 이조 악기 파트

### 3.1 무엇이 문제인가

B♭ 클라리넷은 악보의 `도`를 불면 실제로는 `시♭`이 난다. 그래서 밴드 악보는 **파트마다 조가 다르다.** 지금은 파트에 음색만 있고 조는 악보 하나뿐이라, 클라리넷 파트보를 만들려면 사람이 장2도 올려 다시 적어야 한다.

### 3.2 결정 — 파일에는 **기보음**을 적는다

| 후보 | 뜻 | 결정 |
|---|---|---|
| 실음(concert) 저장 | 파일엔 실제 소리나는 음, 화면에만 올려 보여 줌 | ✗ 화면에서 고친 음과 파일의 음이 달라져 조옮김·되돌리기·비교가 전부 어려워진다 |
| **기보음(written) 저장** | 파일엔 연주자가 보는 그 음. 파트에 이조량만 적어 둠 | ✓ 편집기·조옮김·음역 검사는 지금 코드 그대로. **바뀌는 곳은 소리로 나가는 한 지점뿐이다** |

```jsonc
"parts":[{ "name":"클라리넷", "timbre":"clarinet",
           "key":"D",              // 파트 조표
           "transposition":"Bb" }] // 구현에서는 표(MUSIC_TRANSPOSING_INSTRUMENTS)의 id 하나만 담았다
```

`semitones`는 **기보음 → 실음** 변화량이다(B♭ 관은 −2). 소리로 나가는 곳에서만 더한다:

```
musicTimeline() 의 event.midi = musicMidiNumber(note) + part.transposition.semitones
                                   └ 재생·WAV·MIDI 내보내기가 모두 이 값을 쓴다(표준 MIDI는 실음)
```

구현하며 정한 것:
- **이조량은 표의 id 문자열 하나**로 담는다(설계의 객체 대신). 반음·다이어토닉·옥타브는 표에서 읽으므로 파일이 짧고, 표를 고치면 옛 파일도 함께 고쳐진다.
- **읽을 때 모든 파트에 조표를 채운다.** 문서 조표(`sheet.key`)는 '고른 파트의 조표'라서, 조표가 빈 파트를 그대로 두면 이조 파트가 골라져 있을 때 그 조표를 물려받아 버린다(피아노 파트가 라장조로 열리는 버그였다).
- **`musicTransposePart`는 고른 파트를 옮겼으면 `sheet.key`도 함께 옮긴다.** 그러지 않으면 바로 다음 `musicSyncActivePart`가 화면 조표(옛 값)를 파트에 도로 써 넣는다 — 스모크 스크립트에서 이 되돌림을 잡았다.
- MusicXML 은 `<chromatic>`(옥타브 뺀 반음)과 `<octave-change>`를 나눠 적어야 한다. 그래서 표에 `chromatic`·`octave`를 따로 두고 `semitones = chromatic + 12 × octave` 로 쓴다.

### 3.3 화면

- 파트 만들 때 악기를 고르면 이조가 **자동으로 딸려 온다**. 표는 `MUSIC_TRANSPOSING_INSTRUMENTS` 하나로 두고, 옥타브까지 맞는 값을 쓴다:

  | 악기 | 기보 → 실음 | 악기 | 기보 → 실음 |
  |---|---|---|---|
  | B♭ 클라리넷·트럼펫 | −2 (장2도 아래) | E♭ 알토색소폰 | −9 (장6도 아래) |
  | B♭ 테너색소폰 | **−14** (장9도 아래) | E♭ 바리톤색소폰 | **−21** (장13도 아래) |
  | F 호른 | −7 (완전5도 아래) | 그 밖 | 0 |

  테너·바리톤은 옥타브가 더 붙는다 — 여기서 −2·−9로 적으면 반주와 한 옥타브 어긋난 음원이 나온다.
- 파트 이름 옆에 `B♭ 기보` 배지, 상태줄에 `기보 D장조 · 실음 C장조`.
- **실음 파트 → 이조 파트로 옮겨 담기**: 기존 파트를 복제하고 이조 악기로 바꾸면 음과 조표를 자동으로 올린다. 계산은 이미 있는 `musicTransposeSheet`를 파트 하나에 적용해 재사용한다(음역을 벗어나면 지금처럼 묻고, 저장 못 할 옥타브면 전부 취소하는 규칙 그대로).
- 음역 검사는 **기보 기준**으로 남긴다. 연주자가 보는 음이 음역 안이어야 뜻이 있다.

### 3.4 함정

- `measure.keyChange`(중간 조바꿈)는 파트별로 이미 구조가 맞춰져 있으므로 조표 표시만 `part.key` 기준으로 바꾸면 된다.
- MusicXML `<transpose><diatonic>·<chromatic>`으로 내보내고 들일 때도 읽는다 — 이 값을 빠뜨리면 다른 프로그램에서 반음 어긋난 악보가 된다.
- 자동 반주(코드 기호)는 **실음 기준**이다. 이조 파트에 적힌 코드 기호는 반주로 보내지 않거나 이조량만큼 되돌려 보낸다(결정: **되돌려 보낸다** — 클라리넷 파트에 적은 C가 반주에서 B♭으로 울려야 맞다).

## 4. P4 — 파트 연습 음원 일괄 저장

### 4.1 화면

**연습 음원 ▾** 창 하나:

| 고르는 것 | 기본값 |
|---|---|
| 대상 파트 | 전체(파트마다 한 벌씩) |
| 강조 | 내 파트 100% · 나머지 40% (0%면 내 파트만) |
| 템포 | 70% · 85% · 100% 중 복수 |
| 메트로놈 · 2마디 카운트인 | 켬 |
| 묶는 방법 | **ZIP 한 장** |

### 4.2 구현

`renderWav(sheet, opts)`에 옵션을 넓힌다 — 새 렌더 경로를 만들지 않는다.

```js
renderWav(sheet, { focusPartId, otherGain:0.4, tempoScale:0.85,
                   metronome:true, countIn:true, onProgress })
```
- 템포는 `sheet.tempo`를 곱해 타임라인을 다시 만들면 끝이다(`musicTimeline`이 초를 템포에서 계산한다).
- 메트로놈·카운트인은 **이미 타임라인이 만들어 두고 있다**(`timeline.metronome`, `timeline.countInBeats`). 재생에 쓰던 것을 저장 경로에도 연결만 하면 된다.
- 파일 이름: `학교종 - 소프라노 (85%).wav`, 묶음은 `학교종 - 연습음원.zip`.

| 결정 | 이유 |
|---|---|
| 연속 다운로드가 아니라 **ZIP 한 장** | 파일을 6개 넘게 연달아 내려받으면 브라우저가 막는다. JSZip은 이미 vendor에 있고 지연 로드도 된다 |
| 진행률과 **취소** | 파트 6 × 템포 3 = 18벌이면 렌더가 길다. 상태 줄에 `3/18`과 그만두기 |
| 렌더는 하나씩 차례로 | `OfflineAudioContext`를 여러 개 동시에 돌리면 저사양 PC에서 메모리로 죽는다 |

구현하며 정한 것:
- **vendor 의 JSZip 은 2.x** 다. `generateAsync` 가 없어 `generate` 갈래를 함께 두고(백업 기능과 같은 규약), **Blob 을 `zip.file()` 에 그대로 넣으면 "unsupported format" 으로 죽는다** — `new Uint8Array(await blob.arrayBuffer())` 로 바꿔 넣는다. 둘 다 e2e 가 아니라 실제 브라우저에서 돌려 보고서야 드러났다.
- 한 번에 **12벌**까지만 만든다(`MUSIC_PRACTICE_AUDIO_MAX`). 한 벌이 수 MB 라 그 이상은 메모리가 버티지 못한다.
- 카운트인은 두 마디가 아니라 **한 마디**로 했다 — 재생의 '1234 준비'와 같은 길이여야 익숙하다.
- 믹스 계산은 `mixPracticeTrack` 으로 빼 브라우저 없이 검증한다(렌더 자체는 `OfflineAudioContext` 가 필요하다).
- 곁다리로 고친 것: 켜 둔 도구막대 단추(`.music-btn.is-on`)에 마우스를 올리면 hover 배경이 이겨 **흰 글자가 사라지던** 예전 버그. hover 규칙에서 `.is-on` 을 빼고 진한 강조색을 따로 줬다.

## 5. 공통 사항

- **파일 버전 `9 → 10`.** 새 필드는 전부 선택이고 옛 `.msheet`는 그대로 열린다. `musicSerialize`의 "빈 값은 쓰지 않는다 = 같은 모델이면 같은 바이트" 규칙을 새 필드도 지킨다(테스트가 이걸 본다).
- 악보 UI는 아직 `MNI18N` 사전에 없다(한국어 고정). 이번 작업도 한국어로 두고, 영어화는 i18n 단계에서 한꺼번에 한다.
- 그림·메모·인쇄 세 경로가 같은 렌더를 쓰므로, **높이·부가 텍스트 계산은 반드시 한 함수로** 모은다(P1의 `musicScoreLineHeight`).

## 6. 순서와 크기

| 단계 | 무엇 | 크기 | 왜 이 순서인가 |
|---|---|---|---|
| P1 | 가사 여러 절 + 이어치기·붙여넣기 | 중 | 결손이 가장 뚜렷하고 다른 단계와 안 얽힌다. 줄 높이 함수를 여기서 정리해 두면 P2가 쉬워진다 |
| P2 | 마디 번호·연습 기호·한 줄 마디 수 | 소~중 | 순수 함수 한 곳 + SVG 텍스트. 합주 지시가 바로 가능해진다 |
| P3 | 이조 악기 파트 | 중 | 소리로 나가는 한 지점만 바꾸는 설계라 코드는 작지만, 조표·MusicXML까지 함께 봐야 한다 |
| P4 | 파트 연습 음원 | 소~중 | 앞의 것들과 독립. 이미 있는 타임라인·렌더에 옵션만 얹는다 |

각 단계는 따로 배포할 수 있고, 단계마다 `music-model.test.js`(순수)와 e2e 하나씩을 함께 넣는다.
