## 0. 목표와 비목표

**목표**
- 한 데이터를 **JSON ↔ CSV ↔ 마크다운 표 ↔ XML ↔ YAML ↔ XLSX** 사이에서 서로 변환한다.
- 변환하면 **무엇이 손실되는지 변환 전에 보여준다**. 이게 일반 변환기와 다른 유일한 지점이다.
- 완전 오프라인(EXE·오프라인 HTML 동일 동작).

**비목표 (정직한 한계)**
- **원본 파일에 되쓰기는 하지 않는다.** 변환 결과는 언제나 복사본(클립보드·새 파일·새 탭)으로만 나간다. `table-export.js`가 이미 지키는 규칙과 같다. 손실이 있는 변환을 원본에 덮어쓰면 되돌릴 수 없기 때문이다.
- 스키마 검증(JSON Schema·XSD)은 하지 않는다. 변환만 한다.
- XML의 네임스페이스·DTD·처리 명령은 v1에서 보존하지 않는다(손실 리포트에 기록만 한다).
- 대용량 스트리밍 변환은 v1 제외. 전부 메모리에 올린다(수업용 데이터 크기 기준).

## 1. 핵심 원칙 — 허브 앤 스포크

포맷 N개를 서로 변환하면 N×(N-1)개 변환기가 필요하다. 6개면 30개다. 대신 중간 표현(IR)을 두고 포맷마다 `parse`/`serialize` 한 쌍만 만들면 2N개로 끝나고, **새 포맷 추가 비용이 항상 2개로 고정**된다.

```
JSON  ─┐                                       ┌─ CSV / TSV
JSONL ─┤                                       ├─ 마크다운 표
YAML  ─┼─ parse ─→ Value  ⇄  Table ─ serialize ─┼─ XLSX
XML   ─┘         flatten/unflatten             └─ HTML 표
```

값·구조 손실의 주 경계는 `flatten`/`unflatten`이다. 다만 주석·XML 혼합 콘텐츠처럼 IR에 없는 형식 고유 정보도 어댑터에서 사라질 수 있으므로, 파싱 단계의 손실도 함께 리포트한다.

## 2. 중간 표현(IR) 두 개

```js
// 계층형 — 그냥 JS 값 (JSON과 동형)
Value = null | boolean | number | string | Value[] | { [k]: Value }

// 평면형 — 기존 MNTableExport 표 블록과 호환되는 모양
Table = { header: boolean, columns: string[], rows: Cell[][] }
Cell  = { v: any, raw: string }     // v=타입 있는 값, raw=원문 문자열
```

### `Cell`을 값/원문 두 필드로 나누는 이유

타입 추론을 켠 채로도 원문을 잃지 않기 위해서다. CSV에서 `00123`을 읽으면 `{ v: 123, raw: "00123" }`이 되고, 왕복할 때 `raw`를 쓰면 앞자리 0 소실 사고가 나지 않는다. 사번·우편번호·전화번호가 깨지는 대부분의 사고가 여기서 막힌다.

`Table`은 `MNTableExport.rowsOf()`가 만드는 `string[][]`와 상호 변환 가능해야 한다. 그래야 메모창(scratchpad)·블록 문서(mnote)의 표 블록이 그대로 입력이 된다.

## 3. 모듈 배치

| 파일 | 책임 | DOM 의존 |
|---|---|---|
| `src/js/data-convert.js` | IR, 어댑터, flatten/unflatten, 손실 리포트, `convert()` | ❌ 순수 |
| `src/js/data-convert-ui.js` | 변환 모달, 미리보기, 진입점 배선 | ✅ |

### 순수/UI 분리가 핵심인 이유

이 프로젝트는 `node --test`로 jsdom 없이 테스트한다(`package.json`의 `test` 스크립트). 변환 로직이 DOM을 조금이라도 건드리면 테스트가 불가능해진다. 순수 계층은 **문자열 in / 문자열 out**만 하도록 못을 박는다.

### `table-export.js`에 넣지 않는 이유

`table-export.js`(160줄)는 "표 블록을 앱 밖으로 꺼내는" 전용이라 CSV/TSV만 안다. 여기에 XML·YAML·평탄화·손실 리포트를 넣으면 책임이 섞인다.

대신 **방향을 뒤집는다**: `csvCell`/`toCsv`/`toTsv`를 `data-convert.js`로 옮기고 `table-export.js`가 그걸 호출한다. CSV 직렬화 규칙의 단일 소스가 하나 생긴다.

### 등록

```json
// scripts.manifest.json → moduleBoundaries
{
  "name": "data-convert",
  "file": "data-convert.js",
  "publicApi": "MNDataConvert",
  "consumers": ["table-export.js", "data-convert-ui.js", "spreadsheet-viewer.js"]
}
```

로드 순서는 `table-export.js`보다 앞에 둔다. `allowedDependencies`에 `data-convert-ui.js → ["documents.js", "code-viewer.js", "data-convert.js"]`를 추가한다.

## 4. 포맷 어댑터와 라이브러리 비용

| 포맷 | parse | serialize | 추가 vendor |
|---|---|---|---|
| JSON | `JSON.parse` | `JSON.stringify` | 없음 |
| JSONL | 줄 분할 | 줄 결합 | 없음 |
| CSV / TSV | 자체 구현(RFC 4180) | `table-export.js`에서 이관 | 없음 |
| 마크다운 표 | 자체(파이프 파싱) | 자체 | 없음 |
| HTML 표 | 자체 토크나이저(관대 모드) | 문자열 조립 | 없음 |
| XML | 자체 토크나이저 | 문자열 조립 | 없음 |
| XLSX | `XLSX.utils.sheet_to_json` | `XLSX.utils.aoa_to_sheet` | 기존 `MNLazy.tryNeed("xlsx")` 재사용 |
| YAML | `jsyaml.loadAll` | `jsyaml.dump` | **js-yaml 4.1.0 (39,430바이트)** |

**YAML만 vendor가 늘어난다.** 나머지는 전부 자체 구현이거나 이미 있는 `vendor/xlsx.full.min.js`로 끝난다. YAML은 `MNLazy`의 `yaml` 묶음으로 **지연 로드**하므로 시작 비용은 0이고, 사용자가 YAML을 고른 순간에만 39KB를 받는다.

### YAML만 자체 구현하지 않는 이유

XML은 직접 읽었으면서 YAML은 라이브러리를 쓰는 게 일관성 없어 보이지만, 두 형식의 난이도가 다르다. YAML은 앵커·별칭, 블록 스칼라(`|`, `>`)와 그 chomping 지시자, 들여쓰기 기반 구조, 흐름/블록 혼용, 여러 문서(`---`), 암묵적 타입 해석 규칙을 모두 갖는다. 직접 짜면 **조용히 틀리는 파서**가 되기 쉽고, 그건 이 기능의 손실 리포트로도 잡히지 않는 종류의 오류다(리포트는 "변환 과정의 손실"을 재기 때문에, 애초에 잘못 읽은 것은 왕복해도 일관되게 잘못된다).

대신 **모듈이 라이브러리를 찾아 나서지 않게** 해서 순수성을 지킨다.

```js
MNDataConvert.setYaml(lib)   // 밖에서 넣어 준다
MNDataConvert.yamlReady()    // 지금 쓸 수 있는가
```

전역 `jsyaml`이 이미 있으면 그것도 쓴다. node 테스트는 **앱이 쓰는 것과 같은 vendor 파일**을 `require`해서 넣으므로, YAML 경로도 브라우저 없이 검증된다.

### YAML 관련 손실

| 코드 | 언제 |
|---|---|
| `comment-dropped` | 원문에 `#` 주석이 있을 때 (js-yaml도 값에 담지 않는다) |
| `multi-document` | `---`로 나뉜 문서 여럿을 배열 하나로 합칠 때 |

"노르웨이 문제"(`NO` → `false`)는 **일어나지 않는다.** js-yaml 4는 YAML 1.2 core schema를 쓰므로 `NO`/`ON`/`Y`는 문자열로 남는다. 설계 초안에 위험으로 적었으나 실제로는 해당하지 않아, 손실 코드를 만들지 않고 테스트로 그 사실을 고정했다.

### 포맷 자동 인식에서 YAML을 거의 추측하지 않는 이유

`메모: 오늘 할 일` 같은 평범한 한 줄도 문법상 완전한 YAML이다. 내용만으로 추측하면 텍스트 파일이 조용히 YAML로 읽히고, 그 결과가 그럴듯해 보여서 사용자가 알아채기 어렵다. 그래서 **확장자(`.yaml`/`.yml`)와 문서 구분선(`---`으로 시작)만 믿고** 나머지는 표 계열로 넘긴다. 틀린 추측이 조용히 성공하는 것보다, 눈에 띄게 어긋나 보여서 사용자가 형식을 직접 고르는 편이 낫다.

### XML 파서 — DOMParser 대신 자체 토크나이저 (Phase 3에서 변경)

**당초 설계는 내장 `DOMParser` + 의존성 주입이었으나, 구현하면서 자체 토크나이저로 바꿨다.**

이유는 하나다. node에는 `DOMParser`가 없다(확인: `node -e "typeof DOMParser"` → `undefined`). 주입 구조로 가면 테스트에서 넣을 수 있는 건 가짜 파서뿐이라, XML 경로는 실질적으로 브라우저 e2e에서만 검증된다. 그러면 **"문자열 in / 문자열 out 순수 함수"라는 이 모듈의 계약이 절반만 성립**하고, Phase 1에서 순수/UI를 갈라 둔 이유가 사라진다.

대신 다루는 범위를 좁게 못박아 위험을 줄인다.

| 다룸 | 안 다룸 |
|---|---|
| 요소·속성·텍스트 | 네임스페이스 보존 |
| CDATA, 주석(버리고 보고) | DTD·엔티티 선언 |
| 명명·10진·16진 엔티티 | 처리 명령 보존 |
| 자기닫음 태그 | 스키마 검증 |

`parseMarkup(text, { html })` 하나로 XML과 HTML 표를 함께 읽고, HTML 모드에서만 태그 이름을 소문자로 접고 생략된 닫는 태그를 보충한다.

**HTML 자동 닫기 규칙**은 "이 태그가 열릴 때 닫아야 하는 태그" 목록이다. 스택을 위에서 아래로 훑어 처음 만나는 것까지 잘라내므로, `td`의 목록에 `tr`을 넣으면 부모 행까지 닫혀 버린다(구현 중 실제로 낸 버그다).

```
td, th → [td, th]
tr     → [tr]
thead, tbody, tfoot → [thead, tbody, tfoot]
```

### XML ↔ Value 규약

| XML | Value |
|---|---|
| 자식 요소 | 객체 키 |
| 속성 `id="1"` | `"@id"` 키 |
| 요소·속성과 섞인 글자 | `"#text"` 키 |
| 같은 이름 형제 여럿 | 배열 |

`@`·`#` 접두사를 붙여 두면 속성과 같은 이름의 자식 요소가 있어도 키가 겹치지 않아 **XML → JSON → XML 왕복에서 속성이 그대로 살아난다.** 그래서 속성은 손실 항목이 아니다(당초 설계에 넣었던 `attr-merged` 코드는 그래서 만들지 않았다).

### 루트 벗기기 — 표로 쓸 수 있게 만드는 규칙

`<직원들><직원>…</직원><직원>…</직원></직원들>`을 그대로 매핑하면 `{직원들:{직원:[…]}}`이 되고, 표로 바꾸면 1행짜리 거대한 표가 된다. 그래서 **루트의 자식이 2개 이상이고 이름이 모두 같으면 그 목록을 곧바로 배열로 꺼낸다.**

자식이 하나뿐일 때는 꺼내지 않는다. `<직원들><직원>…</직원></직원들>`이 "직원 1명짜리 목록"인지 "직원 하나를 가진 객체"인지 XML만 보고는 알 수 없기 때문이다. 이때는 `single-element-array`로 그 사실만 알린다. 반대 방향(원소 1개짜리 배열 → XML)에서도 같은 경고를 낸다.

바깥·항목 요소 이름은 `meta.xmlRoot`/`meta.xmlItem`으로 IR에 실려 다녀서 **XML → XML 왕복에서는 원래 이름이 유지**된다. 표를 거치면 이름을 담을 곳이 없어 기본값(`rows`/`row`)이 되므로, 변환 창에서 직접 지정할 수 있게 입력 칸을 둔다.

## 5. 평탄화 규칙 — 유일하게 진짜 결정이 필요한 부분

### 경로 문법

```
주소.시          중첩 객체
태그[0]          배열 원소
["a.b"].c        키에 점이 들어있을 때
```

### 정책 3종 (`flatten` 옵션)

| 값 | 동작 | 왕복 |
|---|---|---|
| `"path"` (**기본**) | `태그[0]`, `태그[1]` 컬럼으로 펼침 | 가능 |
| `"join"` | `태그` = `"신입, 우수"` | 불가 |
| `"explode"` | 태그마다 행 복제 | 불가 |

기본값이 `"path"`인 이유는 **기본 동작이 되돌릴 수 있어야 사용자가 안심하고 쓰기 때문**이다. 보기 좋은 `"join"`은 명시적으로 골라야 한다.

### 루트 형태 판정

| 입력 | 결과 |
|---|---|
| 객체 | 1행짜리 표 |
| 객체 배열 | N행 (컬럼 = 모든 행 키의 합집합, **첫 등장 순서** 유지) |
| 스칼라 배열 | 단일 컬럼 `value` |
| 중첩 배열(`[[…],[…]]`) | 그대로 격자, 헤더 없음 |

빠진 키는 빈 셀로 채운다. 이때 "빈 셀이 `null`인지, 원래 키가 없었는지" 구분이 불가능해지므로 반드시 손실 리포트에 `null-ambiguous`로 기록한다.

### 되돌리기(`unflatten`)

컬럼명을 파싱해 트리를 재조립한다. `태그[0]`·`태그[1]`이 보이면 배열로, `주소.시`가 보이면 객체로 복원한다.

### 빈 칸 정책 (`emptyAs`) — 구현 중 추가된 결정

되돌릴 때 빈 칸을 무엇으로 볼지가 `unflatten`의 유일한 재량이다.

| 값 | 동작 |
|---|---|
| `"omit"` (**기본**) | 키를 아예 만들지 않는다 |
| `"string"` | 빈 문자열 `""` |
| `"null"` | `null` |

기본이 `"omit"`인 이유는, **행마다 길이가 다른 데이터에서 빈 칸을 값으로 채우면 원본에 없던 키·배열 원소가 생겨 왕복이 깨지기 때문**이다. 예를 들어 `태그`가 2개인 행과 1개인 행이 섞이면, 짧은 쪽 `태그[1]`이 빈 칸이 되는데 이걸 `""`로 채우면 되돌린 배열이 `["경력", ""]`이 되어 원본과 달라진다. `"omit"`이라야 `"path"` 평탄화가 "왕복 가능"이라는 약속을 지킨다.

어느 쪽을 골라도 "빈 칸이 원래 무엇이었는지 알 수 없다"는 사실 자체는 남으므로, 표로 내보내는 시점에 이미 `null-ambiguous`로 알린다.

## 6. 손실 리포트

`convert()`는 텍스트만 돌려주지 않는다.

```js
MNDataConvert.convert(text, {
  from: "json", to: "csv",
  flatten: "path",
  inferTypes: true,      // 기본 켜짐 — 4.1 결정
  header: true,
  delimiter: ",",
  bom: true
})
// → { text, table, loss: [ { code, path, before, after, hint }, … ] }
```

내부적으로 **변환 결과를 다시 파싱해서 원본 IR과 비교**하고, 표를 트리로 만드는 파싱 단계의 빈 칸·타입 추론·경로 충돌도 별도로 기록한다. 구조가 달라진 지점과 형식 고유 정보의 소실이 곧 손실 항목이다.

### 경고 코드

| 코드 | 의미 |
|---|---|
| `type-lost` | `3`(숫자) → `"3"`(문자열) |
| `null-ambiguous` | `null`과 `""`가 같은 빈 셀이 됨 |
| `array-joined` | 배열이 문자열로 합쳐져 되돌릴 수 없음 |
| `nested-flattened` | 중첩 구조가 컬럼으로 펴짐 |
| `leading-zero` | `00123` → `123` 위험(`raw` 보존으로 막지만 대상 포맷이 문자열 구분을 못 하면 경고) |
| `precision` | 2^53 초과 정수 정밀도 손실 |
| `date-coerced` | `1-2` 같은 값이 엑셀에서 날짜로 해석될 수 있음 |
| `duplicate-key` | XML 중복 요소·중복 컬럼이 덮어써짐 |
| `comment-dropped` | YAML·XML 주석 소실 |
| `mixed-content` | XML에서 글자와 자식 요소가 섞인 순서를 보존할 수 없음 |
| `path-collision` | `a`와 `a.b`처럼 겹치는 컬럼 경로가 값을 덮어씀 |
| `attr-merged` | XML 속성이 자식 요소와 같은 층으로 합쳐짐 |
| `formula-frozen` | XLSX 수식이 값으로 고정 |
| `single-element-array` | XML에서 원소 1개짜리 배열/객체 구분 불가 |

### 타입 추론 정책 (결정)

- **기본 켜짐**(`inferTypes: true`).
- 추론해도 `Cell.raw`에 원문을 항상 보존한다.
- 추론이 원문을 바꾸는 경우(`00123`→`123`, `1.10`→`1.1`, `NO`→`false`) **전부 손실 리포트에 올린다**.
- 모달에서 체크박스 한 번으로 끌 수 있고, 끄면 모든 셀이 문자열이 된다.

이 조합이라야 "편한 기본값"과 "데이터 안 깨짐"을 동시에 만족한다. 셋 중 하나라도 빠지면 사고가 난다.

## 7. UI

### 진입점 4곳 (전부 기존 배선 재사용)

1. **명령 팔레트** — `command-palette.js`의 `convertFormat`. 활성 문서가 텍스트면 그 내용으로, 표면 시트로 채워 연다.
2. **코드 뷰어 툴바** — `.text-view-bar`에 `🔄 변환` 버튼. `CONVERTIBLE_EXTS`(json·jsonl·ndjson·xml·csv·tsv·md·markdown·html·htm)일 때만 붙는다.
3. **표 블록 버튼** — 메모창(`scratchpad.js`)·블록 문서(`mnote.js`) 표 블록의 기존 `복사 / CSV / 편집기로` 옆에 `변환` 추가. 실제 호출은 `MNTableExport.openConvert`가 받는다.
4. **표 문서** — 스프레드시트·CSV 뷰어가 `doc.sheetRows()`를 걸어 두고, 변환 창이 그것을 CSV로 적어 입력에 채운다.

### `doc.sheetRows()` — 표 문서를 넘기는 통로

표 문서는 글자가 아니라 시트라서 `codeEditor.getValue()`가 없다. `contentSearchFocus`와 같은 방식으로 뷰어가 문서 객체에 함수를 걸어 둔다.

| 뷰어 | 내주는 값 |
|---|---|
| `renderXlsx` | 현재 시트를 `dispCell` 기준 문자열 격자로 (수식은 결과, 날짜·서식 숫자는 표시 문자열) |
| `renderCsvPreview` | 전체 레코드. 단 20,000행 초과면 `null` (변환 창에 올리는 것 자체가 무겁다) |

**화면에 보이는 값을 그대로 넘기는 게 규칙이다.** 사용자가 보는 것과 변환 결과가 어긋나면 손실 리포트가 아무리 정확해도 신뢰를 잃는다.

렌더가 끝나기 전에 창을 열면 훅이 아직 없어 빈 입력으로 열린다(e2e에서 실제로 만난 타이밍이다). 지연 렌더 구조상 정상 동작이며, 사용자가 화면을 보고 여는 실제 흐름에서는 문제가 되지 않는다.

### 모달 구조

```
┌──────────────────────────────────────────────┐
│  [JSON ▾]  →  [CSV ▾]                        │
├───────────────────┬──────────────────────────┤
│  입력             │  미리보기                 │
│  (붙여넣기/파일)   │  (표는 격자로 렌더)       │
├───────────────────┴──────────────────────────┤
│  ⚠ 2가지가 손실됩니다 ▸                        │
├──────────────────────────────────────────────┤
│  평탄화 [경로 ▾] 타입추론 [✓] 구분자 [, ▾]     │
│  헤더 [✓]  BOM [✓]                            │
├──────────────────────────────────────────────┤
│         [복사]  [파일로 저장]  [새 탭으로 열기]  │
└──────────────────────────────────────────────┘
```

- `from`은 확장자와 내용으로 자동 추정하되 사용자가 덮어쓸 수 있다. **직접 고른 뒤로는 자동 인식을 멈춘다** — 안 그러면 사용자가 고른 형식이 입력할 때마다 되돌려진다.
- 입력이 바뀌면 미리보기와 손실 배너를 즉시 갱신한다(디바운스 200ms).
- 지금 조합에서 뜻이 없는 옵션은 감춘다(예: 출력이 JSON이면 평탄화·BOM은 숨김). 늘 다 보이면 무엇이 영향을 주는지 알기 어렵다.
- 표 출력은 격자로 렌더하고 `표 / 원문` 토글로 실제 텍스트도 확인할 수 있다. 트리 출력은 원문만 보여준다.
- 입력이 깨졌을 때는 창을 닫지 않고 오류만 표시하고 내보내기 버튼을 잠근다.
- 손실 배너를 펼치면 어느 경로에서 무엇이 어떻게 바뀌는지 항목별로 보여준다.
- `i18n.js` 영문 사전에도 새 문구를 추가한다.

### 결과 3경로

`table-export.js`가 이미 검증한 경로를 그대로 쓴다. 새로 만들 것이 없다.

| 버튼 | 재사용 함수 |
|---|---|
| 복사 | `copyDocumentMenuText` (클립보드 폴백 포함) |
| 표 편집기로 | `MNTableExport.openInEditor({rows, header})` — 표 형식 출력일 때만 노출 |
| 파일로 저장 | `saveTextDoc(text, null, name)` — `doc`을 넘기지 않아 원본 저장 상태를 건드리지 않음 |
| 새 탭으로 열기 | `handleFiles([...], { isScratch:true, … })` |

**원본 되쓰기 버튼은 만들지 않는다**(0장 비목표). `saveTextDoc`에 `doc`을 넘기지 않는 것으로 코드 수준에서 보장한다.

## 8. 테스트 (`tests/data-convert.test.js`)

핵심은 **왕복 테이블 테스트**다.

```js
const SAMPLES = {
  flat, nested, arrays, nullsAndEmpty, typesEdge,
  unicodeAndCommas, bigNumbers, leadingZeros, ragged
};
const LOSSLESS = [["json","csv"], ["json","md"], ["csv","json"], ["md","csv"], ["json","yaml"], …];

// 1) 무손실로 표시한 경로는 왕복 결과가 원본과 완전히 같아야 한다
// 2) 손실 경로는 loss 배열이 절대 비면 안 된다   ← 더 중요
```

두 번째가 핵심이다. **"손실이 났는데 리포트가 조용한" 경우가 이 기능의 유일한 진짜 버그**이기 때문에, 그걸 테스트가 직접 잡게 만든다.

여기에 엣지 케이스 단위 테스트를 붙인다.

- 셀 안의 쉼표·따옴표·줄바꿈·탭
- 마크다운 `|` 이스케이프, 셀 안 줄바꿈(`<br>`)
- 빈 표, 헤더만 있는 표, 행 길이가 들쭉날쭉한 표
- BOM, CRLF, CP949 입력
- YAML 노르웨이 문제(`NO`→`false`), `1.10`→`1.1`
- XML 원소 1개짜리 배열, 속성 vs 자식 요소
