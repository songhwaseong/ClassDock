# 자바 예제 갤러리 설계 (파이썬 갤러리 공용화)

파이썬 예제 갤러리(`openSnippetGallery`)를 언어 탭이 있는 공용 갤러리로 바꾸고,
자바 예제 83개를 얹는다. 이 문서는 **예제 목록 확정본**과 구현 시 지켜야 할 계약을 적는다.

## 확정한 방침

| 항목 | 결정 |
|---|---|
| 구조 | 갤러리 하나 + 언어 탭(파이썬 / 자바). 진입점(사이드바 ✨·환영 화면·명령 팔레트·드롭존)은 그대로 |
| 문법 수준 | **Java 11 기준으로 통일** — `var`·람다·스트림·`List.of`까지만. `record`·`switch` 식·텍스트 블록은 쓰지 않는다 |
| 규모 | 83개 (12갈래) |
| 파이썬 연결 | 같은 문제의 파이썬 예제가 있으면 카드에 **"파이썬 버전 보기"** 링크 |

### 왜 Java 11인가

런처는 JDK 21을 내려받아 쓰지만(`desktop/launcher.cs` `JdkFeatureVersion = 21`),
최소 허용은 11이다(`JavaMinimumFeatureVersion = 11`). 학생 PC에 이미 JDK 11/17이 깔려
PATH를 잡고 있으면 그 자바로 컴파일되므로, 예제는 11 문법을 넘지 않는다.

## 언어 짝(pair) 연결 방식

파이썬 목록은 **이름도 제목도 중복이 있다**(`소수.py`·`회문.py`·`버블정렬.py` 등 16쌍이
목록 앞뒤에 두 번 들어 있다). 따라서 제목·파일명으로 짝을 찾으면 안 되고, 명시적 id가 필요하다.

- 짝이 있는 파이썬 예제에만 `id:"<kebab-slug>"` 한 줄을 더한다(64개).
  객체 리터럴에 속성을 더하는 것뿐이라 `PY_SNIPPET_META` 병렬 배열의 순서는 흔들리지 않는다.
- 자바 예제에는 `pair:"<같은 slug>"`를 둔다.
- 갤러리를 열 때 `id → 예제` Map을 한 번 만들어 양방향 링크를 그린다
  (자바 카드 → "파이썬 버전 보기", 파이썬 카드 → "자바 버전 보기").
- 링크를 누르면 갤러리를 닫지 않고 **언어 탭만 바꾸고 그 카드로 스크롤**한다.
- 카드는 버튼이라 그 안에 또 버튼을 넣을 수 없다 → 카드와 링크를 담는 칸(`.snippet-cell`)을 하나 두고,
  필터로 숨기는 대상도 카드가 아니라 이 칸으로 바꾼다.
- 건너간 카드가 검색어·난이도 필터에 걸려 안 보이면 소용이 없으므로, 링크로 이동할 때는 둘 다 푼다.

**구현 완료(2026-09-04)** — 파이썬 64개에 `id`, 자바 64개에 `pair`. 한쪽만 고치면 링크가 조용히
사라지므로 `tests/java-snippets.test.js` 가 두 파일을 함께 읽어 양방향으로 빠짐없이 맞물리는지 검사한다.

> 참고: 파이썬 목록의 중복 16쌍은 이번 작업과 별개로 정리 대상이다.
> 짝을 걸 때는 뒤쪽(나중에 추가된, 대체로 더 나은) 예제를 기준으로 삼았다.

## 자바 쪽 구현 계약 (파이썬과 다른 점)

1. **파일 이름 = public 클래스 이름, 첫 글자는 영문 대문자.**
   `java-editor.js`의 `JAVA_FILE_ID_START_RE = /^[A-Z]$/` 검사가 저장 경로마다 걸린다.
   파이썬처럼 한글 파일명(`구구단.py`)을 쓸 수 없다 — 제목만 한글, 파일명은 PascalCase.
   → 테스트로 고정: `name`이 `^[A-Z][A-Za-z0-9_]*\.java$` 이고 코드의 `public class X`와 일치.
2. **여는 방법이 다르다.** `openPythonSnippet`은 `handleFiles()`를 바로 부르지만,
   자바는 `newJavaScratch()`와 같이 `queueFiles([file], { isScratch:true })`를 써야 한다.
   `handleFiles`만 부르면 미저장 새 `.java`가 자동복원에서 사라진다(java-editor.js 주석 참고).
   MIME은 `text/x-java-source`.
3. **자바 실행은 EXE + 로컬 JDK가 있어야 한다.** 브라우저·오프라인 HTML에서는 못 돈다.
   탭을 숨기지 말고, ▶에서 기존 "JDK 없음" 안내·원클릭 설치로 넘긴다.
4. **한 예제 = 한 파일.** 보조 클래스가 필요하면 같은 파일 안에 비-public 클래스로 둔다
   (형제 `.java` 배포로 가면 갤러리가 다중 파일을 다뤄야 한다). `main`도 파일당 하나만
   (여러 개면 `JAVA_MAIN_PREFIX` 실행 대상 선택 UI가 끼어든다).
5. **클래스 이름이 JDK 클래스와 겹치면 안 된다.** 파일 이름 = public 클래스 이름이므로,
   `DayOfWeek.java` 처럼 `java.time.DayOfWeek` 와 같은 이름을 쓰면 그 클래스를 import 하는 순간
   자기 자신과 충돌해 컴파일이 막힌다. → `WeekdayFinder.java` 로 지었다.
   (`Rectangle`·`Point` 처럼 `java.awt` 에만 있고 import 하지 않는 이름은 괜찮다.)
6. **보조 클래스 이름은 예제끼리도 겹치지 않게.** 런처는 `-sourcepath` 로 *참조된 형제만*
   컴파일하므로(launcher.cs `WriteJavaExtraSources`) 같은 폴더에 여러 예제를 저장해도 오류는 나지
   않지만, 읽는 사람이 헷갈린다. 응용 예제의 보조 타입은 `static` 중첩 클래스로 두고
   (`GradeReport` 안의 `Student` 등), 최상위로 둘 때는 서로 다른 이름을 쓴다
   (`ShapeInterface` 는 `Shape`·`Circle`, `AbstractVehicle` 은 `Vehicle`·`Car`).
7. **메타는 병렬 배열을 쓰지 않는다.** `level`·`desc`·`learn`을 각 객체 안에 바로 적는다.
8. `Scanner` 입력 예제는 그대로 된다 — `java-runtime.js`가 stdin 코드를 감지해 터미널로 포커스를 옮긴다.

## 손댈 곳

- 신규 `src/js/snippet-gallery.js` (렌더러를 python-snippets.js에서 옮김 + 언어 탭)

- `classdock.html` 스크립트 태그 2줄 + `sbExamples` 버튼 title/aria를 "예제 갤러리"로
- `scripts.manifest.json` — `localScripts` · `applicationLayers` · `scriptDependencies`
  (release-contract 테스트가 `src/js/*.js` 실제 목록과 정확히 일치시키라고 강제)
- `docs/JS-파일별-기능.md`에 새 파일 2개 설명 (같은 테스트가 검사)
- `src/js/i18n.js` — 기존 "파이썬 예제 갤러리" 계열 4개 + 자바 문구
- `src/js/command-palette.js` — "자바 예제 갤러리" 항목
- `src/js/java-editor.js` — `⋯` 메뉴에 "예제" 버튼
