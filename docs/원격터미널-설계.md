# ClassDock SSH 원격 터미널 1·2·3차 설계

## 범위

- ClassDock.exe에서 IP/도메인, 포트, 계정, 비밀번호로 SSH 서버에 접속한다.
- xterm.js와 Windows ConPTY를 사용해 `vim`, `top`, 방향키, `Ctrl+C`, 창 크기 변경이 가능한 대화형 원격 PTY를 제공한다.
- 브라우저 단독 HTML에서는 TCP SSH 연결을 제공하지 않고 EXE 전용 안내를 표시한다.
- 1차 버전은 비밀번호·keyboard-interactive 인증만 사용한다. 개인키, SFTP, 포트 포워딩, 여러 동시 탭은 후속 범위다.
- 2차 버전은 현재 문서와 SSH 터미널을 좌우로 동시에 표시하고, 너비 조절·좌우 교환·연결 유지 접기를 제공한다.
- 3차 버전은 기능 확장 대신 실패 원인·재접속·취소·종료·도킹 리사이즈를 안정화한다. 개인키, SFTP, 여러 터미널 탭은 범위에 넣지 않는다.
- 터미널 글꼴 계열·크기·줄 간격은 세션 중 즉시 바꿀 수 있고 다음 실행에도 유지한다. 설치되지 않은 사용자 선택 글꼴은 미리 정의한 고정폭 fallback 스택으로 대체한다.

## 사용자 흐름

1. 사이드바 하단 `더보기 → 원격 터미널`을 연다.
2. 호스트, 포트(기본 22), 계정, 비밀번호를 입력한다.
3. 런처가 `ssh-keyscan`으로 서버 공개키를 읽고 SHA-256 지문을 계산한다. Windows `ssh-keyscan`이 서버의 최신 KEX를 지원하지 않으면 비밀번호 없는 `ssh.exe` 협상으로 임시 `known_hosts`에 키만 받아 같은 확인 절차를 밟는다.
4. 처음 보는 지문은 사용자가 관리자에게 받은 값과 비교해 신뢰한다. 저장된 지문이 바뀌면 강한 경고 후 명시적으로 교체한다.
5. 신뢰된 키만 담은 ClassDock 전용 `known_hosts`를 사용해 `StrictHostKeyChecking=yes`로 접속한다.
6. 접속 뒤 문서와 터미널은 좌우 도킹되며 분할선을 드래그해 너비를 바꿀 수 있다. `⇄`로 좌우를 교환하고 접기 상태에서도 세션은 유지한다.
7. 연결을 끊거나 패널을 닫으면 로컬 OpenSSH 프로세스와 ConPTY를 정리한다.
8. 비정상 종료 시 OpenSSH 출력을 분석해 인증 실패, 시간 초과, 연결 거부, DNS, 네트워크, 지문, SSH 협상 오류를 구분하고 해결 방법과 재접속 버튼을 표시한다.

## 구성

```text
xterm.js
  │  UTF-8 입력 / ANSI 출력 / cols·rows
  ▼
127.0.0.1 ClassDock API (실행별 토큰 필요)
  │
  ▼
Windows ConPTY ── ssh.exe ── SSH 서버의 원격 PTY
                       │
                       └─ ClassDock askpass helper ← 일회성 named pipe ← 비밀번호
```

## 보안 원칙

- 비밀번호는 localStorage, 앱 상태, 파일, 명령행, 환경변수, 로그에 저장하지 않는다.
- `ssh.exe`가 비밀번호를 요구할 때만 난수 이름의 일회성 named pipe를 통해 같은 EXE의 askpass helper에 전달한다.
- 브라우저가 서버 키를 임의로 자동 수락하지 않는다. 최초 지문 확인 후 앱 전용 `known_hosts`에 공개키만 저장한다.
- SSH 요청 API는 기존 loopback Host/Origin 검사와 `X-ClassDock-Token` 검증을 모두 거친다.
- 사용자 SSH 설정 파일은 `-F NUL`로 읽지 않고, 포트 포워딩과 공개키 인증은 1차 버전에서 끈다.
- 호스트와 계정은 허용 문자·길이를 검사하고 모든 프로세스 인수는 Windows 인수 규칙으로 인용한다.

## 로컬 API

- `GET /ssh-capability` — OpenSSH/ConPTY 사용 가능 여부
- `POST /ssh-host-key-scan` — 서버 키와 SHA-256 지문 조회
- `POST /ssh-host-key-trust` — 확인한 공개키 저장 또는 명시적 교체
- `POST /ssh-session-open` — 원격 PTY 세션 시작
- `POST /ssh-session-input?id=` — 터미널 입력 바이트 전달
- `GET /ssh-session-poll?id=&offset=` — 누적 오프셋 이후 ANSI 출력 조회
- `POST /ssh-session-resize?id=` — ConPTY/원격 PTY 크기 변경
- `POST /ssh-session-stop?id=` — 세션 종료

모든 API는 EXE가 HTML에 주입한 실행별 로컬 토큰을 요구한다.

## 저장 데이터

- 브라우저: 사용자가 선택한 경우 호스트·포트·계정만 저장
- 브라우저: 터미널 도킹 방향과 너비 저장(세션·접힘 상태는 저장하지 않음)
- 브라우저: 터미널 글꼴 선택, 11~24px 글자 크기, 1.0~1.5 줄 간격 저장
- `%LOCALAPPDATA%\ClassDock\ssh\known_hosts`: 사용자가 신뢰한 서버 공개키
- 저장하지 않음: 비밀번호, 터미널 입력, 터미널 출력, 명령 기록

## 검증 항목

- 한글 계정 환경의 UTF-8 출력과 한글 입력
- 최초 지문 확인, 같은 서버 재접속, 서버 키 변경 경고
- 비밀번호 성공·실패, 연결 시간 초과, 서버 연결 종료
- `vim`, `top`, 방향키, `Ctrl+C`, 터미널 리사이즈
- PDF 등 현재 문서와 터미널 좌우 동시 표시, 분할선 드래그, 좌우 교환
- 접기·펼치기 동안 세션과 출력 유지, 닫을 때 세션 종료
- 잘못된 비밀번호·시간 초과·연결 거부·DNS 실패·네트워크 단절·지문 변경의 원인별 안내
- 실패·정상 종료·사용자 종료 뒤 재접속(호스트·포트·계정 유지, 비밀번호 초기화)
- 지문 조회·신뢰·세션 시작 요청 시간 제한과 상태 폴링 연속 실패 상한
- 분할선 드래그의 pointerup·pointercancel 정리와 빠른 접기·위치 교환 회귀
- 글꼴 변경 즉시 xterm 렌더링과 원격 PTY 행·열 재계산, 설정 복원·범위 제한·미설치 글꼴 fallback
- 창 닫기·앱 종료 시 SSH 프로세스 정리
- HTML 단독 실행 시 EXE 전용 안내
